## Decision and evidence boundary

**Do not expand the remaining ten A-C sources using the old reconstruction checkpoints.** Freeze a distinct deployment candidate, `m1-terminal-continuous-e2e-v1`: canonical source RGB8 -> deterministic original200 unmarked reconstruction -> unchanged100 A-C embedding updates -> unchanged quality-only RGB8 cap -> unchanged blind reader. Validate its initializer and its original two-source gate first, then produce the remaining ten sources and common threats with that same candidate. This changes the numerical definition of initialization, not the scientific loss, latent units, update counts, reader, margins or threshold. It remains family A.

The existing A-C experiments supply `u0` from immutable, previously computed unmarked200 checkpoints. Their reconstruction did not enforce deterministic algorithms. The first nondeterministic embedding replay also differed after an execution placement change; the cause was not proved to be a specific kernel or leak. Consequently, adding deterministic settings to a new-image initializer cannot be called exact legacy reproduction. A 200-step initializer is part of the deployed embedding algorithm, not undocumented external enrollment information.

At this decision, parent reports that the two independent ten-update A-C prefixes pass exact full-gradient, latent, Adam and RNG comparisons; the comparison is `20261004-1021-terminal-prefix-comparison` at `10f9156`. The full legacy-`u0` pilot `20261004-1021-terminal-deterministic` is running. These are component evidence about embedding from a fixed starting tensor. They do not measure reconstruction repeatability, reconstruction-to-embedding integration, or the final method on fresh photographs. The forthcoming result must be analyzed before this design's scientific trigger is decided.

The adapter in [m1-source-initialization-interface](m1-source-initialization-interface.md) currently documents nine CPU tests, including literal-loop parity and checkpoint recovery. Those establish mechanics on fixtures. Real pinned-VAE GPU parity remains unmeasured. The legacy reconstruction and the longer-fit diagnosis remain preserved descriptive evidence; their numerical trajectories are not relabeled as the new initializer.

## Frozen numerical and source contract

Use only the pinned, licensed, already admitted COCO val2017 **development** photographs in [m1-reconstruction-dev.json](m1-reconstruction-dev.json), the current pinned local SD1.5 VAE/CLIP/model assets, and the existing four development owners. No source, seed, optimizer, foundation model or margin search is added. The code/config/assets/runtime receipts must be committed and hashed before these runs. Concrete worker manifests reference this design; missing executable hashes are a build item, not invented completed provenance.

1. Verify the admitted raw SHA256 before decoding. Require native RGB; apply the original EXIF transpose and, where present, ICC-to-sRGB conversion with rendering intent0 and flags0. Resize the resulting image to512x512 with the pinned Pillow BICUBIC implementation, without a center crop. Retain native dimensions, canonical RGB8 bytes/hash and raw/model receipts. Target `I` is batch-one NCHW FP32 `RGB8/255`.
2. Before CUDA initialization, apply exactly `ac-deterministic-execution-v1`: `CUBLAS_WORKSPACE_CONFIG=:4096:8`, `torch.use_deterministic_algorithms(True, warn_only=False)`, cuDNN deterministic true, cuDNN benchmark false, and cuDNN/matmul TF32 false. Keep the current attention implementation and checkpoint implementation. A nondeterministic-operation error is an operational failure; do not warn-and-continue or silently change precision/backend. Pin actual Python, Torch, CUDA, cuDNN, diffusers, NumPy, Pillow, driver, GPU/device capability, thread settings and uninitialized-memory policy. Repeatability is required in this pinned environment, not promised across hardware or software versions.
3. Load the same hash-verified VAE weights as the original reconstruction, using the pinned fp16 asset variant converted to FP32; freeze parameters and use eval mode. Reconstruction needs only the FP32 VAE on GPU. Keep unrelated inference/safety models on CPU during differentiable fitting and record the placement. No FP16/autocast/TF32 substitution is allowed for initialization or embedding gradients. Use the existing FP16 public reader for final scientific observations.
4. Make every source independent of shard order: after loading required assets and immediately before each fresh initialization, set Python, NumPy and Torch CPU/CUDA seeds to0. At the transition to a **fresh** embedding optimizer, reset those seeds to0 again, after feature preparation/model placement and before its step0 checkpoint. This explicitly versioned phase-boundary bookkeeping is not a claim to match the legacy process's RNG state. Resume instead restores the corresponding saved RNG; it must not reseed or recompute a completed observation. Frozen VAE posterior-mode encoding and these fixed losses are intended to be deterministic; retain RNG nevertheless and fail if equivalence checks contradict that expectation.
5. Start `u_init = VAE.encode(2I-1).latent_dist.mode()` in unscaled posterior units. Train its detached clone `u` only. Raw decoder output is `R(u)=(VAE.decode(u)[0]+1)/2`. Use `mean((R(u)-I)^2)` **before clamping**, non-reentrant decoder checkpointing, and exactly200 Adam updates with learning rate.02 in these unscaled units. Preserve the original Adam defaults: betas(.9,.999), eps1e-8, weight decay0, amsgrad false and the pinned implementation's default remaining flags. Record the actual parameter group; do not silently turn on fused Adam, replace the optimizer, scale the learning rate by.18215, add regularization, or select a better intermediate iterate.
6. Observe steps0/50/100/200 in the original loop order. Persist full latent/initial posterior/Adam/RNG state at step0 and after every10 completed updates. The new adapter's receipt boundary is after any observation at that step. Its schema is `m1-original-source-initialization-v1`; legacy before-observation restart receipts are not accepted as resumable new-format receipts. For RGB8 observations, clamp raw RGB to[0,1], permute to HWC, transfer as FP32 to NumPy, multiply by255, NumPy round, and cast uint8. Preserve raw float MSE, latent displacement, quality and final RGB8; no quality-driven initialization selection.
7. Define `u0=u_200` exactly. Pass that tensor directly to the unchanged A-C embedding operator; do not round-trip it through a reconstruction PNG or re-encode that PNG. Its reference remains the A-C clamped decode `D(u0)`, computed fresh from this same FP32 VAE. Discard the initialization optimizer and its moments. Start a **new** A-C Adam optimizer at `u0`, with learning rate.01, exactly100 updates, semantic margin6, instance margin8, every-other-step semantic-cycle margin6, quality weight.01 and the existing35.2dB cap. The source-bypass output remains source plus capped `D(u100)-D(u0)`. Preserve the last-step rule,36-step quality-only final bisection, FP16 posterior-mode public readout, suspect-derived CLIP/pHash, inclusive threshold4 and current operational states.

This is a fixed200+100 method, not a single300-step Adam trajectory. The reconstruction is unmarked: no CLIP, pHash, owner score, safety score or decoder detection objective enters its200 updates. Source pixels, source-derived features and `u0` are embedding-side inputs. The public reader receives only suspect RGB8, public owner/profile and pinned models; neither initialization receipt nor original source is detector side information.

Reconstruction alone is **not** required to pass35dB: the declared method uses source bypass, and legacy pure reconstruction did not meet that requirement. Its worthiness is instead tested by faithful finite200-step execution, exact integration and the final end-to-end clean/VAE gate. Report initialization quality and MSE honestly; a low reconstruction score is not hidden, and a successful hybrid output does not become pure-decoder photo preservation. No600-step extrema initializer, best-of-seeds fallback or cached legacy substitute is allowed.

## Bounded failure rule and resource plan

The immediate queue is finite: conditional R1/R2, E1/E2, then at most the unchanged remaining ten and common assessment if E1/E2 passes. If the currently running legacy-`u0` A-C pilot fails a valid necessary gate, this design does not automatically trigger a second scientific search under a different initializer; record that result and apply the existing family-closure decision. Mechanical initializer work may still be needed for whichever method is actually frozen.

If R1/R2 fails, retain the mismatch and perform one stage-local diagnosis using the saved target, posterior, trajectory, optimizer and runtime receipts. Repair a demonstrated mechanical/execution defect under a new receipt; do not soften exact equality or change scientific optimization to pass. A deterministic-operation error, OOM or failed receipt is an operational issue. If E1/E2 fails despite valid mechanics, the deployable A-C variant fails this frozen two-source gate. Do not fall back to legacy `u0`, extend steps, tune seeds/margins, select images, or expand it merely because its legacy component passed. The retained stage diagnostics plus original-A evidence then inform the existing bounded family-A closure; there is no automatic additional initializer grid.

All execution is local USD0 with existing assets and no new download. Initializer/embedding workers are sequential on the pinned GPU. Each worker uses max1800s, max10GiB GPU allocation or lower initial free availability minus the existing512MiB reserve, max16GiB process RAM and max500MiB retained artifacts; record the effective cap and actual headroom before allocation. Save every10 completed updates and after mandatory observations, using unique output/checkpoint names. No overwrite of any old run or receipt. The interface's no-overwrite atomic checkpoint behavior remains mandatory.

Plan R1, R2a, R2b and each end-to-end pilot source as separate owned workers/phase shards where necessary. Phase sharding does not change the scientific source unit or reset a resumed phase. The estimated added work is600 initializer updates and200 embedding updates before expansion, not a promised wall time. Measure each phase and model-load/finalization time. The remaining ten may retain the five logical two-source groups from the expansion design, but split execution into per-source/phase shards if measured timings cannot fit1800s with a finalization margin. Do not raise budgets or run overlapping GPU workers to preserve an arbitrary shard grouping. Runtime sizing and exact continued checkpoints are operational choices; the200+100 method is fixed.

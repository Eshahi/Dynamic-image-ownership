# A6 policy-compliant runtime route decision

Status 2026-09-25, issue #7 / draft PR #58: **recommend an explicitly authorized local WSL 2 + Ubuntu compatibility preflight**, before any paid RunPod Pod. This is a proposed execution-environment choice, not installation permission, a scientific run, or A6 acceptance.

## Observed host constraint

The [clean rebuild receipt](a6-clean-science-rebuild-20260925.md) shows that all 42 pinned Windows wheels install offline and `pip check` passes. Both original and rebuilt Windows science venvs nevertheless fail to import `transformers` when Windows Application Control rejects unsigned `regex._regex`. Read-only `Get-AuthenticodeSignature` reported `NotSigned` for the rebuilt extension. `tokenizers` and `safetensors` import, but neither makes the full `transformers` package or A5's fixed empty-string text-conditioning path usable. Microsoft's [Smart App Control overview](https://learn.microsoft.com/en-us/windows/apps/develop/smart-app-control/overview) explains that unknown unsigned code can be blocked. We did not alter the host policy or seek a code-integrity bypass.

Read-only host inventory: `wsl.exe` exists, but `wsl.exe --list --quiet` reports that WSL is **not installed**; Docker CLI is absent. Therefore no already-installed local Linux execution surface is available. The successful reviewed image-only CLIP adapter solves only the verifier's visual encoder and does not solve the generator's text encoder.

## Candidate routes and decision boundary

1. **Local WSL 2 (recommended first):** Microsoft [documents Windows 11 WSL installation](https://learn.microsoft.com/en-us/windows/wsl/install), and NVIDIA's [CUDA-on-WSL guide](https://docs.nvidia.com/cuda/wsl-user-guide/) supports Linux GPU applications through the existing Windows NVIDIA driver. Installing/enabling WSL and Ubuntu is a host-level change, can require a reboot, and is **not authorized by this document**. If the user approves it, first perform a no-model Linux Python/`regex`/`transformers`/CUDA compatibility probe; then build a separately hashed Linux package lock and capture exact driver, framework and distribution identities. Windows wheel hashes cannot be reused as Linux hashes. Do not install a separate Linux NVIDIA display driver inside WSL. Later model loads, method compute and data acquisition retain their separate approval boundaries.
2. **Paid RunPod Linux Pod:** a compatible GPU environment is plausible, and [RunPod lists per-GPU-hour Pod pricing](https://www.runpod.io/pricing), but rates, availability and storage charges must be checked when a concrete manifest is ready. The installed `thesis-compute-runner` contract currently **refuses live Pod creation** because its reviewed RunPod CLI/backend deadline protection is not enforced; direct API creation or old flags would bypass that safeguard. No Pod, paid budget or remote scientific run is authorized here. A safe provider lifecycle and exact cost/duration ceiling must exist before requesting execution approval.
3. **Native Windows rewrite or signed native dependency:** a reviewed alternative could avoid the blocked extension, but replacing upstream text-tokenization/model code without full reference parity risks method drift. No suitably signed `regex` candidate is verified on this host. Do not substitute standard-library `re`, fake the import, sign code without a trusted process, or weaken Windows security as a workaround.

The independent reviewer `/root/a6_rebuild_review` of commit `aae18017524f21c1fdf37d0246c40136c6ed1e35` found A6 not closure-ready. WSL 2 is the smallest potentially method-preserving local route and avoids paid Pod spend, but it still requires the user's explicit host-install decision and empirical confirmation. Continue independent repository work while that decision is pending. No deadline change is asserted from this single blocker.

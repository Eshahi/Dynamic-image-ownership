# Native baseline feasibility, inspected 2026-10-10

Read-only feasibility assessment; no third-party code execution, installation, checkpoint/image download or scientific run. Public GitHub API metadata and trees were inspected in memory. No source copies were retained, so there is no download receipt to append. Resource estimates below are engineering inferences, not measured laptop benchmarks.

## Decision

Start with **Watermark Anything (WAM), SA-1B MIT checkpoint**, as the most feasible posthoc existing-photo baseline. Name the checkpoint explicitly: it is an official released model but not the COCO checkpoint evaluated in the paper. **ZoDiac** is technically plausible after a compatibility port and memory rehearsal, but its code/checkpoint permissions are unresolved and its default SD2.1 assets are absent. **FreqMark** remains a paper-specified reconstruction candidate: unable to find official image-watermark code after bounded search, not a claim that none exists. Do not describe an SD1.5 substitution or our reconstruction as an unchanged native baseline.

## Local environment actually observed

MAIN `.thesis-build/a6-science-venv/Scripts/python.exe` reports Python **3.12.14**, torch **2.12.1+cu130**, CUDA **13.0**, torchvision **0.27.1+cu130**, diffusers **0.35.1**, transformers **4.57.6**, NumPy **2.5.2**, lpips **0.1.4**, scikit-image **0.26.0**. GPU is RTX 5070 Ti Laptop, **11.940 GiB** total memory. This corrects the tentative Python 3.13/torch 2.8 assumption. OmegaConf, einops, timm, scikit-learn, opencv-python and pycocotools are missing according to installed-distribution metadata. Asset directory entries are `sd15-fp16`, `clip`, `alexnet`; checkpoint completeness/hashes were not re-audited.

Old CUDA environments should not replace the working Blackwell stack. Compatibility adaptations need an isolated environment, exact pins and a diff documenting departures from the official code. Presence of enough inference weights is not evidence that differentiating through an entire diffusion trajectory fits in 12 GB.

## WAM

API-pinned default main revision **2c08af04d037d5667c02f6ddebbda9ff04581c3e**, commit date 2025-06-20. API `archived=true`; exact archival date was not independently pinned in this assessment. [Metadata](https://api.github.com/repos/facebookresearch/watermark-anything), [commit](https://api.github.com/repos/facebookresearch/watermark-anything/commits/2c08af04d037d5667c02f6ddebbda9ff04581c3e).

Code and SA-1B `wam_mit.pth` weights are MIT. Original paper `wam_coco.pth` weights are separately CC-BY-NC; selecting the MIT model changes the evaluated model. README's generic `checkpoint.pth` example must be pointed at the chosen file. No retraining is needed. [Pinned README](https://github.com/facebookresearch/watermark-anything/blob/2c08af04d037d5667c02f6ddebbda9ff04581c3e/README.md), [MIT](https://github.com/facebookresearch/watermark-anything/blob/2c08af04d037d5667c02f6ddebbda9ff04581c3e/LICENSE), [COCO license](https://github.com/facebookresearch/watermark-anything/blob/2c08af04d037d5667c02f6ddebbda9ff04581c3e/LICENSE-COCO).

Native `embed` accepts arbitrary RGB dimensions, internally resizes to 256 square, upsamples the residual and blends at original resolution with optional JND attenuation. `detect` also resizes to 256. Standard released payload is 32 bits with a localization output. Decode uses the predicted mask, not an oracle donor mask; the full-image comparison should use a full embedding mask. Detector needs the model and candidate message for identity matching, not original image or diffusion inversion. This is a learned image-domain baseline, not proof of content ownership. Two inference forwards at batch one are plausibly comfortable in 12 GB; actual latency, peak VRAM and delivered PNG quality remain unmeasured. [Native inference implementation](https://github.com/facebookresearch/watermark-anything/blob/2c08af04d037d5667c02f6ddebbda9ff04581c3e/watermark_anything/models/wam.py).

Official tested stack is Python 3.10.14/torch 2.5.1/CUDA 12.4/torchvision 0.20.1. Requirements pin OmegaConf 2.3.0, einops .8.0, timm 1.0.11, OpenCV 4.10.0.84, pycocotools 2.0.8, sklearn 1.5.2, skimage .24.0, lpips .1.4. Missing packages above are real; incompatibility with the current stack is not yet demonstrated. The inference helper imports plotting/sklearn and loads four relative YAML configs plus params JSON; running outside repository cwd needs explicit path handling. It calls `torch.load` without explicit `weights_only`; verify the checkpoint structure under modern defaults instead of indiscriminately enabling pickle. [Requirements](https://github.com/facebookresearch/watermark-anything/blob/2c08af04d037d5667c02f6ddebbda9ff04581c3e/requirements.txt), [loader](https://github.com/facebookresearch/watermark-anything/blob/2c08af04d037d5667c02f6ddebbda9ff04581c3e/notebooks/inference_utils.py).

## ZoDiac

API-pinned master revision **89f864d2e4f6f33663dc69b4d99bee49073e194c**, 2024-11-05; repository has three commits. API license is null and recursive tree contains no root LICENSE. This does not establish permission to redistribute modified code or the bundled `loss/rgb_watson_vgg_trial0.pth`; that loss checkpoint's license is also unverified. SD model licensing is separate. [Metadata](https://api.github.com/repos/zhanglijun95/ZoDiac), [commit](https://api.github.com/repos/zhanglijun95/ZoDiac/commits/89f864d2e4f6f33663dc69b4d99bee49073e194c).

The supplied Linux conda export pins Python 3.10.13/torch 1.13.1/CUDA 11.7/torchvision .14.1, diffusers .21.4, transformers 4.37.2, huggingface-hub .20.3, accelerate .28.0, NumPy 1.26.0. Exact Linux build identifiers will not reproduce directly on Windows; the old GPU stack cannot be assumed usable on Blackwell. Its custom diffusion subclass calls old input-checking/decode APIs and checkpointing without explicit `use_reentrant`; those are concrete port surfaces, not verified runtime failures. [Environment](https://github.com/zhanglijun95/ZoDiac/blob/89f864d2e4f6f33663dc69b4d99bee49073e194c/environment.yml), [pipeline](https://github.com/zhanglijun95/ZoDiac/blob/89f864d2e4f6f33663dc69b4d99bee49073e194c/main/wmdiffusion.py).

Default config is **SD2.1-base**, empty prompt, one ring signature (channel 3/radius 10/seed 10), 100 optimization iterations, SSIM blend target .92 and detection score .9. The notebook inverts the existing photo for 50 DDIM steps, then each optimization iteration differentiates through 50 denoising steps, and blends back toward the original. This means approximately 5,000 denoising forwards plus backward recomputation per embedded photo, not a single img2img pass. Full default fp32 optimization may exceed 12 GB despite checkpointing; batch-one memory/runtime must be measured before a grid. FP16/offload/fewer steps are amendments until validated. [Config](https://github.com/zhanglijun95/ZoDiac/blob/89f864d2e4f6f33663dc69b4d99bee49073e194c/example/config/config.yaml), [notebook](https://github.com/zhanglijun95/ZoDiac/blob/89f864d2e4f6f33663dc69b4d99bee49073e194c/example.ipynb).

Input helper does not resize; default signature shape is 1x4x64x64, so supply canonical 512-square photos or document shape changes. Detection requires the matching diffusion checkpoint, ring template/key parameters and a 50-step inversion with empty text; it does not need the original photo. Native default is signature-presence detection, not a matched 32/48-bit message channel. `watermark_prob` defaults to the noncentral-chi-square score; a separate unused-by-default Gaussian helper returns variance as a normal scale, so do not confuse those paths. Neither theoretical score nor .9 default supplies an empirical .001 FPR guarantee. [Input and detector](https://github.com/zhanglijun95/ZoDiac/blob/89f864d2e4f6f33663dc69b4d99bee49073e194c/main/utils.py), [signature and score](https://github.com/zhanglijun95/ZoDiac/blob/89f864d2e4f6f33663dc69b4d99bee49073e194c/main/wmpatch.py).

## FreqMark

Opened method/experiment/appendix sections of arXiv 2410.20824v1 and searched exact title, authors plus GitHub, image-only GitHub FreqMark, and NeurIPS code. No official image-code repository identified. LLM FreqMark (2410.10876) is unrelated. No code revision/license can be pinned.

Paper specifies posthoc latent-frequency optimization with SD2.1 KL VAE, DINOv2-small image-only decoding, 512-square processing, 48-bit experiment payload (directions in first 128 feature dimensions), Adam learning rate 2.0 for 400 steps and PSNR/LPIPS weights .05/.25. Two fp32 images take 5–6 minutes on A100 40 GB; this cannot predict laptop cost or prove a 40 GB requirement. Decoder needs encoder/directions and expected bits, not diffusion inversion. Article lists SD2.1 OpenRAIL++-M and DINOv2 Apache-2.0; that does not license unavailable implementation code. A batch-one VAE/DINO optimization is plausible in 12 GB but untested. Existing SD1.5 assets alone do not reproduce the stated method. [Inspected paper, sections 4–5 and A.1](https://arxiv.org/html/2410.20824v1).

## Comparison contract before any run

- Keep official checkpoint/native configuration and quality-matched adaptation as separate named rows. Disclose every port, backbone replacement, precision change and reduced-step budget; report infeasible or unavailable rows rather than silently excluding them.
- Use identical development photos and delivered 8-bit PNGs, canonical resizing, fixed T3 SD1.5 DDIM schedules/seeds and independent-VAE attacks; T4 donor/recipient pairs and T5 semantic pairs must be shared. Score strict PSNR >35, SSIM >.9, LPIPS <.1 with existing project assessors, including failed images. ZoDiac's SSIM blend alone does not guarantee the other limits.
- Calibrate native detection scores on fresh declared development/calibration data, then freeze thresholds before held-out use. Distinguish nominal .001 from measured error and confidence intervals. Negative cells need unmarked photos, wrong messages/keys and unrelated marked content, including attacked versions. Multiple owners/templates and WAM region searching create additional trials; account for those trials instead of importing a per-call FPR.
- Preserve native payload differences (WAM 32, FreqMark 48, ZoDiac presence template). Compare watermark-presence TPR at matched FPR and separately identity/message accuracy. F5 semantic presence, checked detection and full attribution are distinct endpoints; no native baseline magically supplies F5's certificate/content-binding endpoint.
- Record side information per call and native encoder/detector timing, peak VRAM, initialization cost, key count, and any repeated search. WAM region-level donor recovery is distinct from false full attribution. T4/T5 require explicit owner/content policies shared across methods; payload possession alone is not evidence of cryptographic binding.

Recommended order is WAM inference-only smoke test after dependency/weight vetting, then ZoDiac permission resolution and single-photo port rehearsal, then FreqMark reconstruction only if official code remains unavailable. This assessment did not perform execution.

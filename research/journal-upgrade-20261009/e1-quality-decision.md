## Why attenuation, and why no restoration

Writing the saved RGB8 E1 mark as m=x+d, where x is the original RGB8 source, uniform attenuation gives x+0.8d before rounding. Before rounding, MSE is multiplied by 0.64 and PSNR improves by 1.9382 dB. In a local smooth feature model with squared feature distance, LPIPS would also scale approximately quadratically: 0.1167193 times 0.64 is about **0.07470**. This supplies substantial prospective headroom below .1; it is an explicitly unverified approximation because normalization, nonlinear features, rounding and spatially varying sensitivity invalidate exact LPIPS homogeneity. Neither SSIM nor LPIPS is guaranteed to improve.

The exact integer construction below cannot increase any pixel's absolute residual, so its RGB MSE cannot increase even after rounding. This does not prove semantic or fragile survival. Mixing toward the host reintroduces host interference; normalized received-image correlation, code errors and content recomputation are not linear in the mixing coefficient. BCH can correct up to five hard errors, but the clean h channel has no new outer code. All delivered-payload checks therefore remain hard prerequisites.

`restore_fragile` calls `_embed_fragile` with a target MSE derived from the fixed profile, not the attenuated residual budget. For 147498 the two E1 restoration amplitudes were 27.9890 and 23.5125. Calling it again may add signal and distortion back along fragile coordinates; it has no contraction guarantee and may interfere with the semantic carrier. Because current clean h scores are large, the cheapest informative test is to attenuate the already-present fragile mark together with the semantic mark and measure whether it still works. A fragile restoration fallback would be a second construction, not an automatic repair in E2. Its failure would justify a separate future decision.

A perceptually constrained writer is scientifically plausible, but it introduces another gradient objective, rounding acceptance, feasibility search and runtime question before testing the simpler headroom explanation. No LPIPS weight, larger optimization budget, changed D3 step schedule, or revival of D3 is selected here.

## Exact construction and fixed payload binding

For each of the frozen twelve development sources, take **the final saved E1 clean C1 image** from completed A/B rows. Use the A final endpoint for 1675 and 499768 and B final endpoints for the other ten. For 147498, E1's final endpoint is its preserved invalid-quality initializer; this is explicitly allowed as the input to a new method, never retroactively an E1-valid initializer. No earlier intermediate, best trial, old D2/F5 mark, or alternate output may replace these final endpoints.

The sole new pixel operation is, independently for every RGB integer channel:

```text
d = int32(m) - int32(x)
a = floor((4 * abs(d) + 2) / 5)
y = uint8(int32(x) + sign(d) * a)
```

This is nearest-integer rounding of x+0.8(m-x), with no half ties. Since x and m are in [0,255], y remains in [0,255]. Save PNG, reload RGB8, and evaluate that exact image. No masking, channel-specific scaling, blur, clipping adjustment, new embedding, optimization or h restoration follows it. Every source gets the same rule, including already excellent E1 images. Store source, E1 input, final E2 output, fixed factor and writer ancestry in the ordinary run record.

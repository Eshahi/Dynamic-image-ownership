## Delivered module and API

`scripts/m1_confirmatory_raw_guard.py` deliberately offers only:

- Frozen `InputReceipt` and immutable `ScopedCapability` / `VerifiedBytes` value types.
- `issue_fixture_capability(...)`: generated token/PNG fixtures in a dedicated system temporary directory bearing an exact synthetic marker; public fixture identities/roles only, immutable distinct receipt allowlist, bounded lifetime, exact manifest/index digests and a distinct contained output subdirectory. Official-approval and source-adoption flags remain false. Issuance reads only the marker it authenticates as a generated fixture.
- `read_scoped_input(cap, source_uid, role, manifest_sha256=..., index_sha256=..., output_root=...)`: reject absent/foreign/expired scope and unlisted identity before opening; return the bounded immutable bytes actually checked, not a path to reopen.
- `issue_scientific_capability(...)`: unconditional refusal before inspecting arguments. Supplying purported official JSON, a hash, true boolean, fake capability or a development receipt cannot grant scientific input access.

No CLI or arbitrary-root override is provided. Dataset-looking `data`/`raw` roots are refused before filesystem resolution. Fixture roots must be contained temporary directories with an exact generated marker. Fixture receipts require `fixture:` source identity, canonical relative paths, lowercase SHA256 and exact bounded integer size (<=1MiB); output/marker paths, traversal, aliases, duplicate claims/path ownership and malformed values are rejected. The cap stores its receipt tuple rather than a caller-mutable list. Synthetic token magic is required for token roles; the `synthetic-generated-image` role accepts ordinary PNG bytes under the same marked temporary fixture root, explicit hash receipt and `fixture:` identity. PNG format checking is separate from authorization. This enables candidate-identical generated-image rehearsals without granting access to acquired image or annotation sources.

For each read, root/path components are checked using `lstat` for symlink/junction/reparse metadata, and hardlinked/nonregular inputs are refused. After opening and **before reading**, the final handle path is queried with native `GetFinalPathNameByHandleW` on Windows (or `/proc/self/fd` on supporting POSIX systems) and checked against the exact expected contained path; unavailable handle containment fails closed. This catches redirected parent-directory escapes between path checks and opening. The same file descriptor is used for bounded reading, before/after file identity/size/mtime checks, exact hash/role-format verification and final expiry/scope recheck. Handles always close on success/failure. No caller receives a path subject to a subsequent decode reopen race. These are filesystem/integrity protections for reviewed trusted code, not cryptographic isolation against malicious Python or another process running as the same user; private seal/frozen dataclasses do not assert such security.

## Candidate explicit phase placement (not wired to worker)

`src/embedding/residency.py` provides a prospective single-use `PhaseResidency` state machine. It requires frozen eval CUDA0 fp32 modules, component identity and detached CUDA0 fp32 conditioning. After conditioning, park only text encoder and safety checker on CPU; keep condition/UNet/VAE on their original device and precision. At the end of optimization, move UNet/VAE to CPU and restore safety checker to CUDA0 before saved-pixel safety calls. Text/safety computation is not substituted with CPU forwards. Failed transfers are terminal with partial state retained; no retry or automatic alternate profile. Integer buffers are allowed, floating precision changes are rejected.

This helper is deliberately NOT imported/invoked by the current scientific worker and does not authorize placement changes. It has only label-based fake module/device tests, not real CUDA transfer, value/dtype fidelity, RAM/VRAM fit or safety parity measurements. There is no measured byte saving or runtime estimate. CPU residency increases RAM; a future package must account for transfer peaks and measured RSS, preserve resource ceilings and record actual module/device identities. No inference hooks, autocast, tiling, quantization, source resizing, cap increase or model substitution are included.

[Official Diffusers v0.35 memory guidance](https://huggingface.co/docs/diffusers/v0.35.0/en/optimization/memory) describes component placement/offload as a memory technique, but inference guidance does not establish this custom gradient path's correctness. The proposed explicit boundary avoids automatic inference hooks; that is rationale, not a cure established by the failed run.

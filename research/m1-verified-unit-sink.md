# Verified unit sink v1

`scripts/m1_verified_unit_sink.py` supplies filesystem persistence for the injected unit engine. The caller provides an already owned output directory and explicitly authorized containment root. The sink checks resolved containment and refuses reparse/symlink path components and unsafe names. It creates fresh files with exclusive temporary writes, flush/fsync and same-directory rename, refuses existing completed destinations, and retains partial artifacts on failure. The production host is Windows, where rename also refuses an existing destination. This is integrity/storage infrastructure, not a raw-source capability or isolation against a malicious same-user process.

PNG storage uses the exact supplied canonical uint8 RGB512 pixels, then reopens the PNG and verifies RGB mode, geometry and byte identity. Numeric storage uses no-pickle NPY, verifies finite numeric values, reopens the file and checks dtype/value identity. Checkpoint storage saves the adapter's sealed CPU state with torch, reopens with `weights_only=True` on CPU and compares complete recursive state digests before notifying the observer. Default native array shape is preserved. The explicit generated compatibility layout transforms only the four existing stage arrays from1x3x512x512 float32 to512x512x3 float64, exactly matching the previous generated worker conversion. Reader-z names retain the old `*-reader.npy` convention. This conversion is orchestration/serialization and does not change scientific model arithmetic.

Receipts bind absolute stored path, SHA256 and byte size. The future official analyzer still independently verifies files, scientific core, upstream source lineage and planned namespace. Sink methods neither read raw images nor load model weights or initialize CUDA. `before_checkpoint` and observer callbacks are caller-owned bounded injection/journal hooks; the adapter's callback RNG purity guard remains active.

The generated worker now uses this sink and shared unit engine. Its CPU artifact audit requires the shared engine version and explicit compatibility layout, reconstructs the marked image/cap from retained source/residual, reconstructs unmarked C0 from reference, verifies all three separate saved control images, retained quality schemas and the original clean marked pixel identity, in addition to existing sealed checkpoint/blind-score replay. Four endpoint conditions and22 overlapping full/resume parity states remain unchanged. Extra enrollment images/quality calls affect resource measurements and must be included in the fresh rehearsal; obsolete pre-integration timings are not promoted as final worker measurements.

Five CPU sink tests cover pixel reread/overwrite/traversal rejection, declared output containment, native versus explicit legacy layout, old reader naming, CPU checkpoint reread/observer order, and retained partial storage-pressure failure. The full generated worker CPU integration test uses mocked model context and makes no GPU efficacy claim. Actual shared-engine generated full/prefix/resume GPU parity and lifecycle catalog remain unperformed until the parent commits and runs them.

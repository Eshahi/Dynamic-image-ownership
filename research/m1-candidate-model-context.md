# Shared candidate model context and clean-unit seam

`m1_candidate_model_context.CandidateModelContext(config, scientific_core_sha256, publish=..., event=..., check=...)` is the single explicit real-model loader used by the generated rehearsal worker. Import is standard-library only; construction is GPU work and requires caller-authorized execution. It has no source resolver, source/model path override, official approval issuer or network fallback.

The context blocks network, applies the existing strict deterministic execution policy before CUDA initialization, verifies the exact17 local asset lock and installed LPIPS package, and loads local safetensors only. The embedding VAE is frozen eval FP32, the public VAE and safety checker frozen eval FP16, and CLIP/LPIPS frozen CPU evaluators. Profile and weight identities, verified asset receipts, Python/package versions, driver/device/runtime, deterministic flags, learned LPIPS weight hash, allocation budget, sampled peak RSS and allocator peak are published incrementally so later failures retain provenance.

It supplies the actual `CandidateAdapter` plus `feature`, `readout`, `quality`, `safety_check`, `vae_cycle`, `place_inference('cpu'|'cuda')` and `resource_snapshot`. Inference placement moves only the public VAE and safety model during initializer/embedding gradients, retaining the FP32 embedder. Source/canonical pixels and output storage remain the caller's responsibility.

Feature normalization preserves the existing development code exactly: `three_threat_models.clip_feature` performs FP32 Torch L2 normalization, followed by one FP64 NumPy normalization inside CandidateAdapter. The shared context adds no normalization. This is not a truly raw encoder feature claim. Cycle delegates to the new path-free image-operations module, including the existing float64-before255 RGB8 quantizer. Quality uses the retained pixel/SSIM definition and CPU LPIPS, with PSNR>35, SSIM>.9, LPIPS<.1 conjunction unchanged. Human visual assessment remains missing. No UNet/text model is loaded here; the reviewed DDIM pipeline dependency is a future separately injected context extension.

Working input SHA256 and normalized Git content identity are distinct. The new `m1_git_input_identity.verify_git_input` checks exact current bytes against the manifest SHA256, then compares `git hash-object --path=relative FILE` with `git rev-parse COMMIT:relative`. It retains both working SHA256 and committed/current Git blob IDs. A legitimate CRLF checkout therefore passes a LF Git blob without rewriting input files; changed working bytes or normalized content are refused. Launcher and worker audit consume the same helper. Official manifest raw input receipts remain byte-exact.

Six context CPU fixtures check model-free import, reviewed profile/resource limits, real loader argument/dtype/freezing wiring with explicitly mocked CPU models and CUDA telemetry, helper-feature identity, image-operation safety-hook/receipt ordering and quality-helper parity. The Git helper has two real temporary-repository tests, including CRLF/LF equivalence and changed-content/byte refusal. These are mechanics tests, not model/rehearsal efficacy evidence. Parent alone runs real full/prefix/resume after commit; current scientific runs were not modified.

## Proposed next shared clean-unit API (not implemented/adopted here)

A path-free `CleanUnitEngine(context).execute(rgb8, verified_source_identity, owner, source_uid=None, query_plan=..., recovery=None, checkpoint_store=..., artifact_store=..., event=..., check=...)` can be consumed by both generated rehearsal and the official scientific worker. The upstream resolver/contract supplies immutable source identity (raw hash, canonical RGB8 hash, UID/split/adoption binding) and the reviewed owner/schedule; the engine cannot authorize source access. Candidate choice remains unresolved until freeze.

The engine calls the same adapter original200 initializer and100 embedding, retains every10-step sealed checkpoint, and returns canonical C0-source, matched unmarked reconstruction C0, C1, cap/float-array receipts, model context provenance, quality and actual query results. Matched reconstruction is decoded from the unmarked terminal initializer and remains a separately labeled generation/reconstruction counterfactual. PNG encode/save/reopen byte identity is enforced by an injected owned artifact-store callback; no arbitrary output paths enter the engine. Checkpoint callbacks return exact receipts, and explicit recovery identifies a single predecessor without best/duplicate selection.

`query_plan` lists exact endpoint/claimed-owner pairs supplied by the protocol inventory. Generated diagnostic alpha+3wrong-owner queries and scientific A4 enrolled/next-owner queries therefore use identical science with separately declared counts. C0-source, matched reconstruction and C1 endpoints are explicit; VAE/DDIM attacks, patch operators, v5 comparator and T5 pair scheduling remain shared image-operations/protocol stages after clean artifact persistence. The outer official contract owns fixed denominators, prerequisite/source/index approval checks, outputs, missingness and promotion gates. The contained launcher owns child lifecycle and cleanup; neither is duplicated by the clean engine. No implementation beyond this shared context has been made pending parent review of this seam.

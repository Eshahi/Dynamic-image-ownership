# Shared injected scientific unit engine v1

`scripts/m1_scientific_unit_engine.py` is an orchestration library for generated candidate rehearsals and a future official scientific child. It does not load models, decode raw files, inspect annotations, grant authority, issue capabilities, or discover paths. There is no CLI. Its canonical ndarray boundary must be preceded by the separately verified broker/canonicalizer. Validation of supplied identity fields is integrity validation, not scientific authorization.

## Interfaces and ownership

`UnitEngine(context,sink,check,event)` receives the shared `CandidateModelContext` and its actual `CandidateAdapter`. Initializer and embedding mathematical operations remain solely in the adapter and existing cores. The same `.initialize(...,resume,stop_step)` and `.enroll(...,resume,stop_step)` methods serve fresh, prefix and resumed phases. Exact200/100 update rules and sealed optimizer/RNG/source/runtime continuation checks are delegated to the actual adapter; arbitrary stop steps cannot bypass those checks. Placement calls use the context's reviewed inference offload path. Checkpoint callbacks persist the adapter's complete sealed payload before reporting an event; callback purity/RNG guards remain enforced by the adapter.

The caller supplies a storage sink implementing:

- `save_image(name,rgb8) -> (reloaded_rgb8, receipt)`.
- `save_array(name,numeric_array) -> receipt`.
- `save_checkpoint(name,sealed_payload) -> receipt`.

Receipts require lowercase SHA256; the sink must hash the actual stored file and perform fresh contained atomic storage. The engine compares reread pixels byte-for-byte with the generated image before detector or metric work. It cannot prove arbitrary sink honesty, containment, filesystem durability or file hashes from an injected callback; the production sink and scientific analyzer must independently establish those facts. Names are fixed primitive names or caller inventory IDs; caller binds them to an already validated namespace. No engine method opens a path.

`mode='scientific'` requires a supplied test-source identity with matching `source_id/source_uid/group_id/source_rgb8_sha256` plus a schedule row matching UID/group and exactly derived A4 public owner/wrong owner/uint64 decimal and hex. Only the16 A4 claims are admitted to scientific assessment. This validates per-row identity; full300-source schedule/inventory hash, eligibility, source-contract and official unlock are caller responsibilities.

`mode='generated'` requires `fixture:` source identity, synthetic split, fixed generator seed0/1, explicit existing four-pilot owner and **no scientific schedule**. Its adapter source_uid isNone. Generated identity cannot silently substitute for a scientific schedule. This preserves the existing rehearsal four-owner protocol rather than altering its parity roster.

## Output and failure semantics

Enrollment persists three separate images: canonical `C0-source`, matched unmarked `C0-reconstruction` from the adapter's reference decoder output with the unchanged float64 RGB8 quantizer, and quality-capped `C1`. It retains reference/decoded/residual/surrogate arrays in their native adapter shapes, sealed phase checkpoints, cap receipt, source quality for each image and C1 quality relative to reconstruction separately. Prefix embedding returns only the sealed checkpoint and `completed=False`; it does not produce a science endpoint. Matched reconstruction is not automatically inserted into the old four-condition generated rehearsal roster.

`assess_image` persists/reloads a supplied image, checks safety, computes source and same-arm clean quality, optionally saves suspect E and scaled posterior-mode reader-z arrays plus integer H, then reads only saved suspect bytes against supplied unique public claims. Candidate public extraction remains `context.readout`; callers may inject the unchanged v5 extractor and disable candidate latent retention. Source/clean images reach quality only, not readout. Recorded query durations are wall-clock durations of the injected call; they are not synchronized GPU timing claims. Human visual verdicts remain absent.

`clean(enrollment, claims_by_control=..., mode=...)` applies that same assessment primitive to an explicit planned roster. It never adds a reconstruction control or extra claims implicitly; the generated rehearsal can retain its previous roster, while the scientific caller explicitly requests the frozen source/reconstruction/marked correct/wrong claims. Images are persisted into distinct clean-assessment namespaces before readout.

`attack` accepts a path-free no-argument operation returning the shared `OperationResult`. It retains an explicit failed condition and any operation/safety/timestep receipt on exceptions. It performs no retry or source substitution. Actual DDIM, VAE and centered patch math remains in `m1_confirmatory_image_operations`; the caller supplies fixed upstream saved arrays and graph/control identities. `comparator_enroll` persists unchanged v5 output and full codec report, retaining failed self-verification in that report rather than discarding the source. The comparator's deterministic A4 seed metadata limitation remains visible.

`propagate_missing` copies the declared unit inventory and repeatedly marks dependent planned rows `missing_dependency`, preserving IDs and denominators. A completed descendant with missing upstream is rejected. Unknown IDs/dependencies and duplicate IDs are rejected. Missing descendants never become negative/security successes. Direct failed rows must already carry their explicit error from the caller; this helper does not invent a scientific reason or verdict.

## Remaining integration

The generated `m1_candidate_rehearsal_worker.py` now consumes this library for initialization, enrollment and saved endpoint assessment. Its existing source feature metadata, four clean/VAE condition rows, four pilot claims and full/resume parity checks remain. The worker uses an explicit `generated-hwc-float64` sink boundary for the legacy reference/decoded/residual/surrogate audit arrays; the engine itself retains native shapes. Extra distinct source/reconstruction/enrollment images and quality receipts are retained without inflating the parity condition roster. Full trajectories retain21 initialization plus11 embedding checkpoints; full/resume parity retains its22 overlapping states. Its private PID scope, model context, injections, ownership, timing/resource guards and original sealed adapter are not replaced.

This library is not an executable scientific worker. Official manifest/authority broker and bounded IPC, VerifiedBytes canonicalization/provenance, full frozen schedule/core checks, scientific planned row checkpoint journal, source-oracle audit metadata, per-unit failure finalization, immutable upstream receipts, shard recovery and independent scientific integration remain. Passing mock tests establishes orchestration order and contract behavior, not actual GPU adapter parity, efficacy or confirmatory authorization.

Optional `image_unit` and ordered `query_units` arguments to `assess_image` copy declared inventory metadata. They enforce image/query kinds, image dependency, ordered claims, and exact source/group/method joins. Observed query records preserve `{id,outcome,decision,...}` plus upstream image artifact/pixel identity; image records retain `quality_vs_source`. The caller still binds expected scientific-core/source identity and supplies artifact-verified records to the independent analyzer. The unchanged candidate decision is `s,i,denominators,errors,flags{s,i},state`; v5 keeps its own nested channel fields.

TimeoutError and caller-declared cooperative stop exceptions passed in `stop_exceptions` are propagated after emitting a retained `unit_stopped` event. Other caught attack failures immediately recheck the global stop/budget guard before returning; a bounded process cannot continue merely because an attack failed. The shell must persist that event and missing descendants before finalizing.

CPU command: science interpreter `-m unittest discover -s tests -p test_m1_scientific_unit_engine.py -v`. Nine injection tests cover one shared prefix/full/resume path, distinct source/reconstruction outputs, generated/scientific separation and exact schedule seeds, saved-pixel corruption before detector, retained reader arrays/claims, explicit clean control roster, source-owner binding, exact normalized query joins, timeout propagation and transitive failed-descendant propagation. `test_m1_candidate_engine_integration.py` additionally executes the generated worker with the real engine/sink and explicit mocked model context, checking all4 condition rows,21+11 checkpoints, separate reconstruction images and exact legacy HWCfloat64 layout. No raw dataset bytes, local model assets or GPU work are used.

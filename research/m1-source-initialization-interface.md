# Original200 source initialization adapter

Mechanical preparation, 2026-10-04. `scripts/m1_source_initialization.py` is candidate independent and implements the unmarked reconstruction equations of `m1_latent_reconstruction.py`. It does not adopt a candidate, admit sources, authorize execution, load assets, resolve image paths or open held-out data. No scientific readiness follows from its CPU fixture tests.

## Inputs and preserved operator

The caller supplies an already authorized detached FP32 `[1,3,H,W]` target in `[0,1]`, the already pinned frozen FP32 eval VAE on the same device, and JSON identity metadata containing `source_id`, `source_rgb8_sha256` and `model_sha256`. Upstream owns native RGB eligibility, EXIF/ICC canonicalization, bicubic512 preprocessing, admission and byte/model hash verification. The adapter checks tensor/model mode and precision, records the entire identity dictionary, and independently hashes target tensor shape/dtype/bytes. Identity is a caller-provided receipt, not independent proof that the model matches its asserted hash. Tiny target shapes are permitted for CPU mechanics fixtures; scientific workers must enforce512 upstream.

The adapter uses `vae.encode(target*2-1).latent_dist.mode()` without multiplying the scaling factor. The trainable latent starts from its detached clone. Decode is `(vae.decode(z,return_dict=False)[0]+1)/2`; optimization uses non-reentrant decoder checkpointing, raw decoded RGB MSE, and default `torch.optim.Adam([z],lr=.02)`. Exactly200 completed updates are required for `final()`. Decode observations occur at0/50/100/200, in the original loop order. RGB8 is clamped `[0,1]`, permuted HWC, transferred to NumPy, multiplied by255, rounded by NumPy and cast uint8. The last updated latent is selected without quality filtering or best-step selection. No source residual or watermark is composed.

`ReconstructionSession(target,vae,identity,resume=payload)` creates/resumes state. `advance(to_step=200,on_update=callback)` performs updates; every Adam update is followed immediately by a finite-latent check before recording its completed step or calling the optional callback. The callback runs after each completed update and that step's observation, so it can journal, enforce resources or save/stop. It must not alter the model, target or latent, and any callback RNG consumption must be identical under replay. `save(path)` rejects an existing destination or temporary receipt, exclusively creates and fsyncs its same-directory temporary receipt, then atomically hard-links the final name without overwrite before unlinking the temporary name. A filesystem lacking hard-link support fails closed and retains the temporary file; callers must use supported local storage and unique step filenames. `load_checkpoint(path)` loads an owned receipt using `weights_only=True`. `reconstruct_source(...)` is the200-update convenience wrapper. `final()` returns CPU unscaled `z`, posterior `initial`, fixed step/units, final RGB8 tensor and raw MSE/displacement.

## Checkpoint semantics

Schema `m1-original-source-initialization-v1` contains completed update count, unscaled latent and initial posterior, full Adam moments/step/parameter groups, Python/NumPy/Torch CPU and all initialized CUDA RNG states, all observations through the completed step, immutable operator configuration, source/model identity, target tensor digest and runtime flags. All persisted tensors are detached CPU clones, preventing later optimizer updates from mutating an in-memory receipt. RNG restores after constructing/loading Adam and never reruns encode or an existing observation. Step0 has no Adam moments. Step200 resumes as a no-op and returns the existing final observation.

Checkpoint boundaries are **after** the observation of their completed step. The original script's10-step restart receipts were saved before the next iteration's observational decode and were incomplete; this adapter's new schema does not accept those legacy receipts. This boundary is operator equivalent for the deterministic frozen eval VAE. A stochastic Torch tiny decoder additionally demonstrates original complete-loop RNG ordering and uninterrupted-versus-interrupted equivalence for this new schema.

Resume rejects mismatched schema/config/identity/target/runtime, changed Adam parameter groups, missing moments, incorrect optimizer step, malformed/nonfinite latents/moments and incomplete observation coverage. A recursive SHA256 digest covers every checkpoint field/tensor byte. It detects accidental corruption, not adversarial alteration or authorization; the official caller must pin the file's external SHA256 and enforce its capability/recovery policy. Runtime captures `CUBLAS_WORKSPACE_CONFIG`, compiled CUDA version, initialized cuDNN version, actual CUDA device name/capability and backend/thread flags without selecting their policy. CUDA states and device/cuDNN queries occur only if CUDA is already initialized; cuDNN version is null for a fresh CPU-only session because querying it initializes CUDA on this bundled Torch build. The final CPU test suite verifies this guard and does not initialize CUDA or load models. An earlier failed test and cheap diagnostic exposed the unconditional cuDNN query's initialization side effect before this guard was added; no scientific GPU computation occurred. Runtime flags cannot guarantee cross-driver determinism; caller provenance must pin drivers too.

# B3 prospective DiffusionDB 2M metadata-only part-selection rule

Issue [#10](https://github.com/Eshahi/Dynamic-image-ownership/issues/10), draft PR [#60](https://github.com/Eshahi/Dynamic-image-ownership/pull/60). Status: **prospective, synthetic-tested rule only**. No `metadata.parquet`, image partition, prompt record or image was downloaded or inspected. No actual part ID, source image ID, right-to-use verdict or study split is frozen. The user will acquire source bytes personally under [the handoff](../data/user-acquisition-handoff.md).

The selected source is the curator's **DiffusionDB 2M PNG** repository at revision `fb620fbe49fa4420e0734bd9c0df11f51176b61f`, not the 14M WebP release. Its [dataset card](https://huggingface.co/datasets/poloclub/diffusiondb) describes 2,000 thousand-image parts and a separate `metadata.parquet` with image name, part ID, prompt, dimensions and two NSFW scores. Curator scores are imperfect; this rule is a conservative candidate screen, **not** proof an image is safe, rights-cleared or independent. The [curator datasheet](https://github.com/poloclub/diffusiondb/blob/main/datasheet.md) also points to Stability AI terms. Never commit raw prompts or user identifiers.

1. Hash-rank the 2,000 part IDs `1..2000` with `SHA256(UTF8("b3-diffusiondb-part-v1") || 0x00 || revision_bytes || uint16be(part_id))`, breaking ties by numeric part ID. Only the first **eight** parts in that fixed order are candidates. Do not pick the first files in the browser or search for parts yielding favorable method outcomes.
2. After the user supplies the hash-checked metadata, a separately checked Parquet reader converts relevant columns to ordinary Python values. Validate every part ID as an integer in `1..2000` before filtering; used candidate parts need exactly 1,000 rows and overfull parts block. For candidate rows, require canonical lowercase UUIDv4 `.png` names, unique image names, positive integer dimensions, and finite NSFW scores in `[0,1]`, except the curator-documented `image_nsfw=2.0` already-blurred sentinel, which is always excluded. Other missing/malformed required values block. Empty text prompts are explicitly counted eligibility exclusions; null/nontext prompts remain errors.
3. Prospectively screen out dimensions below `64×64` (the LPIPS/A4 minimum is 63×63) and either curator NSFW score **at or above 0.10**. This 0.10 cutoff is a conservative project choice, not a curator-recommended safe threshold or a substitute for later visual/content review. Keep score-based exclusion counts. If empirical score distribution or rights review makes the protocol infeasible, stop and record a reviewed amendment **before** image IDs or outcomes are exposed; do not tune the cutoff to study results.
4. Normalize prompt text by Unicode NFC, case folding and whitespace collapse solely to form a private `SHA256(UTF8("b3-prompt-group-v1") || 0x00 || normalized_prompt_utf8)` grouping key. Count at most one prospective independent exact-prompt group across candidate parts. This is an early conservative metadata screen, not a full near-duplicate or user-dependence audit; B4 must retain or strengthen grouping after image bytes are checked.
5. Take the **shortest prefix** of the ranked candidate parts containing at least **6,000** metadata-eligible distinct prompt groups: the unchanged 5,000-image commitment plus 1,000 reserves for later image-level integrity, rights/content and duplicate exclusions. This is a bounded download-list criterion, not a final-image-selection algorithm. A missing ranked part in the metadata blocks the handoff instead of being skipped. If all eight parts are present but still provide fewer than 6,000 groups, return `blocked_insufficient_metadata_eligible_groups` with **no** user image-partition request; do not shrink 5,000 or silently expand the cap.

The standard-library pure function and synthetic tests are in `scripts/b3_diffusiondb_selection.py` and `scripts/test_b3_diffusiondb_selection.py`. It takes normalized row dictionaries, never parses Parquet itself, never fetches network data, and returns only a candidate **part** list/counts. After actual metadata arrives, a separately verified adapter and an exact hash/rights receipt are required before publishing any user-operated second-batch image ZIP list. After those images arrive, freeze item-level IDs, bytes, exclusions, exact/near-duplicate groups and deterministic replacements; only then can B3/B4 consider an eligible manifest and split. No method outcome may inform either selection.

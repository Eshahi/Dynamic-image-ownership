## Approval-file and rehearsal route

The current supported dispatcher has no approval-free execution path. This is true in both `thesis-agent-skills/src/thesis_agents/compute.py` and the bundled runtime used by `dispatch_experiment.py`: `dispatch(..., execute=False)` returns a dry-run preview; `execute=True` with no approval raises `Explicit matching human approval required for execution`. Providing an approval dictionary in memory would still assert an approval and is not a suitable workaround for the user's prohibition.

`m1b_coco512_worker.py` explicitly supports direct `data_split="development"` execution. Its `main()` calls `bind_manifest()` and `check_approval()` only for `test` and `rehearsal`. This allows a real development worker exercise without an approval file, plus a separate dispatcher dry-run. Those two checks are useful and authorized, but must not be represented as the requested full pipeline executing through the dispatcher. Existing `m1b_make_rehearsal.py approve` writes a delegated approval and must not be used for this task.

The brief expressly authorizes extending the existing dispatcher with the registry protocol, and the user has already authorized development rehearsals without approval files. A narrow development-only execution mode in that existing dispatcher is therefore a defensible implementation route without asking for a new scientific decision: require the versioned registry rehearsal protocol, local USD 0 execution, development or synthetic sources checked against held-out IDs and hashes, no test split, and retain the ordinary exact-manifest human approval requirement for every held-out run. Record development authorization honestly rather than fabricating an approval object, approval digest or actor. The worker and dispatcher must independently reject held-out source records before any image access. This is new implementation work, not an existing supported no-approval route; it needs the ordinary package tests and whole-package review. If such an extension is not implemented, report the live dispatcher rehearsal as incomplete.

An unfilled approval template may be shown as review text because the brief expressly asks for one; do not save an approval JSON, including a placeholder or delegated rehearsal approval. The exact held-out manifest remains for the user's later approval, and no held-out execution is authorized now.

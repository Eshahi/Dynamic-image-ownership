# Candidate-independent worker contract scaffold

CPU infrastructure only, 2026-10-04. Scientific candidate remains UNRESOLVED. This implementation supplies a concrete adapter/ledger seam for the existing lifecycle harness; it is not a second official launcher, an executable scientific manifest, an unlock or a replacement scientific method. No held-out content, model execution, approval/gate record or scientific output was produced.

Files: `scripts/m1_confirmatory_worker_contract.py`, generated fixture `research/m1-confirmatory-worker-fixture.json`, tests `tests/test_m1_confirmatory_worker_contract.py`. The implementation imports the existing atomic/hash/envelope helpers and `OwnedJobProcess`; it imports no models, PyTorch, image corpus, annotations or candidate code. Its only image adapter generates RGB8 PNG bytes using stdlib and a public uint64 seed. Pixels are fixtures, not watermarks or measured scientific results.

## Integration API

- `validate_plan(plan)`: exact schema/mode/candidate and condition metadata; fixed condition IDs, UID/group, method/axis/arm, claimed owner,16hex-digit uint64 seed and dependency DAG. Reject duplicates, extra fields, undeclared dependencies and cycles. Scientific-plan **metadata** may name original-A/A-C for prospective interface tests; this grants no execution or source access. It deliberately has no raw-path/config/model/annotation field.
- `initial_inventory(plan)`: materializes every planned condition with `not_attempted`, empty artifacts/stages and missing human verdict. The future parent must persist this before any scientific work.
- `safe_artifact(output,relative)`: output-root/path/symlink containment. `completed_receipts(row,unit,output)`: exact unit identity, finite duration, completed stages and nonempty distinct intact artifact hash/size receipts under `<output-root>/units/<condition-ID>/`. This verifies generic artifact integrity; it does **not** validate candidate-specific numeric metrics/decisions or grant a scientific gate.
- `reconcile(plan,observed,output)`: exact fixed denominator, no extra/duplicate rows; missing remain planned/not_attempted, malformed completed receipts become failed with original row retained. Reused output artifact paths cannot be accepted as another condition's fresh output. Transitive failed dependencies invalidate dependent completion independent of row order. Shared source/checkpoint inputs should be upstream dependency receipts, not duplicated output artifacts. This function performs no statistical inference; parent owns separate conservative endpoint/missingness arithmetic.
- `execute_fixture(plan,id,fixture,output)`: refuses scientific mode before directory/source I/O, generates/saves one PNG in a rehearsal directory, retains initial and final unit receipts/stages, preserves injected generate/save/finalize errors and any partial PNG, refuses overwrite. Fixture fields have no external path: only dimension1..512, finite delay0..1s and one explicit failure phase. Every fixture record says `scientific_verdict=NOT_EVIDENCE`.
- `launch_fixture(...)`: bounded owned-child integration seam. It persists full planned ledger before launch, binds the generated request by byte hash, uses the existing suspended-create/assign/journal/resume Job helper and closes/reaps only that owned tree. A timeout/interruption/failure is retained in the fixed ledger; other conditions stay not_attempted. Ownership receipts are persisted before resume/termination. This is a single-unit helper, not a second shard journal/recovery implementation. Existing official-envelope verification is re-exported; a future official parent must require that verified envelope before accepting any scientific adapter.

The internal fixture child CLI accepts `--fixture-request --request-sha256 --fixture-output`; these are private adapter arguments, not the official `--manifest --output-dir` worker interface. The existing harness continues to own that official interface and synthetic-only rejection. Both direct fixture output and owned child output are restricted to MAIN/worktree `.thesis-build/rehearsal/`. No scientific raw resolver/unlock exists. A reviewed future launcher must provide the exact official envelope and authorized raw-index capability, then bind source/model/core/runtime receipts and candidate-specific schemas before this seam can perform scientific work.

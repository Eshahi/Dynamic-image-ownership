The three informal method families—direct DCT, semantic method, and existing-image latent method—are **coverage roles**, not a requirement to execute three extra external packages. A5 C6 plus one explicit pixel comparator, one neural decoder, and one inversion comparator cover the proposal's causal/computational questions if their I/O and rights become sound. One method may cover two roles only after inspection demonstrates both; no implicit substitution or elimination of the inversion and neural-decoder obligations.

The pixel-control reference's `score_pixel_dct` accepts the **correct supplied template** and implements only A5's across-block mean-centered component cosine with a zero-variance veto. The pure-Python pHash routine accepts canonical RGB8 and q projection accepts a supplied normalized embedding. The [model-free candidate-search reference](b2-candidate-search-vector-20260924.md) now tests the bounded q/H neighborhoods and common-q decision, including a separately flagged cross-q-only case. Its pixel-control integration takes **supplied** suspect q/H and RGB8, derives all candidate keys/templates, and caches image DCT observations with one transform per block. It is still not the blind A5 detector: there is no suspect-derived CLIP embedding, complete OwnerID/config validation, canonical PNG decoding, source provenance or full verification timing. Synthetic q/pHash/search/image tests check arithmetic and decision logic, not watermark effectiveness, false positives, image quality or robustness on a study image.

## Common evaluation and knowledge profile

Use the immutable proposal's final data commitments (1,000 MS-COCO, DIV2K 800 source-train +100 source-validation, 5,000 DiffusionDB), with verified exact releases/IDs/licenses and study splits from A4. Do not claim that a generated-only method covers real images. If a baseline cannot process a source because of native size/color/payload/route, preserve the failure and report a restricted compatible subset *alongside* full A5 coverage; never relabel that subset as the committed complete dataset. Matched-quality comparisons must use aligned original-to-output PSNR/SSIM/LPIPS with the same metric versions and denominators, not whichever paper's reported mean is favorable. Detection thresholds and any fairness matching parameters are selected on development/validation only, then locked. Compare ROC/AUC and TPR/FPR at a common declared operating point where the method supplies continuous scores. A decoder's bit accuracy and A5's owner/instance `both_match` are different endpoints; do not pool them.

The core A5 verifier sees only suspect image `J`, tested public OwnerID and frozen model/config; inversion comparators see their own declared model/key/prompt inputs, and any additional original image/enrollment key is disclosed as an **oracle** access profile. Record algorithm, preprocessing, payload rate, Q/K, access, output size, per-source failures, wall-clock warm/cold full verification latency, accelerator/CPU model, peak memory and synchronization boundaries. Report A5's DCT-only component time separately but never compare it against a baseline's full detector. Paired comparisons use the same independent source groups and A4's uncertainty/multiplicity rules; no noninferiority conclusion from nonsignificant difference. Test-set information cannot choose a favorable candidate or strength.

### TrustMark Q/BCH_5 offline payload/decision boundary

`scripts/trustmark_profile.py` proposes a model-free, fail-closed boundary for the
prospective Q/BCH_5 binary profile. It takes a **future manifest-supplied**
32-byte seed (64 lowercase hex digits) and the dataset, version and image ID.
For reproducibility, the 61 bits are the first 61 most-significant-first bits
of `SHAKE256(b"b2-trustmark-q-bch5-payload-v1\x00" || seed_bytes ||
uint16be(len(UTF8(dataset))) || UTF8(dataset) || ...version || ...image_id)`.
Identifiers must be nonempty and unpadded. A fixed *synthetic* vector with
seed `0123456789abcdef` repeated four times, dataset `COCO`, version
`2017-val`, ID `000001`, gives
`0101000111111011101101101001010010111001110100010110110101101`.
The exact study seed and image IDs have **not** been chosen or inspected;
the candidate schedule must be reviewed/frozen in the exact manifest before
test use. These pseudorandom bits are a neutral neural-comparator payload,
not an OwnerID or cryptographic proof of image ownership.

The pinned upstream `TrustMark.decode(..., MODE='binary', DETECTFIRST=False,
ROTATION=False)` returns `(decoded, detected, version)`. Its BCH_5 version is
`1`; `detected` reports ECC validity, while exact equality of the recovered
61-bit payload to the expected ID payload is a **separate** endpoint.
`classify_decode` rejects malformed/wrong-version successes, emits both
`ecc_valid` and `payload_match`, and always leaves `score=None`. Thus Boolean
presence/FPR can be considered with unmarked controls; matched-payload
recovery and wrong-payload controls must be reported separately. It neither
provides continuous ROC/AUC nor makes neural watermark presence equivalent to
A5's owner/instance-binding task. The upstream paths are the pinned
[`trustmark.py`](https://github.com/adobe/trustmark/blob/2ecb73ad28d1a3f66ac9dc19e1b667711f14314f/python/trustmark/trustmark.py)
and [`datalayer.py`](https://github.com/adobe/trustmark/blob/2ecb73ad28d1a3f66ac9dc19e1b667711f14314f/python/trustmark/datalayer.py).
No upstream code was copied into this helper. Six model-free TrustMark
receipt/profile tests pass; no model, image, dataset, or scientific run was
performed. Asset SHA-256 receipts, safe loader, image parity, environment and
exact-manifest compute authorization remain blockers.

Selection is prospective. If a candidate fails feasibility or rights checks, preserve the failure evidence and propose an in-scope alternative *before* evaluating test outcomes. `configs/baselines.json` records these selections as blocked, non-runnable descriptors rather than executable commands.

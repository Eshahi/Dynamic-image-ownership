## Actual adapter path

A literal integer generator constructs two RGB512 fixtures in process. Unit indices 0/1 select offsets in that generator; the seed roster [0,1] denotes those literal units, not stochastic scientific embedding seeds. PNG bytes pass through `m1_canonical_source.canonicalize`. There is no source-path argument and no raw held-out access. Both units share the same fixture construction and do not establish independent source evidence.

The worker consumes the new shared `CandidateModelContext`, which loads only pinned local SD1.5 VAE/safety assets, CPU CLIP and CPU LPIPS, after network blocking and strict deterministic configuration. It supplies the existing helper feature coordinates to `CandidateAdapter`: helper FP32 Torch normalization followed by exactly one adapter FP64 NumPy normalization, matching development E2E. The context adds none. It calls actual `CandidateAdapter.initialize`, `embed`, and `readout`. Original initialization is 200 unmarked FP32 Adam updates at .02, followed by a fresh 100-update embedding Adam at .01. The existing source-bypass operator and quality-only cap are unchanged. The native public VAE reader remains FP16. Frozen reader/safety models move to CPU during gradient phases and return to GPU for persisted outputs, as in the current development execution placement.

The generated owner is alpha; alpha plus three wrong owners give sixteen diagnostic queries over C0-source/C1 crossed with clean/VAE cycle. The scientific core supports twenty owners; this four-owner fixture roster does not rehearse every photo/owner assignment. Source and same-arm clean PSNR/SSIM/LPIPS are retained, with CLIP source cosine descriptive only and human verdict missing. Every model output is checked by the pinned safety checker. Canonical C0-source stays the original generated image.

## Ownership and recovery

Before model imports, the worker validates an inherited private token and a capability issued after suspended-child Job assignment. It binds manifest, plan, worker/core hashes, actual child/parent PID, Job receipt, exact MAIN rehearsal directory, unit, scenario, stage, stop point, upstream receipts and expiry. This guards accidental unsafe invocation; it does not claim cryptographic isolation against malicious same-user code.

Initialization prefix stops at completed update100. Explicit resume requires a same-core, same-source, same-model/runtime completed prefix and its exact sealed checkpoint receipt. It restores the adapter initializer's Adam and all Python/NumPy/Torch CPU/CUDA RNG states, finishes update200, then starts the adapter's fresh embedding phase. No optimizer reset is hidden and no best checkpoint is selected. Checkpoints are exclusive files every10 updates, with sealed adapter configuration, binding, phase and state. The journal, heartbeat, run receipt and four planned endpoint rows preserve incomplete/error attempts.

`audit_rehearsal_run(directory)` validates committed dependency receipts, exact artifact inventory, journal, pinned model identities, generated source identity, fixed checkpoint membership, each wrapper seal, initialization target/config/Adam, embedding initializer/features/config/Adam, and RNG structure without changing global RNG. It also checks saved PNG identity, recorded finite quality conjunctions, four endpoint/sixteen owner inventory and independently recomputes blind scores from saved reader latents/features. It does not recompute model-based CLIP/LPIPS observations.

`compare_full_resume(full,resumed)` returns `{passes,checks,overlap_checks}`. All six checks must pass: original200 endpoint, embedding100 Adam/RNG endpoint, exact endpoint RGB8, exact blind decisions, and exact membership/value parity at all22 overlapping initialization100..200 and embedding0..100 checkpoints. Tensor/state content digests compare values, not incidental torch.save ZIP bytes. A false check is a failed rehearsal audit, never a scientific negative.

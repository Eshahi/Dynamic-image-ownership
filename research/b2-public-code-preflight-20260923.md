## ZoDiac targeted pinned code trace (additional read-only inspection)

The pinned [README](https://github.com/zhanglijun95/ZoDiac/blob/89f864d2e4f6f33663dc69b4d99bee49073e194c/README.md) instructs `conda env create -f environment.yml` and a notebook demonstration; the actual tree has lowercase [`example.ipynb`](https://github.com/zhanglijun95/ZoDiac/blob/89f864d2e4f6f33663dc69b4d99bee49073e194c/example.ipynb), not a single reproducible scientific CLI command. Its example config chooses `stabilityai/stable-diffusion-2-1-base`, 100 latent-optimization iterations, watermark seed 10, a 0.92 SSIM postprocess target and 0.9 detection threshold. These are **upstream example settings**, not adopted A4 thresholds or fair matched conditions. The notebook reads `example/input/pepper.tiff`, uses `WMDetectStableDiffusionPipeline` with `DDIMScheduler`, inverts the existing image, optimizes its initial latent with Adam and 50-step denoising, saves a PNG, then calls `watermark_prob` on the suspect image. The pinned [`main/utils.py`](https://github.com/zhanglijun95/ZoDiac/blob/89f864d2e4f6f33663dc69b4d99bee49073e194c/main/utils.py) detector VAE-encodes that image, runs 50-step forward diffusion, and applies `GTWatermark.tree_ring_p_value` in [`main/wmpatch.py`](https://github.com/zhanglijun95/ZoDiac/blob/89f864d2e4f6f33663dc69b4d99bee49073e194c/main/wmpatch.py). The example passes an empty tester prompt; this is an observed example access profile, not proof of every paper setting. No owner or source image is passed to that detector function, but it does receive the diffusion model, text embeddings and watermark pattern object; it cannot be equated with A5's OwnerID verifier.

The pinned [`environment.yml`](https://github.com/zhanglijun95/ZoDiac/blob/89f864d2e4f6f33663dc69b4d99bee49073e194c/environment.yml) is Linux/CUDA-oriented (Python 3.10.13, PyTorch 1.13.1/CUDA 11.7, Diffusers 0.21.4, Transformers 4.37.2, Datasets 2.14.6). Its direct conda recreation is not a Windows 5070 Ti compatibility result. The notebook also includes attack and dataset-loading cells; executing the whole notebook would be a scientific/network-capable run, not a harmless probe. This inspection did **not** download, import or execute source, models or data. It did not establish code reuse rights, checkpoint hash/terms, performance, memory fit, complete parity with the paper or a safe isolated adapter.

## InvisMark targeted pinned code trace (additional read-only inspection)

The [`Demo.ipynb`](https://github.com/microsoft/InvisMark/blob/8d5ce55705ada1c2daf642c97f7ff3ae6dbd1825/Demo.ipynb) calls `load_dataset("OpenDatasets/dalle-3-dataset", ... train[:5%])`, converts images to tensors normalized to `[-1,1]`, and calls `torch.load('../saved_ckpts/paper.ckpt')`; the external checkpoint was not acquired or trusted. Its displayed example creates a UUID-derived 100-bit secret, runs `Watermark._encode(inputs, secret)`, then `_decode(final_output)` and reports PSNR, SSIM and bit accuracy for the first batch. It does not expose a declared image-level presence score, negative-image calibration or the proposal's OwnerID/instance-binding endpoint. The `Demo.ipynb` source is a network-capable experimental notebook, not an adapter command.

In pinned [`train.py`](https://github.com/microsoft/InvisMark/blob/8d5ce55705ada1c2daf642c97f7ff3ae6dbd1825/train.py), `_encode` resizes the normalized input to the checkpoint-configured `image_shape`, encodes at that shape, upsamples the residual to the original image dimensions, adds it to the original, and clamps to `[-1,1]`; `_decode` resizes the suspect and passes it to the learned extractor. The checkpoint's actual `image_shape` is **unknown** until the file is safely inspected; [`configs.py`](https://github.com/microsoft/InvisMark/blob/8d5ce55705ada1c2daf642c97f7ff3ae6dbd1825/configs.py) defaults to 256×256, 128 encoded bits and ECC, which cannot be substituted for the advertised 100-bit/no-ECC weight profile. [`model.py`](https://github.com/microsoft/InvisMark/blob/8d5ce55705ada1c2daf642c97f7ff3ae6dbd1825/model.py) uses pretrained ConvNeXT for the extractor and returns sigmoid bit outputs; [`metrics.py`](https://github.com/microsoft/InvisMark/blob/8d5ce55705ada1c2daf642c97f7ff3ae6dbd1825/metrics.py) thresholds bits at 0.5 for bit accuracy. The `Watermark` constructor also builds pretrained/loss/training components and a local TensorBoard writer; `load_model` uses unrestricted `torch.load` and restores optimizer states. An isolated inference-only adapter must avoid implicit downloads, unwanted logging side effects and unsafe loading of untrusted serialized checkpoint objects; this code is **not** such an adapter. No code was executed, checkpoint downloaded, or performance inferred here.

## Bounded alternative and access check, 2026-09-23

This check asked whether an already packaged, clearly licensed method could replace the **existing-image inversion** role without adapting a generated-image method. The official [MarkDiffusion README](https://github.com/THU-BPM/MarkDiffusion) lists eleven implemented schemes, including Tree-Ring and SEAL, but does not list ZoDiac; its displayed quick-start calls `generate_watermarked_media(input_data=prompt)` before inversion-based detection. Its published package is useful context and may later aid attack/evaluation tooling, but this evidence does **not** establish a licensed, comparable existing-image signing route. The [Stable Signature official repository](https://github.com/facebookresearch/stable_signature) likewise describes watermarking latent-diffusion *generation* through a modified decoder, not signing the pre-existing image under ZoDiac's protocol. Neither is substituted for the required comparator. This was a bounded screen of these public leads, not an exhaustive claim that no alternative exists.

Fresh public GitHub API inspection of [ZoDiac at the pinned commit](https://github.com/zhanglijun95/ZoDiac/tree/89f864d2e4f6f33663dc69b4d99bee49073e194c) found 52 tree entries, `truncated=false`, no `LICENSE`/`LICENCE`/`COPYING`/`NOTICE` path, and repository `license=null`. This confirms only that no code license was found through those checks; it does not determine all possible permissions. An unauthenticated request to the exact model repository named by its example, `https://huggingface.co/api/models/stabilityai/stable-diffusion-2-1-base`, returned HTTP 401 in this environment. Search-indexed model-file metadata advertises OpenRAIL++ and a safetensors pointer, but the exact model card, applicable terms, revision and full weight-file hashes could **not** be authenticated here. No alternate mirror is silently treated as equivalent. These two independent blockers leave ZoDiac `BLOCKED_CODE_RIGHTS_CHECKPOINT_ADAPTER_AND_ENVIRONMENT`; no weights or code were acquired or run.

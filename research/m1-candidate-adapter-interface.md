# Reusable conditional A-C end-to-end adapter

Version `m1-terminal-continuous-e2e-adapter-v1`, preparation2026-10-04. `scripts/m1_candidate_adapter.py` is a new path-free orchestration layer. Candidate selection is conditional; this module supplies no scientific gate, data admission, held-out authorization, model loading, asset verification, owned-process capability, attack operator or lifecycle readiness claim. It does not change the live development/e2e numerical modules.

## Explicit inputs and numerical reuse

`CandidateAdapter(vae_fp32,vae_public,processor,feature,profile,model_identity)` consumes already verified models and public preprocessing. Both VAEs are frozen eval with scaling factor.18215; the embedding VAE is FP32 and public VAE is FP16. `feature` returns raw CLIP coordinates. The adapter applies the existing finite512-vector normalization once, using it identically for the source oracle and unchanged `m1_terminal_continuous.PublicReader`. Passing an already normalized extractor is discouraged because it would add another normalization operation. The embedding worker must supply the same raw extraction function as its frozen numerical operator.

`model_identity` requires caller-verified lowercase64-digit SHA256 strings under `vae_fp32`, `vae_public`, `clip`, `profile` and `scientific_core_sha256`. The caller computes the scientific core over every executed adapter/initializer/embedding/reader/CLIP/pHash/owner/numerical-config dependency and pins package/environment provenance. A version string alone cannot authorize resumption. The actual profile is also hashed canonically inside the binding, independent of its caller-provided file/model receipt. This module validates receipt syntax and equality; independently verifying the loaded bytes against those identities belongs to the worker.

All source input is an already authorized canonical NumPy RGB8 array of shape512x512x3, never a path. The worker owns raw SHA verification, RGB eligibility, EXIF/ICC handling, bicubic512 canonicalization and data admission. A resolver-supplied `source_identity` must contain `source_id`; optional asserted `source_rgb8_sha256` must match the independently computed canonical hash. Arbitrary receipt metadata stays bound to checkpoints. The adapter requires the caller's already configured deterministic policy: workspace`:4096:8`, deterministic algorithms with errors, deterministic cuDNN, benchmark false and both TF32 flags false. It captures runtime and fill-uninitialized-memory policy, but does not configure CUDA or change numerical settings.

`initialize(rgb,source_identity,owner,source_uid=None,resume=None,stop_step=200,on_checkpoint=None,check=None)` delegates to `m1_source_initialization.ReconstructionSession` exactly. It preserves posterior-mode unscaled latent, original raw RGB MSE, Adam.02, original observations and fixed200 last-step selection. Fresh phases seed Python/NumPy/Torch to0 immediately before encoding; resumes restore the saved initializer RNG through the unchanged session. Stops are scheduled0..200 multiples of10. The returned phase checkpoint contains the complete original session state.

`embed(rgb,initializer,resume=None,stop_step=100,on_checkpoint=None,event=None,check=None)` requires the completed200 initializer and imports its unscaled `u0` tensor directly. It computes source-only E/H and constructs unchanged `FixedSourceScores` for the explicit owner. After this preparation a fresh embedding phase seeds execution RNG to0 and calls unchanged `m1_terminal_continuous.optimize` with100 updates, Adam.01/default betas/eps, every-other-step semantic cycle and interval10 checkpoints. The scientific core retains semantic margin6, instance margin8, cycle margin6, quality weight.01 and clamped reference `D(u0)`. No initialization Adam moments are imported. On resume, that core restores the embedding Adam/RNG rather than reseeding. A requested intermediate stop raises an internal cooperative exception only after its normal checkpoint callback; the core's100-update configuration is not rewritten to a shorter method.

Final composition calls the existing `m1_phase_residual.cap` through the component module, using its unchanged source-bypass residual,35.2dB saved-pixel cap and36 bisections. A completed result contains marked RGB8, cap receipt, full core result and the embedding checkpoint. A partial result contains its checkpoint and no marked image. The worker must perform its own safety checks and persist/reopen PNG pixels before readout; no image persistence or human quality verdict is fabricated here.

`readout(saved_suspect_rgb8,owner)` delegates to unchanged `component.detect` and `PublicReader`. Its only inputs are suspect bytes, candidate public OwnerID, public models and profile. Source identity, source E/H, initializer, original source and phase receipts are never detector arguments. The readout preserves the core's inclusive threshold4 and three states. Its current public-reader implementation uses CUDA; analytic CPU fixtures mock that boundary and do not change it for production.

## Owners and seed roles

The accepted public identifiers are the exact twenty strings validated by the extended core: unchanged four development owners plus `thesis:owner:00`..`15`. Supplying `source_uid` calls `m1_owner_interface.source_schedule` and requires the explicit owner to equal its derived enrolled identity. The exact source UID, owner/wrong-owner, canonical decimal/hex uint64 and schedule metadata are bound to the checkpoint. Upstream UID admission/NFC/uniqueness and actual scheduled-unit validation remain worker responsibilities.

The A4 uint64 is explicitly `metadata_only_not_consumed_by_ac_e2e`; `scientific_embedding_seed` is null. There is no scientific/noise-seed parameter on the adapter and none is passed to the numerical core. The consumed fresh phase seed is0; resumes consume saved RNG state. Omitting `source_uid` supports the existing development owner experiment without pretending it is the A4 schedule. Attack and synthetic-host generation seeds belong to their separate worker operators.

## Checkpoints and integration limits

Schema `m1-candidate-phase-checkpoint-v1` seals every field/tensor with a recursive content digest and CPU clones. A phase is explicitly `initialization` or `embedding`, with its own completed-update count, optimizer role and full latent/Adam/RNG. Binding includes canonical source hash, exact source metadata/UID, owner/schedule, model/profile/scientific-core IDs, runtime, memory-initialization policy and seed roles. Embedding checkpoints additionally bind the entire200 initializer content digest and source E/H digest. The initializer and embedding optimizers remain distinct phases; this is200+100 rather than a300-update Adam trajectory.

Resume rejects wrong phase, source pixels, owner/schedule, model/profile/core/runtime, malformed update counts, changed initializer/features, incompatible Adam parameters or missing/nonfinite moments. Checkpoint and event callbacks receive detached copies and must consume no execution RNG; violations fail. Resource `check` callbacks must likewise be observation-only. Callback storage must provide external SHA256 receipts, atomic no-overwrite persistence and retained attempt journals. The self-content digest detects accidental corruption, not hostile forgery or authorization. Phase receipt admission and official execution capabilities remain outside this module.

There is no automatic import of a legacy reconstruction run or bridge, no model-path resolver and no dataset read. A worker may execute the same injected models on authorized generated images through this interface. Candidate-identical generated-image rehearsals, real adapter-vs-e2e numerical parity, model placement/safety/resource checks, fail-closed official admission and full recovery/rehearsals must still pass before readiness.

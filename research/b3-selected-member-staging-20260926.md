## Bounded implementation

[The staging utility](../scripts/b3_materialize_members.py) previews by default. Its CLI requires an explicit hash-bound JSON mapping of canonical PNG member names to raw SHA-256, a completed approved ZIP, pinned archive inventory, hash-bound private native-dimension index and an existing nonlinked output directory. Duplicate JSON keys block, not silently overwrite selection. `--execute` is required for local copies; that is an explicit file-operation flag, **not scientific compute approval or a new workflow gate**. Do not execute against real data until the source-admission list and handling constraints are reviewed. A supplied selection digest authenticates that snapshot only, not arbitrary source admission.

The existing inspector's unchanged archive/index byte verification was factored into `verified_archive_snapshot` and reused: pinned upstream archive size/full SHA, pinned inventory and source index identity, same in-memory snapshot. The staging function then checks the **entire** 1,001-member ZIP frame and all 1,000 native PNG CRC/full decodes before any write, reusing the reviewed directory/resource rules. Every requested PNG name and raw digest must match inspected records. No `extractall`, archive-supplied path construction, ZIP JSON export, model load, resizing or color transformation occurs.

Require an absolute output root so all lexical ancestors can be checked as nonlinks, require a fresh fixed `part-NNNNNN` subdirectory, check storage against selected raw bytes plus 1 MiB reserve, then exclusively create only explicit canonical PNG files with `xb`. Each copy is read from the same verified ZIP snapshot, checked again for exact size/SHA and written unchanged. Existing destinations are never overwritten. A mid-copy failure preserves the new partial staging directory and raises; no success receipt can be inferred from its existence. This ordinary local asset-management helper neither implements B5 preprocessing nor creates `data/manifest.csv`/`data/dev-ids.json`.

# M1 family A: dual signature transported through an optimized VAE latent

Version: `m1-dual-latent-v1`. Date: 2026-10-03. Status: executable development candidate; no GPU experiment has been run by this author. This file freezes the first bounded pilots, not a confirmatory method or an M1 success verdict. Author: method-design agent, gpt-6-astra/xhigh. ## Scientific question and explicit amendments

Can the terminal latent of the pinned SD1.5 VAE carry the existing dual semantic/instance signature into a saved image that the unchanged image-DCT verifier reads, while preserving the source and surviving a VAE cycle? This is a genuine latent decision variable: only `z` changes and all VAE weights stay frozen. The primary output is the entire decoded image `clip((D_vae(z)+1)/2,0,1)`. There is no source residual bypass, pixel optimization, pixel repair, v5 pixel embedder call or diffusion inversion in this primary route.

This is an explicit **terminal-VAE-latent amendment**, not an initial-Gaussian-noise implementation or evidence about a full denoising trajectory. It retains v5 revision 3's documented signature/carrier and detector amendments. The unchanged v5 codec remains a separate image-domain comparator. Reusing its public key derivation and detector does not turn its original pixel embedder into the latent method.

The second manifest is a separately labeled source-preserving hybrid:

`J_hybrid = clip(I + decoded(z) - decoded(z_ref), 0, 1)`.

Its trainable perturbation is generated by a decoder, but its image contains an explicit original-pixel bypass. It is **not** a pure decoder output and does not count as another substantially different design family. Its matched unmarked output uses `z=z_ref`, hence equals the canonical source up to numerical rounding. Pure and hybrid results must remain separate in every table. The current reconstruction results motivate testing the bypass, not hiding it.

The full channel/identifiability/security derivation and the genuinely different initial-noise and progressive-symbol families are in [the derivation](m1-method-derivation-20261003.md).

## Inputs, public signature and detector side information

The input is a reserved development RGB image, EXIF-oriented, ICC-converted to sRGB when applicable, bicubic-resized to 512x512 and retained as RGB8. Raw file and canonical pixel hashes are recorded. These results are evidence at this canonical resolution, not native-resolution image quality.

The pinned CLIP ViT-B/32 encoder produces the normalized source vector `E`. The unchanged v5 mapping forms the 32-bit sign code `q`. Its 8x8 image-DCT perceptual hash yields 32-bit `h`. The owner is `qim-pilot-owner-alpha`. The exact public-derived v5 recipe creates semantic and instance chip patterns:

`Ws = f_s(q, OwnerID, public profile)` and `Wi = f_i(q, h, OwnerID, public profile)`.

Each channel has 32 segments of ten chips, 320 chips total. This is a transport experiment on the existing finite code, not a claim that 32 sign bits preserve CLIP geometry. The geometry evidence motivates a later capacity-aware coding amendment, which is deliberately not mixed into this first placement test.

**Signing-order amendment:** both `q` and `h` come from the canonical source before any watermark update. They are computed once and never re-signed. Original v5 instead signs its instance payload after the robust pixel stage. The new order makes the content being bound explicit and avoids post-hoc target selection. It can fail if the watermark/reconstruction changes the suspect pHash; such failure is counted by the unchanged verifier. No source feature, source code, source pHash, target chip vector or source image is supplied to verification.

Verification receives only the saved suspect RGB8, candidate public OwnerID, versioned detector profile and pinned CLIP weights. CLIP is recomputed from **that suspect** each time. The image extractor uses the original v5 coarse and full-resolution 8x8 DCTs and its exact thresholds/decision table. It requires no VAE, no diffusion model and no inversion. Therefore only the DCT stage is model-light; the complete verifier still pays for CLIP. Quality metrics and source-relative diagnostics use the source as evaluator side information and are never detector inputs.

The loader verifies the pinned CLIP/VAE/AlexNet asset sizes and SHA-256 values in `research/a6-candidate-model-assets.json`; LPIPS package and learned-head checks remain active. No downloads or network calls are enabled by this run.

## Differentiable bridge and fixed optimization rule

`scripts/m1_dual_latent.py` implements the orthonormal block DCT in Torch. For the robust channel it applies exact 4x4 area averaging from 512 to the 128x128 canonical grid, the v5 frequency positions and whitening, recomputed coefficient-energy normalizers, then keyed chip accumulation. Instance projection uses the original full-resolution frequency positions and chip mapping.

The robust activity/slot weights and chip normalization are frozen at the source. This is a **source-weighted training surrogate**. At the source, its two projection vectors numerically reproduce the codec. At a changed image, the real verifier recomputes its image-dependent weights and may disagree. The optimizer does not differentiate through CLIP, code-bit decisions, v5 payload decoding or content-status decisions. These discontinuities are evaluated only by the full saved-image verifier. Source-template surrogate scores are diagnostics, not detections or oracle-aided successes.

For each channel `Z = <projection, source_pattern> / ||projection||_2`; its mathematical maximum is `sqrt(320)`. Let `d = MSE(J,I) / 10^(-35.2/10)`, where image samples are in [0,1], and `a(m,Z) = (max(0,m-Z)/m)^2`. The actual implemented loss is:

```text
clean loss = d + 10 * max(0,d-1)^2 + 8 * a(9, Zs(J))
joint-stage addition = 4 * a(9, Zi(J))
every-fourth-update addition = 8 * a(8.5, Zs(VAEcycle(J)))
VAEcycle(J) = decoded(Encoder_vae(2*J-1).posterior_mode)
```

The VAE-cycle term protects only the semantic channel. There is no loss that deliberately erases the instance component in an attacked output to manufacture the desired three-state label. The second graph is backpropagated separately and gradients accumulate before one Adam update. Cycle updates occur at zero-based iterations 0,4,8,...,96, in both stages. This is a training augmentation; actual saved/redecoded VAE-cycle evidence is separately measured.

Frozen pilot settings are 60 robust-only updates then 40 joint updates; Adam learning rate .01, betas (.9,.999), epsilon 1e-8; float32 model/latent, batch one, seed 0, TF32 disabled, decoder/encoder activation checkpointing, maximum process allocation 10 GiB. The optimization variable is **unscaled VAE posterior coordinates**, exactly as the reconstruction diagnostic. No latent scaling factor is silently applied; the model's factor is recorded. For scale .18215, a .01 unscaled update corresponds to .0018215 in scaled coordinates, apart from Adam epsilon/numerics.

The final fixed update, number 100, is the output. Intermediate checkpoints are retained every ten updates but are not candidates for selecting a favorable reported result. Gradient/loss/latent nonfinites, allocation limits and wall-time limits stop the run and retain a failure. No best-checkpoint selection, loss-weight sweep, source substitution, human-quality guess or held-out tuning occurs in this pilot.

Why margins 9 and 8.5: at the profile's nominal `1e-6` target and one owner, the existing verifier's recomputed-pattern threshold is approximately 4.982 and its `2^32` decoded-search threshold is approximately 8.259. A target of 6 could create mere presence while systematically failing the payload-reading strength needed to observe content mismatch after transfer. Margin 9 exceeds both thresholds; cycle margin 8.5 also targets reading. This is an analytical engineering choice made before this pilot, not a validated robustness or FPR result. Source-fixed weighting, drift, save quantization and code decoding can still prevent either threshold from being reached.

These settings supersede the illustrative loss/optimizer proposals in derivation section 5 for **this executable version**: quality-excess weight 10 rather than 100, source pHash rather than post-robust pHash, unscaled lr .01, 60+40 updates, margins 9/9/8.5. The derivation records this adoption separately, so the earlier recommendation is not misrepresented as the run's preregistration.

## Bounded pilots and failure criteria

The pure and hybrid manifests are [m1-dual-latent-dev.json](m1-dual-latent-dev.json) and [m1-dual-latent-hybrid-dev.json](m1-dual-latent-hybrid-dev.json). Each fixes the first two reserved IDs, 1675 and 4795, in that order. They are development engineering cases, not a random population estimate. The remaining ten reserved IDs remain missing until a separately versioned expansion actually runs them. Two pilot successes cannot be reported as 12/12 or as an M1 target pass.

Both initialize from each image's completed step-200 reconstruction checkpoint in a declared development run. The loader checks source pixel identity, checkpoint SHA-256, latent shape, finite values, step and unscaled units. The reconstruction run itself may have been interrupted after those completed cases; a completed case with intact checkpoint is usable, while an incomplete case is rejected. Starting a watermark optimizer resets Adam; this is a new optimization, not continuation of the reconstruction optimizer. The receipt includes the parent commit, checkpoint hash, saved checkpoint metric row and reconstruction config.

First inspect clean saved-image quality, correct/wrong-owner outputs and paired deterministic VAE-cycle outputs. The strict clean quality conjunction is PSNR >35 dB, SSIM >.9 and LPIPS <.1 relative to the canonical source. Infinite PSNR is represented by `psnr_infinite=true` with null numeric PSNR. Quality failure is retained even if detection succeeds. The quality penalty is not a guarantee. A source-reconstruction failure is not evidence that watermark optimization could meet this quality budget.

The run harness produces enrollment, clean and VAE-cycle controls; **it does not implement the full T3 diffusion grid, T4 transplant attacks or T5 semantic pairs**. The parent-owned `m1_assess_dual_threats.py` consumes the interface below and supplies those conditions with fixed denominators. It must recompute CLIP from each attack result. A development label needs both its channel/content result and its measured quality/content-retention conditions; missing human semantic assessments remain missing. Cases that fail clean quality may still be studied to locate a channel limit, but cannot count as accepted clean samples.

Scaling to all 12 is justified only after checking numerical correctness and learning something from the two-image pilot. If clean source-template scores improve but blind states fail, inspect feature drift, pHash drift, payload read confidence and surrogate/verifier disagreement. If even source-template scores fail at an admissible quality budget, diagnose the physical transport before replacing the code. If source quality dominates the pure route, compare the separate hybrid and perform the bounded reconstruction diagnosis below. None of these outcomes alone establishes a global impossibility or exhausts the three distinct design families.

## Frozen interpretation of detector outputs

The exact v5 `proposal_state`, `outcome`, channel scores, thresholds, decoded code distances and read flags are retained. Added qualified wording makes the inference limit explicit:

| Existing proposal state | Qualified state | What is observed |
| --- | --- | --- |
| `authentic` | `authentic-consistent` | both signatures present with accepted content agreement |
| `regenerated` | `regeneration-consistent` | accepted semantic signature with absent instance signature |
| `copy_paste` | `content-transplant-consistent` | a reliable component reports content mismatch |
| `not_detected` | `no-evidence` | neither component passes presence |
| `unclassified` | `abstain` | instance-only or uncertain content comparison |

Invalid inputs/configurations and execution failures raise and enter the run's failure record; they are not converted to one of the three scientific labels. The verifier's inherited `embedding_domain="image"` field identifies the original v5 implementation and is not overwritten to claim a latent embedder. Actual route provenance lives in `run.json`; the additional `extractor_domain` states image DCT with CLIP and no inversion.

A public embedder can recreate either signature for any public owner name. No result proves cryptographic ownership or excludes public re-embedding. Two components do not identify a causal history: benign editing and regeneration can have the same signature transition; regeneration can preserve both. The theoretical per-test null model does not establish an empirical/adaptive family-wide FPR, especially across owner/decoded-code searches. Wrong-owner tests and the 12 development images are diagnostics, not a confirmatory 1% FPR bound.

## Bounded reconstruction diagnosis before a ceiling claim

The parent's first three finite step-200 endpoints are PSNR 31.003/28.059/27.706 and SSIM .890/.711/.817 for IDs 1675/4795/6012. They motivate this next diagnostic but are not certified optima. The first reconstruction used unscaled posterior latent, Adam .02 and unclamped decoder RGB MSE for optimization, with clamped saved RGB8 for reported quality; preserve those distinctions.

After completion/recovery of the declared 12-image reconstruction inventory, select the highest- and lowest-PSNR **completed step-200** sources, ties broken by numeric ID. Report this adaptive best/worst selection explicitly; these are not new independent observations or a replacement cohort. If the two selected extrema are the same image because only one completed source exists, do not duplicate it.

Recommended first diagnosis: from each selected step-200 latent, reset Adam, lower unscaled learning rate to .005, and optimize the same unclamped RGB-MSE reconstruction objective for exactly 400 further updates. Keep checkpoints corresponding to total updates 300/400/600 and the terminal result regardless of quality. Record original checkpoint hash, new optimizer state policy and exact latent units. Compare saved PSNR/SSIM/LPIPS and float loss with step 200. A gain below .25 dB between total updates 400 and 600 while still failing quality is an operational plateau criterion, not a proof of a decoder manifold floor.

If that arm remains finite but plateaus, a separately committed second diagnostic can use deterministic L-BFGS on the same two step-200 starts: history size 10, lr 1, strong-Wolfe line search, at most 120 closure evaluations, explicit closure/evaluation journaling and fixed terminal selection. Guard nonfinite loss/gradient and retain any line-search failure. It changes optimizer, not embedding family. Use the same unclamped loss, canonical source and saved-image evaluation; changing model, representation or resolution is a separate amendment. No longer-fit or alternate-optimizer run is performed by this implementation.

Report the actual tested endpoints, best observed values clearly labeled exploratory, and how much additional fitting changed the result. If these bounded trials miss 35 dB/.9, the valid conclusion is failure of these optimizer/model/budget settings. A pure route can be de-prioritized in favor of explicit hybrid/progressive/noise alternatives without claiming all latent approaches impossible.

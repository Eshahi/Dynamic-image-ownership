# F6 writer implementation and server rehearsal contract

Author implementation note, 2026-10-28. No scientific computation has run on the laptop. `scripts/tifs_writer.py` is server-only; local validation is syntax compilation with MAIN `.thesis-build/venv/Scripts/python.exe -I -m py_compile` only. Gradient flow, native scheduler compatibility, memory and timing remain unverified until the authorized server rehearsal. This note is not an independent review or an execution approval.

## Adapter

`F6Writer(assets, base_config, frozen_config, internal=None)` accepts the retained stage-2 asset root, unchanged stage2b configuration and the Stage-S frozen machine configuration. `embed(rgb, variant, source_id)` returns `(RGB8, payload, report)` for `f6-noise`, `f6-codec` and `f6-generic`. `close()` releases/offloads GPU resources. Context-manager use is supported. No CLI or laptop rehearsal path is supplied.

An optional existing `encoder_transfer_runtime.Internal` supplies its F5 reader, CPU semantic feature function and profile; its LPIPS object is not needed by the writer. The standalone path avoids loading LPIPS, loads CLIP on CPU and one frozen F5 reader VAE on GPU. SD1.5 codec computations share that same VAE. SDXL weights load lazily at the first R1 surrogate and are moved to CPU after that graph has been differentiated and freed. Generic-only embedding does not load SDXL weights. Its metadata and scheduler configurations are still checked locally on the server. No denoiser or full pipeline is constructed by this writer.

Call `close()` before native K3 loading. A supplied Internal's reader is offloaded too; the caller must not continue using it on CUDA without explicitly restoring it. Any shared Internal LPIPS object remains the caller's responsibility. After a raised exception the adapter closes and is unusable; create a fresh adapter for a subsequently authorized retry. OOM propagates for the orchestrator to classify as RESOURCE_STOP, without an automatic smaller resolution, shorter run, lower precision or dropped arm. Cleanup is best effort and records `cleanup_errors` rather than replacing the original exception.

`validate_writer_config` and `draw_seed` are standard-library functions. Required writer values match the machine freeze; additional descriptive keys are permitted. Both base F5 settings and Stage-S writer settings are checked before model imports. The input is exactly uint8 512×512 RGB. The fixed original seven-view semantic q is computed once per embed. Every later native suspect read uses the suspect's own seven-view features and the unchanged F5 reader with soft binding, band [4,32], whitening 1 and the unchanged profile. Never pass an F6 label into `Internal.detect`: its exact-label dispatch falls through to v5. Route it explicitly as `f5-r2` in the separate read stage.

## Fixed objective and computation

All variants perform 150 initial updates followed by the first inherited fragile write, 50 clean-only refinement updates and the second inherited fragile write. There is no intermediate best checkpoint or image-specific selector. Each initial update differentiates the clean squared-hinge F5 chip loss, frees that graph, differentiates a separate surrogate loss, adds the two input gradients and takes one normalized projected step. The loss weight is one for each term. Refinement differentiates only the clean loss. The target margin is 4. Initial and refinement L2 budgets are respectively 52 and 58 dB relative to their stage input; mask power is zero. The F5 step schedule is retained: 0.2 times the radius during the first half of each stage, 0.05 during the second half. These stage budgets do not imply final-image quality.

Each embed therefore uses **350 reader-gradient evaluations**, with 150 additional encode/decode gradient graphs in each codec writer. Generic uses 150 transform graphs and no codec gradients. These are matched update and reader counts across the three new writers; they are not 150 F5-equivalent evaluations. Diagnostics, final native clean reads, quality metrics and all native regeneration evaluations are additional work, separately budgeted by the orchestrator. Reports include the counts and synchronized elapsed embed time.

The differentiable robust operator uses the exact F5 Layout arrays and float32 tensor DCT/index-add projections. It calls `Reader.encode`, never detached `Reader.latent`, on active input paths. The latter is used only for final RGB8 verification and a rehearsal parity reference. VAE parameters remain frozen; input gradients remain enabled. Clean and surrogate losses have separate serial graphs; only the input leaf and the detached accumulated gradient persist between them.

The codec family cycle is R0 .2, R1 .1, R1 .2, repeated 50 times. Both codecs use their own scaled **posterior mode**, intentionally differing from native evaluation's sampled posterior. Schedulers are loaded only from retained local assets with the unchanged native overrides, set to 20 scheduled DDIM steps, and passed to each native pipeline class's unbound `get_timesteps` method on a scheduler-only object. This obtains the actual first executed native timestep without loading a pipeline. Receipts record all selected timesteps, executed step count, alpha-bar, a/b and the family's VAE scale. Native-method compatibility is a server check.

F6-noise decodes `(a * scaled_mode + b * epsilon) / family_scale`; a=sqrt(alpha-bar), b=sqrt(1-alpha-bar). There is no division by a, noisy-latent normalization, denoiser or rounding in the objective. F6-codec uses exactly the same family cycle and posterior conventions but applied a=1, b=0. Its receipts distinguish native coefficients from the applied ones.

All VAE computation is fp32. R1 operates at 1024 through `pilot.Resize` differentiable Lanczos matrices, with normalized RGB cast through fp16 then back to fp32 before encoding, following the native input-casting convention. Output is decoded to normalized RGB, clipped and resized to 512. Float Lanczos omits PIL RGB8 fixed-point rounding; it is an explicit approximation, not native primal equivalence. Latents and decoding stay fp32 in this surrogate; native evaluation retains its own precision path. No straight-through RGB8 rounding is used.

F6-generic cycles Gaussian blur (sigma1.5, kernel11, reflection padding), bilinear 512→256→512 (antialias=True, align_corners=False), and independent RGB Gaussian noise (sigma .02, clipping [0,1]). This is the frozen local control, not a reproduction of VINE or all EOT methods.

The fragile body is a bounded copy of unchanged `f5_latent_codec.embed_rgb`: robust output rounds to RGB8; fragile h is recomputed from that robust image; the same instance-table chips and `_embed_fragile(..., False, True)` are used; the luminance change is added to all RGB channels and rounded; refinement rounds; final fragile h is recomputed, written and rounded. The report exports this final intended h. Payload `h` deliberately remains the native clean **decoded** h for compatibility with the retained F5 endpoint basis; `intended_h` is a separate field. Original intended q, intended h and clean decoded h are never silently interchanged. Old F5 code and reports are unchanged.

Random draws use SHA-256 over a versioned, canonical JSON tuple of stream, source identifier, variant and update number. Optimization and diagnostic streams are disjoint. There is no Python process hash, global reseeding or K3 writer exposure. The exact seed function is versioned in `tifs_writer.draw_seed`; the orchestration layer should not substitute another seed hash for these writer draws.

## Round 2: writer activation memory and measured device capacity

The F6 gradient scopes enable native diffusers gradient checkpointing on the frozen eval SD1.5 reader VAE used for the writer objective, and on the writer's SDXL VAE when it is loaded. Both encoder and decoder flags are checked. The flags remain enabled through `autograd.grad`, including recomputation, and are disabled on successful return and exceptions, using local references even if writer closure clears the model fields. This scopes the shared reader's setting to writer optimization and writer rehearsal gradients. Final RGB8 native verification, subsequent readers, quality metrics and native regeneration do not enable checkpointing. No retained adapter is changed.

Source inspection confirms that diffusers 0.35.1 [Encoder and Decoder](https://github.com/huggingface/diffusers/blob/v0.35.1/src/diffusers/models/autoencoders/vae.py#L143) select checkpointing from gradient mode and the checkpoint flag, independently of training mode. [AutoencoderKL](https://github.com/huggingface/diffusers/blob/v0.35.1/src/diffusers/models/autoencoders/autoencoder_kl.py#L67) supports it; [ModelMixin](https://github.com/huggingface/diffusers/blob/v0.35.1/src/diffusers/models/modeling_utils.py#L258) installs non-reentrant PyTorch checkpointing by default in the pinned runtime. This supports the existing `autograd.grad` input-gradient path. No custom block wrapper, `.train()`, parameter training, tiling, precision reduction or objective change is introduced. Recomputing activations costs time, so the complete server rehearsal must measure the revised writer cost.

The hardware statement is **24 GB class minimum**, not a fit guarantee. The forecast now uses each receipt's measured `device_total_bytes`, requires that total to be positive and identical throughout the rehearsal, and allows a peak device footprint only up to **measured total minus 1.5 GiB** (1,610,612,736 bytes). It exports total, reserve, limit, minimum and policy alongside the observed peak. A 48 GiB card therefore has a 46.5 GiB limit; a successful writer needing more than 24 GiB is not rejected merely for that reason. Missing totals, changed devices or insufficient measured capacity fail closed. The screen launch must use the same measured device capacity as the rehearsal. OOM still produces RESOURCE_STOP; checkpointing alone cannot establish feasibility.

Pure stdlib tests cover eval/frozen preconditions, both checkpoint flags, lazy SDXL registration, cleanup after closure or partial failure, 24/48 GiB capacity decisions, inclusive reserve boundary, missing/inconsistent totals and allocator high-water accounting. They do not execute a VAE or certify GPU memory, numerical parity or running time. Server rehearsal gradient checks and the full measured inventory remain required.

## Server-only checks and remaining limits

The preparation status is controlled by the current `../FINAL-REPORT.md` and `READINESS.json`; implementation review does not establish scientific compatibility. Follow `RUNBOOK.md` for the later authorized server rehearsal.

On both prespecified rehearsal sources, invoke `validate_rehearsal(rgb, source_id)` before full embeds. It compares tensor projections with F5 Layout's float64 NumPy projection of the same reader latent (atol1e-3, rtol1e-4), checks finite nonzero clean input gradients, checks all three cells for each codec writer and all three generic transforms with disjoint diagnostic seeds, checks frozen VAE parameters, and records q, losses, gradient norms, scheduler coefficients and projection error. It never uses K3. A tolerance failure is an implementation stop, not permission to adjust scientific settings. These checks do not consume optimization draws or alter model weights.

The orchestrator must additionally compare reported native first timesteps/scales against loaded native regenerators; verify the actual saved PNG through the explicit F5 read adapter; measure strict final quality, finite outputs, peak allocated/reserved/device memory and the complete-inventory runtime; and exercise all native families, baselines, T4/T5 and distortions. The writer's returned RGB8 clean verification does not replace a saved-PNG read or the primary native gates. No local syntax check establishes these conditions, SDXL backward feasibility, fp16-cast gradient fidelity, T3 survival, binding security or TIFS novelty.

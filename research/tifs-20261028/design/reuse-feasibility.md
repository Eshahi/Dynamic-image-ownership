# Stage S reuse and F6 implementation feasibility

Codex code-study agent, 2026-10-28. Static inspection only; no models, images, metrics, timing runs or experiments executed. This is an implementation assessment, not a protocol freeze or an independent review. MAIN STATE.md was read once. Scope: the finite noisy-codec candidate in `design/candidate-derivation.md` and its matched codec-only ablation.

## Verdict

**CONDITIONAL-GO for implementation and a server rehearsal.** The retained code supplies all four frozen comparator adapters, native regeneration, coupled random draws, RGB8 output hashes, quality evaluation and most journal mechanics. F6 still needs a new differentiable tensor objective and a new writer wrapper. Neither the existing public embed API nor the native pipeline is an interchangeable differentiable surrogate.

A 24 GB fit is plausible only with serial graphs, serial model families, and controlled reader concurrency. The 15-hour bound is unverified because SDXL decoder-plus-reader backward cost has never been measured here. Preserve the full design and stop on rehearsal extrapolation failure; do not quietly shorten steps or sources. K3's 21.7 GB prompt encoder is a particularly tight transient load on a genuine 24 GB device.

## Exact reusable interfaces

Paths below are repository-relative. Signatures are copied from inspected source. Asset arguments are `pathlib.Path`, not strings.

| Interface | Meaning and reuse boundary |
|---|---|
| `f5_latent_codec.Reader(assets: Path, device: str = "cuda")` | Pass `assets / "a6"`; loads `sd15-fp16/vae`, variant fp16 weights converted to fp32, frozen parameters. It does not load a denoiser. |
| `Reader.tensor(rgb01: np.ndarray)` | HWC float RGB [0,1] to BCHW float32 on reader device. CPU array conversion is suitable only at the optimization boundary. |
| `Reader.encode(self, x01)` | **Differentiable** BCHW [0,1] -> CHW posterior-mode latent times fixed `SCALE=.18215`; drops batch dimension with `[0]`, so use batch size one. This is the core frozen reader to reuse. |
| `Reader.latent(self, rgb8) -> np.ndarray` | RGB8 -> NumPy float64 latent under inference mode. For final reads only; using it in an objective destroys gradients. |
| `Layout(checked, key: bytes, config: bytes, owner: bytes, band=BAND, whitening=WHITENING)` | Supplies `ch,u,v,weights,chip,signs,norms,dct`. Defaults BAND=(4,32), WHITENING=1.0. |
| `Layout.projections(self, z: np.ndarray) -> list[float]` | Exact final chip operator in NumPy. For differentiation, reproduce the tensor operator from `robust_pgd`; do not call this NumPy method. |
| `robust_pgd(reader: Reader, rgb01: np.ndarray, layout: Layout, ws: Sequence[float], psnr_db: float, steps: int, target_margin: float, mask_power: float = 0.0)` | Returns float HWC image, no report. Contains normalized projected update schedule and differentiable DCT/index-add chip loss. Cannot accept an EOT transform callback. Reuse its algebra in a new `tifs_` module rather than modifying F5. |
| `embed_rgb(rgb, owner_id: str, profile: Mapping[str, object], semantic_features: Sequence[float], reader: Reader, psnr_db: float = 46.0, steps: int = 150, target_margin: float = 4.0, mask_power: float = 0.0, band=BAND, whitening=WHITENING, refine_rounds: int = 1, binding: str = "hard")` | Returns `(RGB8, report)`. Default arguments are **not** the retained F5 setting. Wrapper supplies 52 dB, soft binding and seven semantic views. Has no custom robust-writer hook. |
| `detect_rgb(rgb, z, owner_id: str, profile: Mapping[str, object], semantic_features: Sequence[float], binding_mode: str = "combined", roster_size: int = 1, band=BAND, whitening=WHITENING, binding: str = "hard") -> dict[str, object]` | Reuse unchanged for F6, explicitly `binding="soft"`; `z` is the frozen F5 reader latent. Do not change threshold/profile or call F6 a new reader. |
| `encoder_transfer_runtime.Internal(assets, config)` | Loads reader on CUDA, CLIP on CPU, LPIPS, profile. `features(self,rgb,views)`, `metrics(self,a,b)`, `embed(self,rgb,method)`, `detect(self,rgb,method,payload,control)` supply unchanged F5/v5 comparators. Only recognizes `f5-r2`/`v5-r3`; F6 needs dispatch with new names. |
| `encoder_transfer_runtime.Wam(assets)` | Uses `assets/wam/source`, `wam/wam_mit.pth`, `journal_wam_probe.Adapter(...,"cuda")`. `embed(self,rgb,bits)` and `detect(self,rgb,bits)` return native mark and read. WAM quantizes floor(255*x+.5). |
| `encoder_transfer_runtime.Vine(assets,encoding=False)` | Encoder: `VINE_Turbo.from_pretrained(assets/vine/encoder,local_files_only=True)`; decoder: `CustomConvNeXt.from_pretrained(assets/vine/decoder,local_files_only=True)`. Both frozen fp32 CUDA. `embed(self,rgb,bits)` with encoding=True; `detect(self,rgb,bits)` with encoding=False. Encoder downsizes to 256, then upsizes residual onto original image. Preserve its native PIL quantization. |
| `encoder_transfer_test.message(source_id,bits,seed=20261019)` | Fixed public SHAKE-256 per-source payload, independent of pixels. Config retains WAM 32 bits and VINE 100; wrong seed 20261020. |
| `encoder_transfer_test.presence(decoded,expected)` | Inclusive `matches >= binomial_threshold(bits)`, exact random-bit null tail <=1e-4. VINE threshold 69/100. Presence is not attribution; do not substitute WAM native mask criterion for this frozen comparison endpoint. |

Private F5 helpers that the new wrapper must deliberately reuse are `v5._resolve(profile,None)`, `v5.canonical_owner(owner_id)`, `f5._semantic_pattern(checked,key,config,owner,semantic_features,luma)`, `v5._Fragile(...)`, `_instance_table(...)`, `_embed_fragile(...)`, and the base luminance analysis/perceptual hash helpers in the unchanged `embed_rgb` body. They are not stable public APIs; pin the repository commit and copy the bounded wrapper logic with an explicit source reference. Never monkeypatch `f5.robust_pgd` globally to inject F6, since concurrent comparator calls could then change F5.

## Native attacks and finite surrogate semantics

`et_final_pilot.channel_specs()` returns `(config, dict(R0=...,R1=...,K3=...))` from stage2b-config.json. R0=SD1.5, R1=SDXL and K3 uses the R3 Kandinsky specification. `rt.Regenerator(assets,spec)` loads a full native pipeline, so use it only in the native attack stage, not while writing F6.

`pilot.native_input(family,rgb)` upsizes R1/K3 512 RGB8 inputs to 1024 using PIL Lanczos. `pilot.pipe_kwargs(regen,rgb,strength,generator)` supplies retained prompts, guidance, steps and SDXL microconditioning. `pa.run_native(fam,regen,rgb512,strength,seed,tape=None,hooks=None)` is a complete attack function: no-grad native inference, official quantization, SD1.5 safety validation, and R1/K3 Lanczos resize back to 512. It expects the 512 input, not a manually upsized array. Wrap it in `pilot.ClassicAttention(...)` if preserving the Phase-A/B option-(a) kernel contract. `pilot.native_rgb(...)` is an alternative inference-mode wrapper but does not itself establish that attention context.

`pilot.Tape()` supplies `.record()`, `.replay(start=0,stop=None)`, `.draws`, `.cursor`, `.receipt()`. It patches loaded diffusers modules' `randn_tensor` in a context, records every draw, and checks replay shape/dtype. Record C0 once per source/cell/seed, replay identical draws for each marked arm, and assert all draws consumed. The tape is process-global monkeypatching: do not generate native outcomes concurrently in threads. New pipeline versions can change draw count; fail rather than silently reseeding.

For R0/R1, `pa.law_tangent` reveals the native latent convention: posterior draw eta, scaled latent `sf * (mean + std*eta)` cast at native precision, then independent injection draw epsilon. `pilot.encode_terms(fam,regen,rgb_in,dtype_override=None)` reports mean/std, but runs under no-grad and returns detached clones. It is an inspection template, **not** a writer function. R1 preprocesses through fp16 before the fp32 VAE encoder; its scaling factor must come from its own config, not F5's `.18215`.

The F6 protocol must explicitly resolve whether E_f is posterior mode or posterior sample. Native SD img2img samples; silently using mode and calling it native-noisy is inaccurate. A deterministic-mode surrogate is permissible if named as such. A sampled surrogate needs **two** independently recorded random streams/draws per update (posterior eta and injection epsilon), held identical across matched comparisons where applicable. Codec-only should explicitly use mode, a=1, b=0 if intended as a deterministic codec; this makes posterior sampling an additional intervention unless the noisy arm also uses mode. For a clean noise-injection ablation, prefer the same deterministic posterior-mode convention in both writers and label this an intentional approximation to native img2img.

Scheduler coefficients must be taken from the actual first native timestep: retained pilot code calls `scheduler.set_timesteps(steps)`, `pipe.get_timesteps(steps,strength,device)` and reads `alphas_cumprod[timesteps[0]]`. Do not equate `.1` to a Gaussian sigma or use a guessed training timestep. For scaled z, decode noisy latent divided by the corresponding family scaling factor. Keep a=sqrt(alpha_bar), b=sqrt(1-alpha_bar) unchanged; do not divide by a or normalize the noisy latent before decode.

`pilot.Resize(in_size,out_size,torch)` is a differentiable Lanczos matrix operator BCHW->BCHW with clamp; it builds dense weights on CUDA. Reuse for writer input and output resize. It deliberately omits RGB8 fixed-point rounding, so even with fp16 casts the finite tensor surrogate is not bit-identical to native PIL preprocessing. State this approximation; native saved-image endpoint remains decisive. Decoder output normalization is `(sample/2+.5).clamp(0,1)`. Do not round to RGB8 inside the differentiable loss; round and re-read final saved images separately.

## Hidden F5 semantics and matched computation

The retained config uses robust budget 52 dB, 150 steps, margin 4, mask_power=0, band [4,32], whitening=1, refine_rounds=1, soft binding and seven-view semantic features. RGB8 quantization and the fragile tier materially change this budget; final quality is measured against the original, not inferred from robust budget.

The writer first robust-marks, rounds to RGB8, fragile-marks, then refines robust for `max(steps//3,20)` at `max(psnr_db+6,50)` dB, rounds, and fragile-marks again. At 150 steps there are 200 robust updates, two fragile writes, and multiple quantizations. Fragile h is recomputed from the current robust image, so refinement changes intended h. F5 does not export its intended final h: `Internal.embed` uses the clean decoded h and labels that limitation. Export F6's intended final h separately if needed, but do not retroactively redefine F5's h endpoint.

The new wrapper must state whether refinement uses F6 EOT or the original clean-only objective. Both F6-noise and F6-codec must use the same rule, budget, semantic target, fragile stages and quantization. Retaining 150 EOT updates plus 50 clean-only refinements is a concrete bounded option; retaining 200 EOT updates is another, more expensive option. The design currently says “inherited fragile processing” and “150 updates”; freeze this ambiguity before implementation is judged ready.

For each EOT update, clean and surrogate losses require separate reader encodes (unless explicitly sharing a graph). Backpropagate clean loss, detach/free that graph, then surrogate loss, accumulate input gradients, and perform one normalized projected update. Frozen VAE parameters still require input gradients. Never enclose the active path in no-grad/inference mode. The ablation repeats deterministic codec exposure with the **same number of reader/codec gradient evaluations**. Count them in the report; equal loop labels alone are insufficient.

F6 labels require their own embed dispatch and metadata but must route to the unchanged F5 read, with seven-view suspect semantics and soft binding. `Internal.detect` chooses one view and no latent for every label except the exact string `f5-r2`; passing `f6-noise` directly silently selects v5 behavior. Use explicit F6 dispatch, never string fallthrough. For C0 and wrong-owner calls, preserve which claimed owner is being tested and do not attach target payloads that make exact-code recovery look available.

`encoder_transfer_test.endpoints` dynamically imports `m1b_e3_s1_analysis.predicates`, whose module imports NumPy/SciPy at top level. It is unsuitable for allowed laptop stdlib tests even though the predicate itself uses only dictionaries and integer operations. Put frozen predicates in a new stdlib-only `tifs_` logic module, with parity fixtures. C=`semantic.read AND semantic.content_match`; it does **not** require exact original q. Q is exact original q, J=Q AND content_match; both_match is F. Report these separately, especially for T4/T5 where exact donor attribution matters.

## Journals, resume, quality and safety

`pa.Journal(path)` exposes `.latest`, `.done(uid)`, `.append(row)`. Last parseable JSON row per ID wins; malformed lines are skipped. Done means status in `{ok,safety_blocked,error_terminal}`, so terminal failures do not retry on resume. Explicit transient statuses remain pending. It does not verify successful output files/hashes still exist, enforce schema/config identity, ensure contiguous complete lines, or serialize concurrent writers. Validate artifacts and manifest/config hashes before trusting resumed rows. Ignore only a torn final line; malformed interior rows deserve a stop in new code.

`pb_read.append(path,row)` uses one `os.write` to O_APPEND for concurrent readers and adds UTC. This is a useful pattern, but its comment promising no interleaving is stronger than a portable regular-file guarantee and short writes are not checked. Prefer one writer per journal, or have disjoint shard journals and merge latest rows. `pb_read.part(uid,k)` supplies stable SHA256 sharding. `pb.merge_clean` rejects a UID in two shards. Preserve ID uniqueness across stages/arms/cells/seeds/control calls.

`rt.save_rgb(path,rgb)` writes PNG and returns `{path,sha256}` of the file. It is not atomic with journal append: save first, hash, append terminal row; orphan image after interruption can be overwritten. Verify hashes on resume and final inventory. Tape receipt has tensor hashes, while saved tape file needs its own file hash (as Phase B does). Release and seal manifests only after expected IDs have terminal or explicitly unresolved states; mere absence is not zero events.

`et_final_phase_a_attacks.Quality(assets)` provides `lpips(self,a,b)` and `__call__(self,reference,rgb)` returning `psnr_db`, `psnr_infinite`, `ssim_rgb`, `lpips`. It loads LPIPS on CUDA. Existing `passes(q)` is an attack eligibility gate (25/.75/.15), **not** the strict clean gate (>35/>.9/<.1). Store clean-vs-original, output-vs-original and output-vs-clean-marked separately. The read-stage `items(args)` and `quality(args)` patterns are reusable, but their literal phase-b filenames and hardcoded kind/arm lists must be replaced, not called unchanged.

`three_threat_models.validate_generated(result)` rejects missing/malformed SD1.5 safety results and raises `safety_checker_blocked_output` when blocked. Keep the actual pipeline checker. Phase B classifies exceptions by substring safety/nsfw; improve new code with a typed safety wrapper or exact message and retain traceback. Do not treat arbitrary exceptions containing safety as an authentic model safety verdict. SDXL/K3 lack that same SD1.5 checker interface; record native behavior, not a fabricated “passed safety” field. Safety blocks remain terminal missing outcomes; no new seeds or altered prompts to rescue them.

The Phase-B shell driver is an orchestration template, not safe to copy literally. It hardcodes `/workspace/thesis`, asset/venv paths, Phase-B acquisition/forecast seal, four-reader spawning, a 600-second sleep and error logs without hard stage failure stops (`set -u`, not `set -e`). Stage S needs explicit exit checking, no held-out acquisition, explicit completion inventory, and signal propagation/wait for all children. A failed family must not leave readers and proceed to a misleading completion marker.

## 24 GB and 15-hour assessment

1. Writing: load frozen F5 reader VAE plus one active codec VAE. SD1.5 codec may share reader weights if precision and posterior convention are intentionally the same; no denoiser, CLIP GPU model or baseline encoder should be resident. Keep CLIP features on CPU or precompute original features; LPIPS can load after marking. SDXL at 1024 fp32 has the largest backward graph. Offload inactive codec to CPU; clear references and graph before `rt.release()` (GC + CUDA cache clear). `empty_cache` cannot free referenced tensors.
2. Native K3: `rt.Regenerator` puts the 21.7 GB text encoder alone on GPU to encode the empty prompt, returns it to CPU, removes it, then loads U-Net/MoVQ. On 24 GB, begin this load with all writer/read/LPIPS GPU models absent. K3 first plus delayed detection helped historical runs, but a fixed 600-second sleep does not prove the load finished. Use a readiness marker or serialize.
3. Reading: Phase B launches four F5/v5 readers, reportedly about 1.5 GB each; it also uses WAM/VINE readers and GPU LPIPS. Do not combine that historical concurrency with an unmeasured 24 GB native peak. Safest rehearsal starts one reader and serial quality. Raise concurrency only from recorded measured headroom under the frozen procedure.
4. Memory telemetry: `rt.PhaseMemory(cuda,path)` has `.begin(label)`/`.finish(incomplete=False)`, reports allocated peak only. Extend new reporting to reserved peak and actual device total, reset peaks at each stage, synchronize for timings, and record failed/OOM peaks. Define 24 GB in bytes consistently and reserve context/driver memory; allocated <24 GB alone is not a safe cap.
5. Time: the design's 7-hour total marking allocation includes the 24 unchanged F5 marks (historical anchor 119 s/source, about .79 h) plus v5/WAM/VINE. Even ignoring those other comparator costs, the 48 new F6 marks have **under approximately 466 seconds each**. At 200 EOT updates this is under about 2.33 seconds per update including clean loss, active codec encode/decode, reader encode/backward, graph disposal and fragile overhead. At 150 EOT plus 50 clean refinement the ceiling is less strict but still unmeasured. Historical F5's 119 seconds is not an F6 estimate.
6. Rehearsal must measure both F6 variants on two non-screen development sources, native family load and attack time, reader/quality work and disk. Use `1.5 * measured per-unit time` for the planned inventory, plus measured one-time loading/setup/retrieval. Refuse a full launch if projected total exceeds 15 hours. Runtime budget checks must run between units and reserve enough for one uninterruptible unit plus retrieval; `rt.Budget(start_utc,hourly_usd,reserve_seconds=1800,max_hours=15,max_usd=15)` supplies a useful start, but pass current price and user-approved cap explicitly.

No new disk estimate can be established from tensor graph code alone. The cached instance assets exceed its original 30 GB cap; reuse only the approved asset inventory. Stage S's 2,016 native 512 RGB8 PNGs plus 168 clean images, tapes, distortions and logs should be budgeted using measured rehearsal file sizes; no extra family download is needed for candidate A. K3 remains optimization-excluded, not discovery-unseen.

## Pure-logic tests to write before server execution

- Manifest: 24 fixed screen IDs and two disjoint rehearsal IDs, all from 60 development identifiers; reject Phase-B/reserve/test IDs, duplicate IDs, bad hashes, unknown arms and path traversal.
- Freeze identity: changed config/profile/code/source manifest cannot resume an old output directory; whole intended inventory deterministically reproduces unit IDs and counts.
- EOT schedule: finite family/strength cycling, clean/refine call counts, two writer arms' gradient-evaluation equality, deterministic per-source/update draw seeds, diagnostics stream disjointness, no K3 in writing.
- Journal: last row wins, torn final line recovery, malformed interior-line rejection, terminal versus transient policy, hash corruption/missing-file invalidation, shard collision rejection, interruption before/after file save.
- Endpoints: C/S/Q/J/F/A truth tables, recomputed-only S, no payload exact-Q unavailability, wrong-owner and donor-target semantics, VINE inclusive 69/100 and WAM fixed threshold, missing decoded payload and malformed bit values.
- Decision: strict versus inclusive quality boundaries, PSNR infinity, NaN/Infinity rejection elsewhere, clean paired quality differences, source-majority with fixed seeds and conservative missingness, paired count improvements, incomplete negatives versus scientific kill versus resource stop. Do not call a partial subset GO.
- Budget/driver contract: injected clocks, price conversion, reserve boundary, per-unit estimates, child-stage failure propagation and inventory completeness before DONE.

Tensor gradient flow, projection parity, native-noise scheduling, quantization behavior, memory and timing are **server rehearsal checks**, not laptop pure-logic tests. `py_compile` is permitted locally and proves syntax only; no claim of model compatibility follows from it.

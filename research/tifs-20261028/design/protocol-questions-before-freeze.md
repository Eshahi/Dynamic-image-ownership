# Questions to resolve before the Stage S freeze

Author notes, 2026-10-28. These are unresolved design choices, not an executable protocol. They inform the WP2 hostile review and must be resolved in the frozen protocol. No scientific run has been performed.

1. **Specific contribution versus ordinary augmentation.** The multi-codec noise objective needs both the codec-only control and a routine image-space blur/noise control under the same clean term and gradient-call budget. Otherwise improvement could be generic EOT. Adding another writer increases the dominant unmeasured cost; the two-source rehearsal must reject an over-budget design rather than silently removing an arm.
2. **Refinement accounting.** The retained F5 implementation is 150 robust steps plus 50 clean refinements between two fragile writes. For each proposed writer, freeze 150 clean-plus-surrogate updates and 50 clean-only refinements, or explicitly choose another matched convention. A clean reader call plus a surrogate reader call is not one F5-equivalent gradient evaluation.
3. **T4 access.** The baseline threat gives the attacker the published donor, recipient and public owner label, not the clean donor. A known-residual transplant requires a separate, stronger-access row. Include an actual published-image patch transplant and its sham. Evaluate recipient fidelity against the recipient. Report donor carrier delivery separately from acceptance; no delivery does not demonstrate effective content binding.
4. **T5 identity and endpoint.** C is semantic read plus current-content consistency, not exact original-code recovery or original-instance identity. All historical marks use the same public ALPHA owner, so a correctly marked different source is not a wrong-owner negative merely because it is not the donor. Unmarked semantic-neighbor negatives, wrong-owner reads, exact donor-code diagnostics and core both-match must be separately named. An evaluator-only comparison with donor q/h must not become undisclosed detector-side reference information.
5. **T5 pair selection.** A fixed nearest-neighbor rule on original-only semantic features may run on the server before any new marks and be sealed there. It is permissible development selection only if no result changes the rule. It is not a human verdict that the pair is operationally distinct or a genuine near-copy. Fresh confirmation needs a specified distinct-instance/near-copy stratum, with human labels missing until supplied.
6. **Missingness.** Safety-blocked native positives count conservatively as failures for screening but retain their missing status. A blocked C0 output cannot count as a true negative. Unresolved negative checks mean incomplete specificity, not zero events. Comparator missingness must not manufacture apparent superiority; use paired conservative bounds or require the relevant comparator cells complete.
7. **Fresh family.** K3 is optimization-excluded only; it was already used in discovery. A future SD3.5/FLUX family requires fresh frozen outputs, an access decision where gated, a fixed native schedule, and actual 24 GB feasibility. Architectural difference is not documentary proof of independent training initialization.
8. **Quality and interpretation.** Preserve each method's original payload, detector, threshold and side information. VINE-R presence is a strong positive control and cannot be plotted as equivalent to semantic attribution. F5 PSNR superiority does not imply perceptual-quality superiority; report PSNR, SSIM and LPIPS separately and keep the human verdict absent.

These questions do not authorize laptop image processing, model calls, downloads or experiments. The final protocol and independent review control implementation.

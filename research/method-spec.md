# A5 method architecture: candidate v1

Status 2026-09-23: **complete algorithm specification for review, untested scientific candidate**. Issue #6, source task `repair-4`. This document applies [scope-guard.md](scope-guard.md), [research-contract.md](research-contract.md), [io-spec.md](io-spec.md) and [threat-model.md](threat-model.md). A complete algorithm is not evidence that its hypotheses hold. The original proposal and claim ledger remain authoritative. Parameters that require validation selection are mandatory in [method.schema.json](../configs/method.schema.json); an incomplete configuration cannot execute.

The protected input is an existing RGB image `I`, whether camera-originated or an existing DiffusionDB image. Its source bytes, decoded orientation/color policy, image ID and raw SHA-256 are recorded. This route does not generate a substitute image from a prompt. The prompt-only signing-order branch remains `UNSUPPORTED_IO07` and is excluded from the executable profile. The A5 candidate implements semantic and perceptual signatures, public OwnerID binding, initial noise modification in an image-conditioned diffusion suffix, and blind image-domain DCT verification. It excludes automatic transfer/registry and authenticated legal ownership as required by the scope guard.

The canonical image profile is RGB8 sRGB. At input, apply recorded EXIF orientation, convert an embedded ICC profile to sRGB using a pinned LittleCMS/Pillow pipeline, or explicitly assume sRGB when no profile exists. Reject unsupported alpha, CMYK, high-bit-depth or failed color conversion rather than silently changing them. Convert each RGB8 channel to float32 `byte/255`. The output is PNG RGB8 with no ancillary metadata or color profile; its declared color interpretation is sRGB. Before encoding, clamp the continuous `[0,1]` image, multiply by 255, and round each channel to nearest integer with ties to even. Decode the saved PNG back to float32 RGB8/255 and use **that decoded image** for final CLIP/pHash/DCT verification and quality reporting. The source-byte hash and output-byte hash are distinct from these canonical decoded pixel identities. Pin the encoder, decoder and color-management versions in A6; never use a continuous pre-encoding success score as final evidence. Each rejected source remains in the dataset coverage/failure inventory.

## Canonical features and signatures (IO-01/02)

From canonical image `X`, `E(X)=encode_image(CLIP_preprocess(X))` is a 512-vector. Reject nonfinite values or norm below `1e-12`; compute `e=E/||E||₂` in a declared float32 inference profile, then convert elements to float64 for ordered projection sums. The exact checkpoint, preprocessing and arithmetic implementation are part of the configuration identity; cross-runtime bit parity is an acceptance test, not presumed.

The semantic code `q(X)` has 12 bits. Each of 12 public projection rows has 512 Rademacher values derived by `SHAKE256(pack(["a5-semproj-v1", projection_seed_bytes]))`, where the seed is the fixed 32 bytes decoded from configuration hex. Read XOF bytes in row-major order and use **successive low-to-high bits** as sign `+1` when 0, `-1` when 1. Divide each row by `sqrt(512)`. Dot products accumulate in increasing feature index in float64. `q_k=1` when the sum is nonnegative, otherwise 0. Low bit index is stored first; the final 4 unused bits in the second byte are zero. The seed must be fixed before data inspection and logged. Twelve bits limit the initial candidate count; they do not claim semantic discrimination or stability. Projection margins, code collisions and exact-code drift must be measured, including on marked outputs.

For `H_p(X)`, transform canonical sRGB float channels to `Y=0.299R+0.587G+0.114B` without gamma linearization. Resize Y to 32×32 with bilinear interpolation at pixel centers and edge clamping; perform an orthonormal 2-D DCT-II. In the top-left 8×8 coefficients excluding DC, take the median of all 63 values. Sort those 63 positions by `(u+v,u,v)` and use the first 32; bit j is 1 iff its coefficient is strictly greater than the median. Bit packing is little-bit-first in each byte. This is a precisely specified DCT-based perceptual hash candidate, not a claim of invariance. A constant image yields an all-zero code; this is a documented collision, not an ownership proof. Pin the numerical implementation and test decoding/resize parity before scientific use.

For resize from source width W to output width 32, destination center x samples source coordinate `(x+0.5)*W/32-0.5`, with the analogous height rule; clamp the four neighboring integer coordinates to the image edge, then bilinearly interpolate. For an N-point orthonormal DCT-II, coefficient k is `sqrt(1/N)` times the cosine sum at k=0 and `sqrt(2/N)` times the cosine sum otherwise, using `cos(pi*(n+0.5)*k/N)`; apply it separably to rows and columns. A full implementation must pin IEEE float arithmetic and verify test vectors; this document specifies the mathematical operation, not cross-library bit identity.

`OwnerID` is an explicit, public UTF-8 string normalized to Unicode NFC, with 1 to 256 UTF-8 bytes; no whitespace trimming or case folding. The caller supplies the same canonical identity at signing and detection. Define `pack(fields)` as each field preceded by its unsigned 32-bit big-endian byte length, with a version/domain field first. Text fields use UTF-8, `component_byte` is the one-byte ASCII `s` or `i`, integer fields use the stated big-endian width, and digests/codes are raw bytes. Define:

```text
Ws = SHA256(pack(["a5-ws-v1", q_bytes, owner_bytes]))          # 32 bytes
Wi = SHA256(pack(["a5-wi-v1", q_bytes, phash_bytes, owner_bytes])) # 32 bytes
```

No raw floating point value is hashed. These are public-derived signatures, not secret authentication keys. Whole-code hashing has avalanche behavior: even one changed feature bit yields an unrelated digest/template, barring a hash collision. The candidate detector enumerates codes within Hamming radius one around the suspect `q(J)` and `H_p(J)` without knowing source codes. This gives 13 semantic candidates and at most `13×33=429` instance candidates for a single tested owner. It recovers a source signature only if its q and H_p codes fall in these neighborhoods. The radius and bit counts are method choices whose false-attribution and stability costs are explicitly tested. Do not enlarge neighborhoods after observing held-out results. For K tested owners the actual candidate and query counts multiply; report any-of-K false attribution, not a single-owner FPR. The operator must bind the exact configuration ID to each enrollment; candidate keys cannot silently span versions.

## Image-domain templates and statistic (IO-04/05)

For suspect image `J` of shape `[3,H,W]`, reject nonfinite/out-of-range pixels and dimensions below 32. Convert the same sRGB luminance Y. Extend only the right and bottom edges by replication to the next multiples of 8; keep a zero-based top-left block grid. An 8×8 orthonormal DCT-II produces `C_J[b,u,v]`, with blocks in row-major order and `B=ceil(H/8)ceil(W/8)`. The two channels use distinct, fixed coefficient positions:

```text
semantic F_s = [(1,2),(2,1),(2,2),(1,3)]
instance F_i = [(3,1),(2,3),(3,2),(1,4)]
```

Indices are `(vertical u,horizontal v)`, zero based. These mid-band sets are candidate design choices: separating components avoids direct coefficient overlap, but does not establish survival, optimality or quality. Coordinate framing makes geometric synchronization a limitation; no unrecorded crop/rotation search is part of the core method.

For component `a∈{s,i}`, generate `B×4` Rademacher template values from SHAKE256 of `pack(["a5-template-v1", component_byte, W_a, uint32be(H), uint32be(W), detector_config_id])`. Consume successive bits from each XOF byte low-to-high in row-major block and listed-frequency order, mapping 0→−1 and 1→+1. Shapes and dimensions are part of the template domain. The template uses only the suspect image dimensions, candidate public signature and frozen config. It does not use source I, the original signature, diffusion states or a decoder.

`detector_config_id` is the SHA-256 of canonical JSON (UTF-8, lexicographically sorted object keys, compact separators) for the static `feature`, `signature` and `dct` config objects only, deleting `dct.config_id` before hashing. It excludes thresholds and embedding optimizer values. The runtime must recompute and compare it before embedding or detection. Changing any static preprocessing, projection, candidate radius, score layout or template rule changes the ID; changing thresholds produces a separate calibration version but does not retroactively alter enrolled templates. The JSON numeric and Unicode canonicalization implementation must be pinned and cross-tested before scientific execution.

For each selected frequency f, subtract its across-block mean from `C_J[b,f]` and from `T_a[b,f]`. Flatten each centered `B×4` matrix in block-major order to c and t. Define the score as `dot(c,t)/(||c||₂||t||₂)`; if either norm is ≤`1e-12`, return score 0 with diagnostic `zero_variance` and no positive match. Numerical accumulation order and dtype must be pinned by implementation tests. Score lies in `[-1,1]` up to floating error; higher means stronger match. It is not a probability or a residual score. Host image content remains in c. The full detector score must be calibrated on unmarked and marked validation data, including its candidate search and K owner trials.

For q candidate `q*`, `S_s(q*)` uses `Ws(q*,OwnerID)`. For each pHash candidate h*, `S_i(q*,h*)` uses `Wi(q*,h*,OwnerID)`. Record the highest semantic and instance scores and candidate IDs. `both_match` requires **one common q*** whose semantic score exceeds `tau_s` and whose instance score for some h* exceeds `tau_i`. Otherwise `semantic_only`, `instance_only` or `neither_match` are observed component states. A semantic hit paired with an instance hit under a different q is not a joint match. `tau_s,tau_i` are explicit configuration inputs frozen by A4 on validation data; neither this document nor tests infer their values. They must be in `[-1,1]` and the declared threshold version stored with each result. All per-candidate scores, maximum selection, tested OwnerID count and decision costs must be reproducible. None of the four states alone diagnoses regeneration, copy-paste, enrollment authorization or legal ownership (IO-06, SC-03/04).

## Embedding algorithm and bridge (IO-03/04)

`embed_existing(I,OwnerID,config,seed)` first computes `q(I),H_p(I),Ws,Wi`, templates for the declared output grid, and provenance. Here `I` and all quality/detector outputs are on the original `[3,H,W]` pixel grid; `I_pad` is a separate encoder input made by edge-replicating only bottom/right to multiples of 64. Crop the decoded output from `[3,Hpad,Wpad]` to `[3,H,W]` **before** comparing it with I, deriving signatures or applying image DCT. No source resize is implicit. Inputs exceeding the configured explicit maximum dimension yield `unsupported_input_resolution`; they are retained in the coverage inventory, not silently dropped. If the final dataset has such images, a reviewed resource/method resolution is required before claiming its full coverage or native-resolution quality. Follow the reviewed [initial-noise path](initial-noise-path.md) with scaled VAE posterior mode `v=s_vae*E_vae(I_pad)` and fixed Gaussian epsilon0, fixed DDIM suffix and matching unmarked reconstruction `I_ref` **after the same crop**. Divide the terminal denoised latent by the same s_vae before VAE decoding. Text conditioning is the fixed empty string, tokenized by the pinned model tokenizer for every image; use one conditional UNet pass with guidance scale 1 and **no classifier-free guidance branch**. This avoids a captioner or hidden prompt input but may worsen reconstruction and requires evaluation. For padded working shape Hpad,Wpad, the candidate uses all-one latent masks on `[1,4,Hpad/8,Wpad/8]`. Domain-separated SHAKE256 streams from each signature, seed and latent shape produce unit-norm Rademacher carriers `P_s,P_i` (byte/bit order as for templates). The only optimized tensor is u of the same shape, initially zero. Candidate noise is `epsilon0 + alpha_s P_s + alpha_i P_i + u`, where both alphas are nonnegative mandatory inputs. Project u after each optimization step onto `||u||₂≤rho`, with mandatory finite positive rho. This preserves two explicit key-derived carriers while permitting image-objective guidance. The resulting pattern depends on I and seed as well as keys; do not claim key-only reconstruction of u at detection.

Generate base epsilon0 deterministically from `SHAKE256(pack(["a5-base-noise-v1", uint64be(seed), source_sha256_bytes, uint32be(C), uint32be(h), uint32be(w)]))`. Read consecutive unsigned 64-bit big-endian integers x and map each to uniform `U=(x+0.5)/2^64`; consume pairs `(U1,U2)` with Box-Muller `sqrt(-2 ln U1)*(cos(2πU2),sin(2πU2))`, then round in channel/row/column order to float32. Reject nonfinite output. The source digest is provenance and affects enrollment noise only; it never enters verification. Elementary-function implementation and parity tolerance must be pinned in A6. This deterministic pseudo-Gaussian proposal does not imply cryptographic secrecy or cross-platform bit identity without tests.

For component a, the carrier XOF input is `pack(["a5-carrier-v1", component_byte, W_a, uint64be(seed), uint32be(C), uint32be(h), uint32be(w), detector_config_id])`; C,h,w are the actual latent shape and uint64 seed is the recorded nonnegative per-image seed. Read `C*h*w` successive XOF bits low-to-high in channel/row/column order and map to ±`1/sqrt(C*h*w)`. The all-one masks leave every latent coordinate eligible; this is an explicit candidate, not a claim about optimal placement. The image-conditioned suffix time and objective still determine whether either carrier affects the final DCT score.

The decoded model output in `[-1,1]` is converted to sRGB `[0,1]` by `clip((x+1)/2,0,1)` before crop, DCT, signatures and output encoding. Keep that conversion in the embedding computation graph; at saturated values its gradient can be zero. For fixed source templates `T_s(Ws),T_i(Wi)`, let `S_s(I_float(u))` and `S_i(I_float(u))` be the continuous DCT scores **without detector-side key enumeration** during embedding. Define an embedding objective

```text
L(u) = lambda_q * mean((I_float(u)-I)^2)
     + lambda_r * mean((I_float(u)-I_ref)^2)
     + lambda_s * max(0, m_s-S_s(I_float(u)))^2
     + lambda_i * max(0, m_i-S_i(I_float(u)))^2
```

The two quality terms expose both total reconstruction distortion and incremental watermark cost. Positive weights, margins in `[-1,1]`, optimizer learning rate, iteration cap, alpha values and rho are required config values; A4 must choose/freeze them without test-set tuning. Use deterministic Adam with explicit beta1=0.9, beta2=0.999, eps=1e-8, bias correction, and projection after each step. The model and its weights are fixed; backpropagate only through the image-conditioned reverse suffix and decoder to u. Record loss/score/quality trajectories and every nonfinite/abort path. Stop at the fixed iteration cap or a declared pre-frozen tolerance rule; no unlimited retries or best-of-test output. The public img2img entrypoint disables gradients, so an independently reviewed component path is required. Actual gradient continuity and hardware fit remain unmeasured.

The source proposal's PSNR >35 dB, SSIM >0.9 and LPIPS <0.1 targets remain evaluation obligations on the aligned output versus I, with metric implementation, aggregation and acceptance rules frozen in A4. MSE in the embedding objective is not a replacement for those three reported metrics. Also report the same metrics for the matched reconstruction I_ref to disclose model reconstruction loss. No target is asserted achieved.

After the last step, encode the declared output image and recompute `q(I_w),H_p(I_w)` and the **entire core detector** using Iw and OwnerID. If source codes fall outside the declared Hamming neighborhoods, or the detector fails at frozen thresholds, record an embedding failure; do not feed source keys to the detector, re-sign Iw, change parameters or silently discard it. Matched C0 reconstruction uses **alpha_s=alpha_i=0 and u=0** with the same base noise, model path and output handling; merely setting u=0 while leaving keyed carriers in place would contaminate C0. This chain specifies how a key-derived image template guides a latent/noise perturbation into image-DCT coefficients, not a proof it works. If image DCT scores cannot be reached under quality/resource constraints, keep the failed feasibility result and request a reviewed scope decision before replacing the latent or detector route.

## Verification algorithm and limits

`detect(J,OwnerID,config)` validates the fully versioned config, canonical image and claimed public owner; extracts `e(J),q(J),H_p(J)`; enumerates bounded Hamming candidates; computes DCT coefficients once; generates each key-derived template; computes continuous component scores; applies validation-frozen thresholds with the common-q rule; returns all candidate counts, scores, IDs, flags, diagnostic reasons, timing and configuration hashes. All core costs include CLIP, pHash, code enumeration, DCT and scoring. A separately reported DCT-only cost cannot be compared with another method's full verification latency. Unsupported configuration, missing checkpoint, model hash mismatch, malformed image or missing threshold produces an error/unsupported result, never a clean negative.

The evaluator alone has source images, original keys, seeds, prompts, dataset labels and attack provenance. C0 unmarked and matched reconstructions, C1 marked correct owner, C2 wrong owner, C3 wrong-pattern oracle, C4 distinct instances, C5 donor/target transfer pairs and C6 ablations retain their separate roles. T6 public-method re-embedding and multiple OwnerIDs limit attribution claims. A neural decoder and an inversion-based detector remain distinct comparator obligations for RQ-03 and HYP-03/METRIC-07. No security, robustness, quality or source ownership hypothesis is accepted by this architecture.

A syntactically plausible nonzero digest is not proof of artifact existence; the runtime must verify every referenced byte stream, tokenizer constituent and validation manifest. They cannot verify dataset licenses, exact gradient path, scientific power or method success; runtime and independent review must do those checks. No instance of a final config is created here because optimization/threshold/resource values have not been selected or approved. A5's deliverable is the bounded, falsifiable architecture and enforceable configuration contract.

# A4 stop, continuation and failure rules

Status 2026-09-23: prospective control document for issue #5. A stop pauses the affected branch or exact run; it does not erase negative evidence or stop unrelated safe work. The official Spec Kit controller alone advances lifecycle gates. No scientific experiment is approved by this document. Related criteria and counts: `acceptance.md`, `sample-size.md`; authority: `approval-policy.md`, `scope-guard.md`, A3/A5.

No presumed supervisor/university or publication acceptance. |

Bulk evaluation may begin only after: (1) dataset licenses/IDs and split/group locks are verified; (2) reviewed implementation passes deterministic finite/shape, exact serialization, seed and checkpoint-hash tests; (3) C0/C1/C2 and diagnostic C3 controls behave as specified on development data; (4) threshold, margins, attack/owner/seed profiles, failure policy and multiplicity plan are frozen; (5) a complete exact execution manifest has user scientific-compute authorization. A calendar date, successful prompt call or a passing unit test alone is not this gate. If any item fails, stop bulk work but continue source research, software fixes, literature/baseline inspection and other independent tasks. The conservative per-image missingness accounting in `acceptance.md` does **not** override `STOP_PIPELINE`: systemic conformance failure quarantines the affected run and prevents confirmatory inference even if adverse counts can be tabulated descriptively.

Every attempt, including failed seeds and timeouts, gets a run ID, commit/config/input hashes, resource telemetry, output/error paths and disposition. A technical error is distinct from a negative result: the former invalidates or limits inference, whereas the latter can pass an evidence-completeness review. The end-to-end primary denominator includes all attempted eligible sources and its failure handling must be frozen before execution. No early efficacy stopping or optional sample-size extension is authorized; evaluate the planned fixed N when safe and available. A safety/resource stop preserves partial data as incomplete, not as a confirmatory success. Final results acceptance remains a separate evidence audit.

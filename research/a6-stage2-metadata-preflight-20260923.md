## Candidate intersection from maintainer-published release metadata

The A5 method pins Diffusers `0.35.1`; its [PyPI release metadata](https://pypi.org/pypi/diffusers/0.35.1/json) lists `huggingface-hub>=0.34.0` and `safetensors>=0.3.1`, but does not install Transformers in its base requirements and does not set a Transformers upper bound. For the model path, explicitly considering the last published 4.x [Transformers `4.57.6` release](https://pypi.org/pypi/transformers/4.57.6/json) avoids an unconstrained resolver choosing 5.x. This is a **candidate**, not a tested Diffusers/Transformers pair. Its metadata requires Python ≥3.9, Hub `>=0.34,<1.0`, Tokenizers `>=0.22,<=0.23`, and Safetensors `>=0.4.3`. [Accelerate `1.10.1`](https://pypi.org/pypi/accelerate/1.10.1/json) requires Torch ≥2.0, NumPy `>=1.17,<3`, Hub ≥0.21 and Safetensors ≥0.4.3. Therefore Hub `0.36.0`, Tokenizers `0.22.1`, Safetensors `0.6.2`, installed Torch `2.12.1+cu130`, and NumPy `2.5.2` satisfy these **declared version inequalities**. They have not passed an import or API compatibility test together.

For A4's image-quality implementation, [scikit-image `0.26.0`](https://pypi.org/pypi/scikit-image/0.26.0/json) requires Python ≥3.11, SciPy ≥1.11.4, Pillow ≥10.1 and NumPy ≥1.24. [SciPy `1.16.2`](https://pypi.org/pypi/scipy/1.16.2/json) requires Python ≥3.11 and NumPy `>=1.25.2,<2.6`; it is metadata-compatible with installed Python 3.12.14, NumPy 2.5.2 and Pillow 12.3.0. This does not establish metric parity. A4 pins LPIPS source commit `082bb24f84c091ea94de2867d34c4544f68e0963`, with separate learned-linear and AlexNet-trunk weights. Although [LPIPS `0.1.4`](https://pypi.org/pypi/lpips/0.1.4/json) has a small pure-Python wheel, that package has **not** been reconciled with the pinned source commit or its implicit weight-loading behavior; it is not selected as an executable metric by this preflight.

These are **server-advertised wheel digests, not local byte receipts**. The installed Stage-1 pip reports `cp312-cp312-win_amd64`, `cp39-abi3-win_amd64` and `cp38-abi3-win_amd64` among its compatible tags; the six explicitly compared package-version inequalities above were also checked with `packaging.specifiers` and all returned true. Neither check is an import or API test. A package resolver must freeze and verify all transitives (including `hf-xet`, `imageio`, `tifffile`, `lazy-loader`, `requests`, `PyYAML`, `packaging` and their dependencies) and reject unplanned Torch/TorchVision replacement. The exact LPIPS source/package relationship, official CLIP source/requirements, model/tokenizer/weight receipts and license terms remain separate. No implicit `from_pretrained()` or pretrained LPIPS constructor is permitted in a package-import preflight. Only after an explicitly authorized Stage-2 installation may `pip check`, import-only/no-network tests, numerical image/ICC/DCT vectors, and a complete wheel-hash lock turn these candidates into environment evidence. A RunPod image still requires an independent lock and receipt.

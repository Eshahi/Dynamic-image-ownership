# Conditional deterministic A-C development worker

Candidate `m1-terminal-continuous-e2e-v1` implements the frozen deterministic original200 initializer followed by unchanged100 A-C embedding. This file describes implementation, not efficacy or M1 completion. The frozen method decision remains `m1-end-to-end-initialization-design.md`.

`scripts/m1_terminal_e2e.py` accepts the exact committed `research/m1-terminal-e2e-dev.json`, one fixed development source, one verified initializer bridge directory and a passing complete original component CPU-analysis receipt. It imports the existing optimizer, differentiable embedder, public reader, detector, fixed-source scorer and checkpoint helpers by identity. The live component module is never modified or monkeypatched. Scientific losses, margins, last-step selection, RGB8 quality-only cap, FP16 public readout and threshold4 remain identical.

Only IDs1675/4795 may execute before the new end-to-end pilot gate. Every later source requires a same-method-core passing pilot merge. The full development roster is fixed; caller paths do not authorize another photograph. Every source gets4 C0/C1 clean/VAE rows and16 four-owner queries, including14 negative queries. The merged original pilot requires8 rows,32 queries,28 negatives, two clean source-quality passes, two clean both-match detections, two VAE semantic detections and all negative channels below4. A missing/invalid query cannot pass.

The bridge loader revalidates the full200 endpoint and independent literal/prefix/resume audit, runtime, source RGB8 hash, model bytes and initialization scientific core. No legacy fallback is present. The canonical photograph remains hybrid C0; pure initializer decoder quality and pure marked decoder quality are recorded separately. The initializer tensor reaches embedding directly without PNG re-encoding. Fresh phase RNG is reset to0 after feature/model preparation and inference-model offload, immediately before optimizer step0; resume restores checkpoint RNG through the unchanged optimizer.

Each source process retains every-ten latent/Adam/RNG checkpoints, float reference/decoded/residual/surrogate arrays, saved PNG endpoints, public FP16 and diagnostic FP32 reader arrays, CLIP/hash descriptors, source-template oracles, projection diagnostics, extraction timing, embedding timing and GPU placement snapshots. Source/config/import hashes and command/commit are recorded; the separate method core hashes executed Python and numeric configs rather than report-only HEAD commits. Resume requires the same method/core/manifest/source/initializer, a fresh output directory and cumulative wall budget. Resource limits remain1800s,10GiB or current free-minus512MiB GPU,16GiB RSS and500MiB output. Local pinned assets, blocked networking and existing safety checks are retained.

`--merge-pilot DIR1675 DIR4795 --output-dir FRESH_MAIN_DEV_DIR` independently audits outputs before writing a merge receipt. CPU audit reuses the original independent scalar-cap implementation and `verify_row` directly. Its initializer-specific source stage adapter replaces only the old analyzer's hardcoded legacy reconstruction provenance. It independently checks saved pixels, pHash, score algebra, decisions, quality pixels and arrays; CLIP and LPIPS inference remain recorded-only, matching the old analyzer's limit. A failed scientific gate may produce a completed integrity audit with `passes:false`, which never authorizes expansion.

The parent must commit all dependencies before execution and must use the owned-worker harness, execute sources sequentially and retain failures. No GPU execution or commit was performed by this implementation subtask. Parent still owns common-threat evaluation, final freeze, owner-interface amendment, held-out runner and independent M1 review.

Example (paths resolved by parent, no placeholder execution): `python scripts/m1_terminal_e2e.py --run --manifest research/m1-terminal-e2e-dev.json --source-id 1675 --bridge-dir VERIFIED1675 --component-analysis COMPONENT_ANALYSIS/run.json --output-dir FRESH_MAIN_DEV_DIR`.

If the component's recorded public-core hash differs from current bytes, `--owner-extension-receipt OWNER_AUDIT/run.json` is mandatory. The proof must be a completed `m1-owner-extension-audit-v1` matching both old/new source hashes, all128 legacy cells in each of two passes,32 retained development queries,512 projection cells,8192 alignments,512 nulls and20 distinct maps. The worker checks proof code/dependencies and all output bytes; absent/incomplete proof fails closed. The candidate core includes the extension-audit executable and every initializer scientific config/dependency. This permits an explicitly proved compatible owner-domain extension without pretending that the old component used the new core.

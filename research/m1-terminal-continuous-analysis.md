# A-C CPU analysis contract

`scripts/m1_analyze_terminal_continuous.py --input-dir <completed-or-incomplete-A-C-run> --output-dir <fresh-MAIN-dev-runs-directory>` uses the science Python runtime; no models, CUDA calls, network, reconstruction fitting or threshold selection. Parent commits before actual analysis. Exit0 means complete receipt/analysis, not promotion; a nonzero exit preserves incomplete evidence (the CLI declares2; the parent launch of the first failed-run analysis reported process1).

Fixed denominator: source IDs1675/4795, eight C0/C1 × clean/VAE rows,32 owner queries and28 negative queries, two source clusters. Missing, duplicate, malformed, refused and corrupted conditions remain eight inventory rows and32 CSV query slots with null scores/gates; raw input conditions and source errors remain retained. No eligibility filtering. The frozen gate requires both clean source-quality conjunctions (strict PSNR>35, SSIM>.9, LPIPS<.1), both clean blind `both_match`, both VAE blind semantic flags, all28 negative semantic and instance scores strictly below4, and complete integrity. Instance-only or invalid measurements never promote. Inclusive score threshold4 is unchanged.

Receipt checks pin source run, copied manifest, journal/conditions, all output hashes, exact19 committed dependencies against source-commit Git blobs and working SHA256,17 local model assets and learned LPIPS weights, raw two-source hashes, canonical EXIF/ICC/bicubic RGB8 sources, original reconstruction run/step200 checkpoint receipts and identical resumed fingerprints. Every generated artifact is inside its source directory, unique and named for its planned source/condition/stage. Source checkpoint endpoints must end at fixed100; optimizer checkpoint contents and model inference are not independently replayed. Float64 NPY readers/features reproduce source-template fp32/fp16 oracle and suspect-feature fp16 blind scores, flags, states, denominators and projection diagnostics. Actual PNGs reproduce pHash, RGB8 identity, source/paired pixel PSNR and Gaussian-window SSIM. LPIPS and CLIP embeddings remain pinned recorded model measurements, not separately rerun numerical validation.

The exact float64,36-bisection scalar quality cap is independently replayed with ties-to-even RGB8 rounding and pixel SSE; clean C1 must equal its replay, clean C0 the canonical source. Pure decoded arrays, residual, differentiable cap beta/RMS, float-surrogate relation and cap rounding error are checked. `stages.json` retains four recorded-only float source-oracle stage scores and24 independently recalculated PNG stage endpoints; only blind endpoints receive promotion credit. Tiny fp32 arithmetic tolerances are explicit in code; thresholds are not relaxed. Extra VAE-cycle PNGs and their saved endpoint latents are hash-verified, not model-regenerated.

Output: `run.json`, `conditions.json`, `input-conditions.json`, `queries.csv`, `stages.json`, `artifact-receipts.json` and a per-condition journal. Budget receipts retain cumulative/attempt wall duration, allocation cap and measured GPU peak; completed receipt must satisfy caps. Artifact size is recalculated. RAM was guarded by the runner but no retained peak exists; no independent RAM or optimizer certificate is implied. Timings share the reader's content cache and are not32 independent cold detector latencies. Source-bypass composition is explicit; oracle success, tiny pilot negatives and VAE-only survival are not public forgery resistance, diffusion robustness, human quality or milestone approval.

Validation: eleven CPU synthetic tests cover exact cap replay, strict/nonfinite quality, inventory duplicates/subsets, independent template-dot scores, complete endpoint re-read plus altered/missing score/projection fields, artifact paths/hashes, null missing gates, negative threshold boundary and an end-to-end incomplete fixture preserving8/32. No scientific output was analyzed during implementation.

Recovery receipt amendment: dependency membership is determined from the source-commit runner (original19, inference-offload20 including its recovery document). Blob OIDs and working SHA256 are checked against source Git bytes including Windows CRLF checkout form. Current imported scientific/reader functions are AST-identical to the source version; every other active scientific dependency remains hash-identical. The intentionally changed execution runner is not required to have the old working SHA. When a replay reference exists, its hash/config/commit and positive execution replay are mandatory; the CPU checkpoint state and all saved first-source artifacts/owner decisions are rechecked with the recovery parity helper. Failed/missing replay blocks promotion. Original plus recovery wall cost is retained, without treating first-source replay as another cluster. Two further CPU tests cover19/20 membership, changed receipts and missing/false/corrupt replay controls; thirteen analyzer tests now pass.

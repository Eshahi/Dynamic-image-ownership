# Shared confirmatory image operations v1

Prospective implementation of tasks5–8 in `m1-confirmatory-worker-build-plan.md`, under the unadopted `m1-confirmatory-draft.md`. This module does not select a candidate, authorize scientific inputs, issue a capability, or establish confirmatory readiness. Development/rehearsal callers may inject generated images; the future official scientific worker must supply separately authorized canonical saved RGB8 and validated model/assets provenance.

`scripts/m1_confirmatory_image_operations.py` imports no torch/diffusers models, loads no assets, reads no files, makes no network calls, and initializes no accelerator. All image inputs are exact512x512x3 uint8 ndarrays. Inputs are copied before execution. `OperationResult` contains output RGB8 and an in-memory receipt with pixel hashes. `OperationFailure.receipt` retains failed-operation information, including actual executed DDIM steps and safety flags. Artifact persistence, elapsed/resource measurements, atomic journal, ownership, input lineage and planned missing descendants belong to the caller; successful operator execution is not evidence of security or delivery.

Its execution RNG policy is deterministic/no RNG. This limitation must remain visible in any source-contract/seed amendment; preserving a seed receipt does not imply protected A4 compliance.

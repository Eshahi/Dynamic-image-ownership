## Implementation and selected details

`src/data/preprocess.py`, `configs/data.json` and `tests/test_preprocess.py` implement the A5 RGB8 sRGB profile. JPEG/PNG only; RGB only; reject alpha (including RGB PNG transparency), palette, grayscale, CMYK, high-bit-depth PNG even when Pillow reports RGB, multiframe, damaged files, excessive bytes/pixels, malformed EXIF and failed ICC conversion. Limits are 100 MB source, 40 million pixels and 4 MB ICC; a limit failure stays in coverage, not a silently removed source. No dimension reduction or upscaling is implemented. Native DIV2K pixels remain native; this does not prove the downstream model can process them.

Apply EXIF orientation 1..8 before pixel identity. Embedded ICC is converted through Pillow/LittleCMS to sRGB with perceptual intent 0 and flags 0; absent ICC explicitly means an sRGB assumption, not verified camera colorimetry. The intent resolves an ordinary A5 configuration detail, not a claim of perceptual correctness for every profile. Malformed/unusable profiles fail. Implementation follows the inspected official [ImageCms API](https://pillow.readthedocs.io/en/stable/reference/ImageCms.html) and [EXIF transpose API](https://pillow.readthedocs.io/en/stable/reference/ImageOps.html#PIL.ImageOps.exif_transpose).

Normalized arrays are HWC float32 RGB8/255. Future CHW consumers must transpose explicitly. Caption is the fixed empty string; source prompts and source users are not read/exported. No caption model exists here. The canonical RGB8 pixel digest has the `b5-rgb8-srgb-v1` domain, width/height in uint32 big-endian and row-major RGB bytes, so shape is part of identity.

Output floats must be finite. Quantization uses float64 multiplication after clamping, ties-to-even rounding and RGB8 PNG compression level 6 with optimization disabled. Float64 intermediate defines the rounding of the supplied representable values; it does not erase preceding float32 model error. A fresh image carries no inherited EXIF, ICC or text; only IHDR/IDAT/IEND chunks are allowed. The saved bytes are decoded again and the exact decoded RGB8 is returned for final metric/feature use. Continuous pre-encoding pixels cannot stand in for those outputs. The source raw digest, canonical pixel digest and output-file digest are separate.

## Cache and provenance

Explicit absolute source/cache paths are checked for symlinks/junctions at every ancestor. The source snapshot is size/hash checked and the same bytes are decoded (no hash-then-reopen). The cache key binds raw SHA, canonical config SHA, exact preprocessing source-file SHA and observed runtime. Each receipt contains orientation, original/output dimensions, ICC hash/action, empty caption, native/no-resize flag, output size/hash and canonical pixel hash. Cache files and receipts use exclusive creation. Existing entries are verified before reuse; partial or corrupt entries fail and are preserved, never overwritten as successful evidence. Callers serialize writers. Files remain in ignored local-only `data/cache/`; this grants no source rights clearance. A caller must retain the source ID and rejection reason in its coverage inventory.

Two captured runtime profiles are allowed: Windows CPython 3.12.14 / NumPy 2.5.2 and WSL CPython 3.14.4 / NumPy 2.5.3. Both have Pillow 12.3.0, LittleCMS 2.19 and libjpeg-turbo 3.1.4.1; exposed JPEG/zlib versions differ and are explicitly pinned. Cache keys differ by runtime even if pixels coincide. Unrecognized versions fail rather than claiming parity. The existing A6 wheel locks remain unchanged; no install/download was needed. Broader platform/ICC/JPEG parity remains unproven.

## Scores and thresholds: not probabilities

- SOURCE: `scripts/revised_watermark_v5.py:1178-1199`: for projection vector p, recomputed score is dot(p, recomputed sign pattern)/||p||2. Decoded score is the largest such normalized correlation over 2^32 possible codewords, computed by choosing each segment's better bit. Ties keep the recomputed bit. Zero projection energy returns both scores zero and the recomputed code.
- DERIVED: these are energy-normalized correlation statistics, not probabilities or [0,1] confidences. A negative soft margin is not a negative probability. Under 320 unit-sign chips the absolute correlation bound is sqrt(320), by Cauchy-Schwarz.
- SOURCE: `scripts/revised_watermark_v5.py:1149-1169`: threshold inverts `TAIL_CONSTANT * patterns * 0.5 * erfc(t/sqrt(2)) <= target`, using 200 bisection iterations. `TAIL_CONSTANT=1/(2*erfc(1))`. `patterns=roster_size` for recomputation and `2^32*roster_size` for decoding. The source attributes its tail bound to Bentkus-Dzindzalieta; this memo has not independently audited the theorem's assumptions for this implementation.
- SOURCE: `scripts/revised_watermark_v5.py:1232-1278`: `read = decoded_score >= decoded_threshold`; `found = read OR recomputed_score >= recomputed_threshold`, inclusively. The frozen spec records thresholds approximately 8.259 and 4.982 (`research/f5-r2-spec.md:32`).
- SOURCE: generic `score` and `threshold` select the decoded branch **only if `read` is already true**, otherwise the recomputed branch. Both branch scores/thresholds are separately exported, including below threshold.
- DERIVED: `score-threshold` is branch-selected and is not a uniform C margin. It can be positive when the mark is found only through recomputation and C is false. Preserve this requested generic margin, but separately report `decoded_score-decoded_threshold`, `recomputed_score-recomputed_threshold`, `read`, and binding status. The Phase A forecast reader already uses decoded margin (`scripts/et_final_phase_a_fit.py:147-151`). Neither single margin alone equals the combined C decision.
- SOURCE: `log10_false_positive_bound` is a clipped analytical bound from the selected score and search count (`revised_watermark_v5.py:1172-1175,1277`), not an empirical false-positive rate or posterior probability.

## Distance and content compatibility

- SOURCE: `scripts/revised_watermark_v5.py:1249-1259`: when read succeeds, `code_distance` is raw Hamming distance between decoded code and the code recomputed from the suspect. When found only by recomputation it is set to zero. When neither route passes it is null, despite `decoded_code` still being emitted.
- SOURCE: `corrected_distance = round(clip((distance-32*e)/(1-2*e),0,32),6)` on reads. The model-derived bit error rate e comes from inversion of a Gaussian segment-score model, not observed bit errors (`revised_watermark_v5.py:1202-1254`). It is null without a read; recomputation-only distance and corrected distance are zero.
- SOURCE: v5 compares corrected Hamming distance to limits. F5 soft binding instead uses a maximum-likelihood angle over a fixed 2,000-point grid from .001 to pi-.001, multiplied by 32/pi, when read and semantic checking are active. The likelihood uses continuous CLIP projections and the inferred bit error rate (`scripts/f5_latent_codec.py:110-155`). `soft_distance` is this angle-equivalent distance, not `code_distance`; it is null on no-read/hard/unchecked paths.
- SOURCE: `scripts/revised_watermark_v4.py:978-991`: checked distance <=6 is match, >=10 mismatch, between them uncertain. Unchecked is assigned the same rank as match. `content_match = found AND status rank==0` (`f5_latent_codec.py:315-318`; `revised_watermark_v5.py:1354-1357`). Thus in non-combined diagnostic modes an unchecked channel can have `content_match=true`; inspect `binding_mode` rather than treating that field as proof of both checks.
- SOURCE: instance testing uses recomputed q unless a found semantic channel has nonmatching content, then uses decoded q. The instance status inherits the worse of its own perceptual-hash comparison and semantic status (`f5_latent_codec.py:300-310`; `revised_watermark_v5.py:1334-1349`). The two content decisions are not independent.

## C, J, F and negative calls

- SOURCE: `scripts/encoder_transfer_test.py:72-75` forwards to frozen `scripts/m1b_e3_s1_analysis.py:70-84` predicates:
  - S = semantic found AND content_match; C = semantic read AND content_match.
  - Q = semantic read AND decoded q exactly equals original payload q; J = Q AND semantic content_match.
  - H = instance read AND decoded h equals payload h; D = Q AND H.
  - F = outcome `both_match`; A = either channel found. `recomputed_only_S` distinguishes S without read.
- DERIVED: J requires exact original semantic code, not exact original h and not both_match. C can accept a changed q compatible with current content. F can hold without decoding either original code. Do not interchange these endpoints or older S-based gate success with C.
- SOURCE: original q/h are endpoint-evaluation side information, not inputs to the native raw detector. For F5 the payload h is the native clean **decoded h**, because the intended h was not exported; for v5 it is intended h (`scripts/encoder_transfer_runtime.py:154-180`). This limits H/D interpretation.
- SOURCE: `scripts/revised_watermark_v4.py:994-1016`: any found content mismatch takes priority and returns `content_mismatch`; both compatible found channels produce `both_match`; compatible semantic alone produces `semantic_only`; compatible instance alone produces `instance_only`; other found/uncertain cases produce `content_uncertain`. The corresponding authentic/regenerated/copy-paste labels are decision-table observations, not attack ground truth (`revised_watermark_v5.py:1299-1301`).
- SOURCE: C1 is marked input, C0 unmarked. Correct owner is `qim-pilot-owner-alpha`, wrong owner is `qim-pilot-owner-beta` (`encoder_transfer_test.py:20`). Internal C1 gets both calls, C0 only alpha; wrong-owner calls get no original payload (`encoder_transfer_runtime.py:172-183`). Two separate calls each use roster_size=1; this is not the roster API's jointly corrected two-owner search.
- SOURCE: historical transfer negative reporting uses endpoint A, i.e. **either key found**, for C0 and wrong owner, and counts unresolved calls separately (`encoder_transfer_test.py:354-367`). A wrong-owner endpoint J being false by missing payload is not a negative-control success.
- SOURCE: source-majority means >=2 true outcomes among three prescribed seeds; missing values count as non-success, with optimistic/missing counts reported separately (`encoder_transfer_test.py:78-81,339-352`; Phase A `et_final_phase_a_fit.py:245`). This is a reporting aggregation, not an adaptive verifier.

## Multi-view choice, gradients and rounding

- SOURCE: seven views are full image, horizontal mirror, four corner crops and center crop of side round(7w/8); compute each unit CLIP vector, average, renormalize (`scripts/f5_gate.py:35-54`). This is one averaged semantic descriptor, not seven separate watermark decisions or a best-of-seven test. v5 uses the single full-image vector.
- SOURCE: deployed CLIP feature extraction runs in inference mode and PIL preprocessing (`scripts/three_threat_models.py:150-159`). F5 `Reader.encode` is differentiable, but `Reader.latent` runs inference mode and returns NumPy (`f5_latent_codec.py:88-107`). DCT, projection and fixed-pattern correlation are mathematically differentiable away from zero norm; retained reader decisions use NumPy/Python, hard code bits, threshold comparisons and argmax and expose no autograd path.
- SOURCE: existing F5 PGD already differentiates the pinned VAE plus DCT/chip projections using a squared hinge loss and normalized-gradient step (`f5_latent_codec.py:175-215`). This is gradient optimization, not RL. Its fixed learning-rate switch is halfway through 150 steps; one later refinement changes later image state (`:233-250`).
- SOURCE: RGB is rounded/clipped after main F5 optimization, fragile insertion and refinement (`f5_latent_codec.py:231,245,250`). The final reader sees saved uint8 pixels. Differentiable optimization does not make these rounding operations or hard C/J endpoints differentiable. v5 RGB embedding also rounds before verification (`revised_watermark_v5.py:1454-1481`).
- SOURCE/DERIVED: explicit rounding of corrected distance to six decimals is separate from RGB8 quantization and F5 angle-grid discretization. Do not round margins before threshold classification. Threshold comparison uses full floats in code.
- Cost limitation: no measured gradient cost or timing was inspected here, and no measurement was run. Existing `seconds` fields isolate different spans: raw F5 timing starts after latent/features are supplied, owner-call timing also follows shared feature extraction, whereas Phase A row timing starts before image loading and adapter processing (`f5_latent_codec.py:276-327`; `encoder_transfer_runtime.py:173-183`; `et_final_phase_a_fit.py:94-121`). They cannot be substituted for end-to-end reader/gradient cost without identifying the timing scope.

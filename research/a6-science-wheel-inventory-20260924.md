# A6 read-only science wheel inventory

Status 2026-09-24: **partial distribution-file coverage, not a complete science environment lock**. Issue #7 / draft PR #58. This inventory uses the already-installed isolated Windows CPython 3.12 science venv and existing ignored local wheel caches. It performs no package installation, download, model load, CUDA operation, dataset access or scientific run.

`scripts/audit_science_wheels.py` reads installed distribution metadata, SHA-256-hashes cached wheel files, and checks every entry in `requirements-science-stage2-win312-hashes.txt` against a matching installed name/version and local wheel digest. It fails closed on a missing/mismatched locked wheel, duplicate lock entry, malformed wheel or linked wheel root/file. The lock input SHA-256 was `0f9cc032fdda00a220cff6272f0219e1eb41ec3fb5c9513368746649e2d35271`. The invocation included the existing root, `a6-stage2-all`, and `a6-stage2` wheel directories under the ignored main-project `.thesis-build/wheels`.

The actual report: **42 installed distributions**, **37 cached wheel files**, **29 unique cached name/version pairs**, and **24/24 Stage-2 hash-locked distributions matched**. Thirteen installed distributions had no wheel in those checked directories: `clip==1.0` (pinned VCS source, not a wheel), `filelock==3.32.3`, `fsspec==2026.7.0`, `jinja2==3.1.6`, `markupsafe==3.0.3`, `mpmath==1.3.0`, `networkx==3.6.1`, `numpy==2.5.2`, `pillow==12.3.0`, `pip==25.0.1`, `setuptools==78.1.0`, `sympy==1.14.0`, and `typing-extensions==4.16.0`. Some may be recoverable from an existing cache, but that was not established here. Do not label the environment fully reproducible from these 37 files.

The workflow test environment ran `python -m unittest discover -s scripts -p 'test_*.py' -q`: **65 discovered, 63 passed, two expected skips**, including four new synthetic inventory tests. The real science-vendor invocation exited zero because the 24 declared Stage-2 hashes matched; its JSON `status` was `partial_inventory`, not `locked`. The script does not verify that an installed package's internal files equal a particular wheel's installed `RECORD`, attest PyPI provenance for uncached dependencies, verify the CLIP Git source tree, cover model/data bytes, or show cross-host/CUDA numerical parity.

Before a scientific execution manifest, obtain a reviewed complete wheel/source inventory and hashes without treating package version strings or this partial cache as sufficient. Any new substantial acquisition remains subject to the user's installation preference and a concrete scoped decision. The pending bounded CLIP/LPIPS runtime-probe question is separate; this inventory neither authorizes nor executes it. A6/#7 and the official `plan-acceptance` gate remain open.

# A6 read-only science wheel inventory

Status 2026-09-24: **partial distribution-file coverage, not a complete science environment lock**. Issue #7 / draft PR #58. This inventory uses the already-installed isolated Windows CPython 3.12 science venv and existing ignored local wheel caches. It performs no package installation, download, model load, CUDA operation, dataset access or scientific run.

`scripts/audit_science_wheels.py` reads installed distribution metadata, SHA-256-hashes cached wheel files, and checks every entry in `requirements-science-stage2-win312-hashes.txt` against a matching installed name/version and local wheel digest. It fails closed on a missing/mismatched locked wheel, duplicate lock entry, malformed wheel or linked wheel root/file. The lock input SHA-256 was `0f9cc032fdda00a220cff6272f0219e1eb41ec3fb5c9513368746649e2d35271`. The invocation included the existing root, `a6-stage2-all`, and `a6-stage2` wheel directories under the ignored main-project `.thesis-build/wheels`.

The actual report: **42 installed distributions**, **37 cached wheel files**, **29 unique cached name/version pairs**, and **24/24 Stage-2 hash-locked distributions matched**. Thirteen installed distributions had no wheel in those checked directories: `clip==1.0` (pinned VCS source, not a wheel), `filelock==3.32.3`, `fsspec==2026.7.0`, `jinja2==3.1.6`, `markupsafe==3.0.3`, `mpmath==1.3.0`, `networkx==3.6.1`, `numpy==2.5.2`, `pillow==12.3.0`, `pip==25.0.1`, `setuptools==78.1.0`, `sympy==1.14.0`, and `typing-extensions==4.16.0`. Some may be recoverable from an existing cache, but that was not established here. Do not label the environment fully reproducible from these 37 files.

The workflow test environment ran `python -m unittest discover -s scripts -p 'test_*.py' -q`: **65 discovered, 63 passed, two expected skips**, including four new synthetic inventory tests. The real science-vendor invocation exited zero because the 24 declared Stage-2 hashes matched; its JSON `status` was `partial_inventory`, not `locked`. The script does not verify that an installed package's internal files equal a particular wheel's installed `RECORD`, attest PyPI provenance for uncached dependencies, verify the CLIP Git source tree, cover model/data bytes, or show cross-host/CUDA numerical parity.

## Additional existing-cache inventory, same date

A later read-only pass included pip's existing HTTP-v2 `.body` wheel payloads and built-wheel cache. The script now accepts explicit `--pip-http-cache-root` and `--pip-built-wheel-cache-root` directories; it reads wheel metadata and SHA-256 without installing, copying or fetching anything. It found **60 wheel payloads** in the HTTP cache and **three built wheels**, bringing the unique cached name/version pairs to **64**. Eleven of the earlier thirteen missing installed distributions now have candidate cached wheels. The real report still says `partial_inventory`: **42 installed**, **24/24 Stage-2 hashes matched**, no declared-lock failure, and **two without a checked wheel: `pip==25.0.1` and `setuptools==78.1.0`**. This does not turn the inventory into a full environment lock.

The built `clip==1.0` candidate wheel's locally measured SHA-256 is `68fc1aa1fc25591c3c61e621cfd47b6f8e19536901db70f5da0c1af1ba485969`. Its pip-cache `origin.json` and the installed CLIP `direct_url.json` both record `https://github.com/openai/CLIP.git` at commit `d05afc436d78f1c48dc0dbf8e5980a9d471f35f6`. This is stronger source-candidate identification, **not** a byte comparison between the installed package and cached wheel or a verified rebuild. The HTTP cache scan only identifies wheel metadata and computes local digests; it does not establish a supplier signature or package-index receipt for each body.

A subsequent targeted [CLIP installed-source audit](a6-clip-install-byte-audit-20260924.md) compared the five source-package files with that cached wheel and found 5/5 byte matches. That narrows the preceding installed-byte gap for CLIP source only; it does not verify a rebuild, model behavior or the rest of the science environment.

After this extension the workflow suite discovered **70 tests: 68 passed, two expected skips**, and `git diff --check` passed. No network, installation, model load, CUDA work, data access, scientific compute or Spec Kit transition occurred. The separate CLIP/LPIPS runtime-probe question remains pending.

Before a scientific execution manifest, obtain a reviewed complete wheel/source inventory and hashes without treating package version strings or this partial cache as sufficient. ## Bootstrap-wheel candidate closure, same date

An additional bounded check closed the **missing candidate-file** gap, not the full environment-lock gap. The bundled `pip-25.0.1-py3-none-any.whl` in the existing Codex Python runtime is 1,841,526 bytes; its measured SHA-256 `c46efd13b6aa8279f33f2864459c8ce587ea6a1a59ee20de055868d8f7688f7f` matches the [official PyPI pip 25.0.1 wheel](https://pypi.org/project/pip/25.0.1/#files). The official [setuptools 78.1.0 PyPI release metadata](https://pypi.org/project/setuptools/78.1.0/#files) advertised `setuptools-78.1.0-py3-none-any.whl` at 1,256,108 bytes and SHA-256 `3e386e96793c8702ae83d17b853fb93d3e09ef82ec62722e61da5cd22376dcd8`. That 1.2 MB wheel alone was downloaded to the ignored `a6-bootstrap` cache, and both size and SHA-256 matched; no package was installed or changed.

The first audit of the official setuptools wheel exposed a parser defect: its package tree contains vendored `*.dist-info/METADATA` files, whereas a wheel's own distribution metadata is at the ZIP root. `wheel_identity` now selects exactly one **top-level** metadata file and still rejects multiple top-level candidates. Two regression tests cover both cases. The full repository suite then found **77 tests: 75 passed, two expected skips**.

With the original wheel roots, the new `a6-bootstrap` root, the bundled ensurepip root, and the same pip HTTP/built caches, the science-venv audit exited zero: **42 installed distributions, none without a cached wheel candidate, 24/24 declared Stage-2 hashes matched, and no declared-lock failures** (`status: cached_wheels_present`). The report saw 39 named wheel files, 62 HTTP wheel bodies, three built wheels, and 67 unique name/version pairs. This is **candidate-file coverage only**: neither this report nor the two bootstrap hashes proves installed-file equivalence for all 42 distributions, a complete provenance/compatibility lock, a clean offline reconstruction, CLIP/LPIPS numerical parity, model rights, method fit or any scientific result. A6/#7 and the official gate remain open; the separate model-load permission remains pending.

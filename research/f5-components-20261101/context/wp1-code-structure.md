## Corrections that matter before assigning component loss

- SOURCE — The retained F5/v5 contrast changes more than the carrier: F5 uses seven-view CLIP and soft semantic binding, while v5 uses one view and corrected-Hamming binding (`scripts/encoder_transfer_runtime.py:154-179`; `scripts/journal_vae_probe.py:60-69`). DERIVED — The statement that the two arms differ only in K4/K5 is not true of these executable comparisons. Their quality budgets, writer, ordering/refinement, and semantic reader also differ; this is a useful system contrast, not an isolated carrier intervention.
- SOURCE — One F5 mark uses 150 initial robust updates, a fragile insertion, 50 robust refinement updates at 58 dB, and a second fragile insertion (`scripts/f5_latent_codec.py:231-250`; `configs/f5-r2.json:20-28`). DERIVED — “150 steps + fragile tier” omits one quarter of robust gradient updates and one complete fragile fitting stage.
- SOURCE — `judge/reader_ball.py:61-67` tries to parse `semantic.candidate` as a hexadecimal recomputed code. The actual value is `"decoded"`, `"recomputed"`, or null (`scripts/revised_watermark_v5.py:1255-1259`). DERIVED — On outputs from this implementation, parsing fails, `dist` stays null, and the decoded-in-ball branch at `reader_ball.py:71-72` cannot add a hit. Its published radius counts come only from `recomputed_score >= threshold(r)`. They are still lower bounds for a hypothetical ball maximizer, but not measured gains from constrained decoding.
- SOURCE — The main agent's completed saved-journal aggregation independently reproduces all 84 original radius counts and supplies the corrected center. Main reported r=3 source counts remain unchanged; the added v5 R1-mode .2 cell changes from 16 to 18 (`research/f5-components-20261101/results/wp1-accounting/REPORT.md:7,29-48`). DERIVED — Correcting the implementation does not overturn the judge's main numeric table, although the endpoint and null qualifications remain.
- SOURCE — F5 soft binding uses continuous suspect projections and a model-derived decoding error rate, not a raw Hamming-radius test (`scripts/f5_latent_codec.py:148-155`). DERIVED — A raw Hamming ball of radius 6 is a new acceptance region, not exactly the codes the frozen content check could accept.
- DERIVED — “Not found” identifies failure of two tests, not a measured absence of watermark signal; an exclusive causal allocation of that pool to K4/K5 is UNKNOWN (`scripts/revised_watermark_v5.py:1244-1265`). SOURCE — The allowed Phase A report independently localizes a large SDXL loss to noise injection, with reported retention .66 after mode codec and .08 after noise injection (`research/encoder-transfer-20261019/final-study-20261025/phase-a/PHASE-A-REPORT.md:99-109`). JUDGMENT — That mechanism evidence is stronger than naming a threshold-failure class “carrier gone,” but it still does not isolate the optimal change to K4 versus K5/K6/K7.

## K1 — Semantic descriptor

- SOURCE — Inputs are suspect/source RGB8 and the pinned CLIP ViT-B/32 model plus preprocessing. Each view produces a checked, finite, nonzero 512-dimensional unit vector. F5 averages full image, horizontal mirror, four corner crops, and center crop, then renormalizes (`scripts/three_threat_models.py:150-160`; `scripts/f5_gate.py:35-54`). The crop side is `round(width*7/8)`, so the code assumes the canonical square input, rather than independently defining a fractional height.
- SOURCE — The descriptor is computed from original source pixels at embedding and from saved suspect pixels at standalone detection. Embed-report self-verification is different: it receives the supplied original feature vector (`scripts/encoder_transfer_runtime.py:158-165,173-179`; `scripts/f5_latent_codec.py:254`). DERIVED — An embedded verification report is not evidence that CLIP re-extraction from the final mark succeeded.
- DERIVED — Cost is seven CLIP forward passes per image, shared across owner calls in the transfer adapter, with zero direct pixel distortion. Individual CLIP-view latency was not identified; low-level detector `seconds` excludes these passes (`scripts/encoder_transfer_runtime.py:173-183`; `scripts/f5_latent_codec.py:276,327`). It is one averaged descriptor, not seven tests and not a best-view search.
- JUDGMENT — Keep K1 distinct from K2, but name preprocessing/canonicalization as part of K1. Changing its model, views, or preprocessing changes q and the soft statistic; a reader-only change can therefore also change recomputed presence and instance-table selection. Its causal recovery ceiling is UNKNOWN. A content-decision-only oracle with frozen scores is bounded by existing reads; replacing E and rewriting is not bounded by that oracle.

## K2 — Content code and semantic compatibility model

- SOURCE — The supplied descriptor maps to 32 signs of HMAC-derived Rademacher rows. Rows depend on profile key, detector configuration, and vector width, not OwnerID; exact bit generation first scales by the largest absolute component and sets a bit when the projection exceeds `1e-9` (`scripts/revised_watermark_v5.py:322-335`; `scripts/revised_watermark_v4.py:443-463,524-539`). The continuous F5 projections instead unit-normalize the descriptor (`scripts/f5_latent_codec.py:115-128`). DERIVED — Their directions agree away from the tiny numerical threshold, but “signs exactly match” has a threshold/scale qualification near zero.
- SOURCE — F5 soft compatibility estimates an angle on 2,000 fixed points between .001 and pi-.001 using a product likelihood `Phi(c_j*p_j*cot(theta))`, mixed with estimated bit-flip probability e; distance is `32*theta/pi` (`scripts/f5_latent_codec.py:111,131-155`). This is evaluated only on decoded reads with semantic checking active; other found paths use the corrected-distance rule.
- SOURCE — The base code itself warns that the exact angle/pi disagreement identity holds for isotropic Gaussian/Haar hyperplanes, not general Rademacher rows (`scripts/revised_watermark_v4.py:443-450`). DERIVED — Neither this soft likelihood nor 32 iid Bernoulli semantic-bit errors is an exact distributional consequence of CLIP plus Rademacher hashing. Dense descriptors may motivate an approximation; saved success counts do not prove the model.
- DERIVED — Extraction costs 32 by 512 sign projections; a soft-angle evaluation forms 2,000 by 32 likelihood terms. The implementation can evaluate soft status twice on a found semantic channel (`scripts/f5_latent_codec.py:298-300`). There is no direct distortion, but q fixes the robust and instance payload targets. The binding-only ceiling on frozen reads is identifiable; a different q/code family has UNKNOWN ceiling and affects T4/T5 as well as T3.

## K3 — Payload construction and channel coding

- SOURCE — Each semantic bit selects one of two independently generated ten-chip sign patterns in its segment. Thirty-two nonoverlapping segments form a 320-chip semantic pattern. The instance table has four ten-chip patterns per segment, selected jointly by q-bit and h-bit (`scripts/revised_watermark_v5.py:338-380`).
- DERIVED — “Repetition only” is imprecise: this is a per-bit binary random codebook/spreading construction, not ten identical copies of a bit or necessarily an antipodal binary code. There is no parity or error correction across the 32 message segments. Distinct choices can have variable Hamming distance, and identical short option patterns are not excluded by generation. The decoded maximizer is separable across segments, so the `2^32` multiplicity is statistical search size, not exponential computational cost (`scripts/revised_watermark_v5.py:1178-1199`).
- SOURCE — q is content-derived, not an arbitrary 32-bit owner identifier; OwnerID conditions both carrier layout and code tables. h is a separate content descriptor. The native reader receives no original q/h (`scripts/f5_latent_codec.py:265-304`; `scripts/encoder_transfer_runtime.py:172-180`). DERIVED — “32 payload bits” is not a certified capacity for identifying 2^32 owners or instances.
- DERIVED — Coding adds small table/projection arithmetic and no separate pixel write; it determines all 320 writer targets and exact-decoding reliability. A changed codebook/ECC normally requires new marks and thresholds, so its T3 recovery ceiling is UNKNOWN from the old endpoint table. The found-but-not-read pool is a target for investigation, not a bound on every possible coding improvement.

## K4 — Carrier space and normalization

- SOURCE — The writer/reader use the scaled SD1.5 posterior-mode tensor, 4 by 64 by 64 for canonical 512-square RGB. Per-channel orthonormal DCT slots satisfy `4 <= hypot(u,v) < 32` (upper endpoint excluded), with public weight `radius/4`. The frozen configuration records 3,272 slots (`scripts/f5_latent_codec.py:44-66,101-107`; `configs/f5-r2.json:9-18`).
- SOURCE — Slot assignment is a pseudorandom permutation followed by modulo-320 assignment, with keyed signs; F5 recomputes each chip's normalization as the square root of the sum of its assigned squared frequency weights (`scripts/revised_watermark_v4.py:679-692`; `scripts/f5_latent_codec.py:72-85`). DERIVED — At 3,272 slots, chips receive 10 or 11 slots. The denominator is key/layout dependent through grouping, even though each frequency weight is public and key independent. The DCT projection norm and subsequent full-chip energy normalization are separate operations.
- DERIVED — A 64-square DCT is hard-coded; the low-level generic image check only enforces a minimum side and finite luminance, not correct latent shape (`scripts/revised_watermark_v4.py:197-209`; `scripts/f5_latent_codec.py:82-85`). The production adapter supplies the missing shape contract by requiring saved RGB8 inputs to be 512-square (`scripts/encoder_transfer_runtime.py:111-117`). No spatial synchronization is implemented by this latent carrier.
- DERIVED — Cost includes one latent DCT at read time and the DCT/chip graph on every robust gradient step; distortion is incurred through the RGB writer, not by substituting the VAE reconstruction. Its independent improvement ceiling is UNKNOWN: final scores mix carrier geometry, writer optimization, budget, host interference, encoder response, and regeneration. Public weights alone do not establish the null theorem; see the conditional table-sign argument below.

## K5 — Encoder model and channel surrogate

- SOURCE — `Reader` loads local SD1.5 fp16-variant weights into a frozen fp32 VAE. It maps `2*x-1` through encoder posterior mode and multiplies by .18215; no decoder, posterior sampling, UNet, or attack simulator is used in the robust objective (`scripts/f5_latent_codec.py:88-107,195-205`). SOURCE — The same encoder supplies gradients for writing and latents for reading.
- DERIVED — F5 is an image-domain mark optimized through a latent encoder, not a watermark inserted into a generative sampling trajectory (`scripts/f5_latent_codec.py:218-251`). The original image, registry, regeneration checkpoint, and attack seed are not native reader inputs. Knowing the reader VAE does not imply knowing the actual foreign regenerator.
- SOURCE — The transfer adapter's read shares one VAE encoding across owner calls; the low-level `seconds` starts after z has been provided (`scripts/encoder_transfer_runtime.py:173-183`; `scripts/f5_latent_codec.py:265-276`). DERIVED — Reader costs must include this forward pass separately. Writer cost includes 200 encoder-gradient evaluations in r2 plus final encoding, not 150 alone.
- JUDGMENT — K5 should explicitly include the distinction between reader coordinate system and writer channel model. Replacing the reader, replacing only the differentiable surrogate, and using an ensemble are different interventions. Their ceilings are UNKNOWN from saved fixed-reader detections. SOURCE — Phase A reports encoder gain transferring while robust survival does not, and identifies noise injection as a major SDXL loss stage (`PHASE-A-REPORT.md:87-112`, full path above); “SD1.5 encoder dependence” does not mean the foreign codec alone erased the mark.

## K6 — Writer optimization and objective

- SOURCE — The target q/chip pattern is fixed before writing. Main optimization uses squared hinge `mean(relu(4 - signed_chip_margin)^2)`, normalized gradient descent from zero perturbation, and step size `.2*budget` for the first half then `.05*budget` for the second half. It projects actual RGB delta to a global L2 ball after clipping to [0,1] (`scripts/f5_latent_codec.py:158-161,175-215,227`).
- DERIVED — The objective directly targets unnormalized signed chip margins. It does not optimize normalized decoded correlation, soft content binding, exact q recovery, total two-tier quality, negative controls, or foreign-regeneration output. A good surrogate optimum need not be a good C/J optimum. There is no early stopping, best-iterate selection, multistart, or learned optimizer in this implementation.
- SOURCE — Refinement restarts a new optimization centered on the already rounded combined image, using `max(psnr+6,50)` and `max(steps//3,20)`; frozen r2 therefore adds 50 steps at 58 dB (`scripts/f5_latent_codec.py:246-250`). DERIVED — The total is 200 gradients, with a separate halfway switch inside each solve. The reported `steps=150` field is the main-run parameter, not total work.
- SOURCE — The inspected Phase A report supplies a historical 119 s/source write anchor (`research/encoder-transfer-20261019/final-study-20261025/phase-a/PHASE-A-REPORT.md:124`). DERIVED — This cannot identify per-step, CLIP, fragile, or refinement latency. Optimization-limited loss and additional-step recovery ceiling are UNKNOWN without saved convergence/intervention evidence; the presence of 150 steps does not demonstrate convergence.

## K7 — Quality budget, allocation, clipping, and saving

- SOURCE — Main robust L2 radius in [0,1] coordinates is `10^(-PSNR/20)*sqrt(number_of_RGB_entries)`. Frozen r2 uses 52 dB and mask power zero. Each robust stage is rounded to RGB8; each fragile change is added equally to R/G/B and then rounded/clipped (`scripts/f5_latent_codec.py:164-172,186,208-215,231-250`).
- DERIVED — Even for a nonzero mask, the code projects the actual pixel delta, not an unconstrained mask-weighted norm. With the retained all-ones mask this distinction disappears. The 52 dB constraint applies before first rounding, relative to the source of that one solve. The 58 dB constraint applies relative to its later combined starting image. Neither is a final end-to-end PSNR guarantee.
- SOURCE — Fragile design MSE is `255^2/10^(47/10)` with a `1/12` rounding reserve; host rejection chooses an expected spread-spectrum cost using host power (`scripts/revised_watermark_v5.py:842-853`; `scripts/revised_watermark_v4.py:86,762-779`; profile `embedding.instance_psnr_db`). DERIVED — This is approximately 1.30 byte-squared before reserve, while the 52 dB robust budget is about .41 and the 58 dB refinement budget about .103. These are design budgets, not measured orthogonal residual energies. The actual host-change cost has a pattern/host cross term, and the final image has two fragile fitting stages, clipping, rounding, and cross terms between stages.
- JUDGMENT — The judge's roughly 60% fragile share is a useful hypothetical allocation, not an identified share of final distortion. A robust-only 2.2x amplitude gain is not an established feasible gain. DERIVED — Uniformly multiplying all chip projections by a positive constant leaves the detector score exactly unchanged (`scripts/revised_watermark_v5.py:1186-1199`); increasing only watermark signal relative to host/noise requires a channel model, and the foreign channel need not be linear. SOURCE — Phase A reports this nonlinearity for SDXL (`PHASE-A-REPORT.md:74-83`, full path above).
- DERIVED — Quality/visibility adds no isolated recovery ceiling: all per-cell improvement ceilings are UNKNOWN without new residual/quality measurements. A global L2 budget is not a bound on maximum local artifact or human invisibility. The frozen spec's accepted historical image set and the transfer study's missing human ratings are different evidence populations (`research/f5-r2-spec.md:12,29-30`; `research/encoder-transfer-20261019/results.md:156`).

## K8 — Fragile instance descriptor, tier, and write order

- SOURCE — h combines coarse DCT structure from a 32-square resampled block-mean map with block-gradient detail from (0,1)/(1,0), then takes 32 sign projections. Detail uses a dead zone, saturation, and a floor; coarse/detail nominal squared shares are 1/4 and 3/4 (`scripts/revised_watermark_v4.py:60-67,466-515`). It is not the semantic descriptor and not a cryptographic instance hash.
- SOURCE — The fragile mark occupies six full-resolution block-DCT positions distinct from those hash detail positions. It is fit with host rejection/amplitude and three corrective passes (`scripts/revised_watermark_v5.py:825-887`; profile `instance_frequencies` and `embedding.passes`). F5 computes h after the initial robust mark, embeds Wi(q,h), robust-refines the image, recomputes h, and re-fits Wi(q,h) (`scripts/f5_latent_codec.py:233-250`). q remains the original fixed semantic code.
- DERIVED — The v4 documentation that its embedder does not modify h's feature planes is not globally true of the complete F5 PGD writer. The final fragile stage preserves those planes before rounding/clipping; the unconstrained robust/refinement stages can change them. The second fragile write is corrective, so it should not simply be counted as two independent 47 dB noise additions.
- SOURCE — F5 does not export intended final h. Transfer evaluation substitutes the embed-report clean decoded h, whereas v5 exports intended h (`scripts/encoder_transfer_runtime.py:160-167`). DERIVED — Exact H/D comparisons have this asymmetry; substituting decoded h does not validate intended-payload recovery.
- DERIVED — Read costs include full-resolution DCT/hash extraction even when only C is reported; write cost includes two three-pass fragile fits. The native C/J endpoint does not depend directly on instance acceptance, but K8 alters robust latent chips through its pixel perturbation. Its removal could change C/J physically and would change F/instance interpretation. Recovery/quality/T4/T5 ceilings are UNKNOWN; no claim that this tier is uniformly useless after every regeneration family follows from its design name.
- SOURCE — The main agent's saved-development supplement reports source-majority instance found/read/exact-H/F counts of 52/37/3/5 under Stage 2 SDXL .1, and 30/19/0/0 under SDXL .2, each out of 60; every listed SD1.5 F5 cell has zero instance-found sources (`research/f5-components-20261101/results/wp1-fragile/REPORT.md:27-35`). DERIVED — Family-independent fragile extinction is contradicted. The older “both_match 0/90 by design” observation cannot be substituted for instance presence, instance read, H, or J in these foreign cells. The detector does not receive the attack identity or force the fragile result to zero after regeneration (`scripts/f5_latent_codec.py:265-311`).

## K9 — Reader statistic, null model, and thresholds

- SOURCE — For 320-chip vector p, recomputation scores `p dot w(q_now)/||p||2`; decoding maximizes the same normalized score independently in each segment. Zero energy yields zero scores; ties retain the recomputed bit. Read is decoded score at least 8.259326826136963, while found is read OR recomputed score at least 4.982033056390042 for roster one (`scripts/revised_watermark_v5.py:1178-1199,1244-1278`; `configs/f5-r2.json:38`).
- DERIVED — Scores are not probabilities and are bounded above in magnitude by sqrt(320). Decoded score is always at least recomputed score, but the two pass events have different cutoffs and are not nested. The generic `score` and `threshold` switch to the decoded branch only after it passes; a generic positive margin is not necessarily a C success (`scripts/revised_watermark_v5.py:1260-1272`).
- SOURCE — The code inverts a Bentkus-Dzindzalieta-attributed sign-sum bound with 200 bisection steps, multiplying by roster count for recomputation and `2^32 * roster_count` for decoding. It then infers a decoding error rate by inverting a Gaussian two-option segment-score model and corrects raw Hamming distance as `(d-32e)/(1-2e)`, clipped and rounded to six decimals (`scripts/revised_watermark_v5.py:1149-1175,1202-1257`). DERIVED — e is not a measured bit error rate; option correlation, unequal segment energies, and non-Gaussian/interdependent channel noise are not represented by that model.
- JUDGMENT — Keep K9, but distinguish three subcomponents: statistic, multiplicity/null calibration, and decoding-error model. Their assumptions differ. A changed threshold can move tests without changing carrier energy; old endpoint loss classes cannot establish its safe T4/T5 operating point. See the conditional-null and ceiling sections below.

## K10 — Binding decision and endpoint semantics

- SOURCE — Checked distance <=6 means match; >=10 means mismatch; intermediate values abstain as uncertain. Unchecked has the same status rank as match. F5 replaces semantic corrected-Hamming distance with soft distance on decoded semantic reads (`scripts/revised_watermark_v4.py:978-991`; `scripts/f5_latent_codec.py:148-155`).
- SOURCE — Instance-table selection uses q_now except when the found semantic channel has a nonmatching content status; then it uses decoded q. Instance status inherits the worse semantic status. A found mismatch has priority in the final decision table; both compatible found channels return `both_match` (`scripts/f5_latent_codec.py:294-318`; `scripts/revised_watermark_v4.py:994-1016`). DERIVED — The two tiers' binding decisions are coupled, not independent votes. Labels `authentic`, `regenerated`, and `copy_paste` are inferred output names, not attack ground truth.
- SOURCE — Frozen endpoint code defines C = semantic read AND content_match; Q = semantic read AND exact original q; J = Q AND content_match; H = instance read AND exact original h; D = Q AND H; F = `both_match`; S = semantic found AND content_match; A = either channel found (`scripts/m1b_e3_s1_analysis.py:70-84`; `scripts/encoder_transfer_test.py:72-75`). DERIVED — J does not require H, while F can succeed by recomputation without exact q/h read. A new content-ball result must have its own endpoint name and report frozen C and J separately.
- DERIVED — J contains no fragile-tier content check at all, tolerant or exact. F uses tolerant content statuses of both found channels; exact h is H, not F. SOURCE — Saved-development aggregation makes the distinction material: clean F5 C/J/H/F are 60/52/34/60; SD1.5 .1 C/J are 60/41, .2 57/38, .4 39/14, and K3 .2 5/0. Under SDXL .1 F=5 even though C=0 (`research/f5-components-20261101/results/wp1-fragile/REPORT.md:27-35,45,51`). DERIVED — An exact-semantic-payload deficit already exists on clean saved marks; it is not a fragile-tier deficit, and fixing tolerant binding alone cannot repair it.
- DERIVED — Recomputed-only presence gets distance zero and hence automatic content match in checked mode; it supplies S but not C/J (`scripts/revised_watermark_v5.py:1256-1257`; endpoint definitions above). Lowering a binding distance cannot be interpreted as adding independent content evidence on that route. Decision-only C recovery is bounded by existing reads; J recovery is bounded by existing exact-Q reads. Other component changes are not limited by those bounds.

## K11 — Keys, side information, and configuration identity

- SOURCE — The deployed profile is `public-derived`; its master key is a fixed SHA-256 constant and streams are domain-separated HMAC-SHA256 expansions. NFC-normalized OwnerID conditions carrier/table labels, but semantic projection rows do not include OwnerID (`scripts/revised_watermark_v5.py:95,304-314,343-359`; `scripts/revised_watermark_v4.py:212-218,344-354`; `scripts/f5_latent_codec.py:123-128`). DERIVED — “Keyed” denotes deterministic indexing, not a secret possessed only by the legitimate owner. Possession of OwnerID is not authorization (`research/threat-model.md:7-9`). No cryptographic unforgeability follows.
- SOURCE — Native inputs are suspect RGB, the latent z supplied by the pinned encoder, claimed owner, profile, and suspect semantic features, with band/whitening/binding parameters (`scripts/f5_latent_codec.py:265-267,323-326`). Evaluation also receives original q/h; those are evaluator side information, not reader side information (`scripts/encoder_transfer_runtime.py:179-180`; endpoint code above). There is no registry in this F5 reader.
- SOURCE — The inherited detector configuration hash covers v5 profile fields but excludes decision thresholds and embedding fields; F5 band, whitening, binding mode, CLIP view count, and VAE weights are not added to that hash (`scripts/revised_watermark_v5.py:138-150,292-301`; `configs/f5-r2.json:8-48`). DERIVED — The hash alone does not identify the entire F5 reader. Conversely, changing inherited `robust` profile settings that F5 does not directly use still changes the seed/config hash and therefore q, tables, and carriers. Such a change is not an isolated physical-parameter perturbation.
- JUDGMENT — Keep K11 as an assumptions and provenance component. Its “sources recovered” ceiling is not a meaningful performance quantity without specifying a changed method. Introducing a secret, registry, or externally supplied original descriptor changes the trust/side-information model and must not silently inherit native C/J or public-derived security claims.

DERIVED — Encoder family is coupled to native resolution, resampling, model/scheduler, and noise path. Equal nominal strengths do not isolate a common perturbation budget.
- SOURCE — Majority means at least two true results for the three prescribed seeds. Missing calls count as non-success; optimistic missing-as-success totals are reported separately. DERIVED — This is study aggregation, not a verifier allowed to generate/retry three suspects; source-majority counts cannot be obtained by dividing a seed total by three.
- SOURCE — The historical `f5_t4.py` study uses clean-donor residual access at scales .5 and 1 and tests `both_match`, with a binding-disabled delivery control; it explicitly does not reproduce the public projection attack (`scripts/f5_t4.py:1-10,62-90`). SOURCE — `f5_binding_experiment.py:156-178` also contains descriptor-level T4 comparisons and joint near-collision T5 diagnostics; its h-distance input is imported from the supplied T5 run's `f4_C1` field. - SOURCE — Phase A fit reuses the same internal adapter and original C1 payload; its row timer includes image loading and processing, while owner-call timing begins after shared features/latent (`scripts/et_final_phase_a_fit.py:84-121`; `scripts/encoder_transfer_runtime.py:173-183`). DERIVED — Low-level detector, owner-call, full image read, writer, regeneration, and quality times need separate scopes. No per-component latency decomposition was identified here.
- JUDGMENT — K12 has no algorithmic recovery ceiling. It controls what is identifiable: pair source/seed records, keep failed/missing calls, distinguish C/J/F/A, preserve development versus frozen evidence, and avoid using a change of negative endpoint or source selection to claim method improvement.

## Conditional null validity and multiplicity

1. SOURCE — The implemented tail formula is a bound for a weighted sum of independent random signs whose squared weights sum to at most one (`scripts/revised_watermark_v5.py:1149-1156`). DERIVED — For a fixed nonzero chip vector p and an independently random selected table pattern w, the weights `p_i/||p||2` meet that normalization exactly. Gaussian image coefficients or independent p_i are not required by this conditional argument. Correlated full codewords also do not invalidate a union bound: independence is needed within the random-sign pattern under this argument, not between every searched codeword. The `_tail_bound` docstring's wording about independent *patterns* is stronger than the union bound requires.
2. DERIVED — The useful independence is between table-sign generation and p plus code-set selection. p itself uses keyed carrier signs and layout normalization. Therefore the comment that public, key-independent frequency weights alone preserve the proof is incomplete. Under an idealized independently random domain-separated stream model, one can condition on image, semantic projection stream, carrier stream, and q_now, then use randomness of the separate `ws` stream. Actual public deterministic HMAC streams are not freshly sampled independent Rademacher variables per claim; the code supplies a reproducible pseudorandom construction, not an unconditional population-FPR theorem for arbitrary chosen images/owners (`scripts/revised_watermark_v4.py:349-354,679-692`; `scripts/revised_watermark_v5.py:343-359`).
3. DERIVED — A content-conditioned ball `B(q_now,r)` is compatible with the conditional union-bound argument if the center/set is selected independently of the tested table signs after conditioning, its cardinality is fixed/bounded, and the image/owner were not selected by looking for high scores. Computing both E and p from the same image is not by itself fatal: condition on that image. Deriving q and w from different labels of one public deterministic key does not, by itself, prove the necessary independence. An adaptive center, radius, view, owner, or image selected using the same table scores needs its selection multiplicity or a separate valid calibration.

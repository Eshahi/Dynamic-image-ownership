## Byte/config custody and the exact loader

`src/embedding/local_assets.py` imports no Torch, model or dataset. `plan_assets` reads only the small A6 public inventory, exact SHA-256 `b8c2595857853ea5b7835bb71f12a34dde07b78623c5e638f692dc7eb220b27e`, and selects its exact 15 SD constituents. Its returned immutable byte fields include the raw lock; every subsequent operation reconstructs and checks the entire plan so caller-substituted entries/hash totals cannot become an accepted copy instruction. The 17-file original lock remains unchanged; CLIP/AlexNet are not reacquired, converted or silently included in SD loader work.

Define each method `embedding.model_component_hashes[name]` for this loader as SHA-256 of ASCII canonical JSON (`sort_keys=True`, compact separators, `allow_nan=False`) containing `profile="c4-component-inventory-v1"`, `name`, and lexicographically path-sorted `{path,size_bytes,sha256}` records relative to `sd15-fp16/`. VAE, UNet and text encoder groups each include config **and** safetensors, tokenizer includes all four constituents, safety includes checker config/weight **and** feature extractor config. This is a concrete interpretation of A5's mandatory component digests, not a raw-weight-only digest or new acquired artifact. Model repository/revision and Diffusers commit must also match. Loader config snapshot bytes/hash/value must agree with the C1 `LoadedConfig`; full C1 schema validation before entry remains mandatory, not a permission conferred by the dataclass. Ordinary tests explicitly use unit-only synthetic config objects, not actual selected scientific configurations.

Inside a future **approved** worker, `snapshot_assets` would copy each pinned SD file into a new private, uniquely named local directory, with exclusive create, finite expected byte size, SHA-256, fsynced file content, a start receipt and success/failure marker. Wrong/partial snapshots are preserved, never reused/overwritten/deleted; original model files remain untouched. Hash verification applies to copied bytes, and snapshot is checked again immediately before loading. This avoids relying on the original mutable path after hashing. It does not promise OS-enforced immutability against an adversarial concurrent writer; the worker must serialize writers and control its artifact root. The **additional disk footprint is the sum of the 15 SD files**, which a future manifest must explicitly budget; no actual candidate-weight copy happened here.

The explicit future `load_snapshot` operation requires pinned config, complete snapshot, offline environment flags, deterministic/TF32-off profile, Diffusers 0.35.1 and Transformers 4.57.6. It calls local `StableDiffusionImg2ImgPipeline.from_pretrained(..., variant="fp16", use_safetensors=True, torch_dtype=float32, local_files_only=True)` only as a component loader, never its no-grad image-generation entrypoint. Weight storage is fp16 but declared component arithmetic is float32. It requires safety checker and feature extractor, freezes/checks float32 text/safety weights, tokenizes **only `[""]`** with fixed 77 padding/truncation, captures token IDs/digest, runs fixed text encoder without gradients, then constructs the reviewed DDIM/UNet/VAE component engine. It does not infer caption, CFG, alternate model, pickle fallback, remote code or missing-file download. A scientific launcher must block network in addition to local-files-only; no model-loading authorization is created by this module or by an environment flag.

This loader is not yet empirically exercised with real candidate assets. Prior A6 load approval is fulfilled/consumed and cannot be reused. Float32 full-gradient memory fit, empty-conditioning numerics, mirror publisher custody and rights remain limitations, not solved by byte inventory or mocks. The existing WSL science environment lacks `jsonschema`; a real worker still needs an honestly reviewed full-config validation bridge or separately authorized minimal software dependency, not fake validation or a bypass.

## Source keys, final PNGs, safety and retained failures

`src/embedding/output.py` adds explicit future `enroll_canonical` integration: canonical RGB8 source snapshot -> C2's pinned encoder extraction/semantic quantization -> C3b native pHash -> C3a public owner-bound signatures. It does not accept supplied/oracle feature vectors, generate a caption, re-sign a marked output or supply enrollment keys to a blind detector. This function has not been invoked on study data or real CLIP here.

`TrialStore` is an output custodian **under an existing approved runner artifact directory**, not a second scheduler/state engine. It creates a fresh directory/start record before computation, fsyncs finite JSON trajectory rows, preserves interrupted trials and emits exception-type-only failure markers. Identity stores source ID/raw and canonical-pixel hashes, native shape, seed and config hash; mutation/shape/seed/source-digest/control-mode mismatches are errors. The source RGB8 is copied and remains unchanged. It rejects control-only candidates mislabeled as marked.

It saves the **matched control and marked candidate** separately with B5's clamp/float64-scale/ties-even/no-ancillary RGB8 PNG encoder, reopens the actual bytes and requires equality to the encoded bytes. Safety is invoked on copies of those decoded saved pixels. The actual pinned-model checker adapter ignores black replacement images returned by its checker: a flag is recorded as `failed_safety_flagged`, with original diagnostic PNGs retained locally, not counted as successful preserved content. Missing/ambiguous safety results abort and remain failed/partial. Hashes and decoded MSE versus source are recorded; SSIM, LPIPS, blind verification and scientific acceptance remain explicitly NOT_RUN/false. No continuous target-template score is substituted for final verification.

The final study/development `reports/dev/embedding-manifest.csv` is still header-only, **zero executions**. All new PNGs in tests are disposable owned synthetic fixtures in temporary directories. No native study-image output, Control/Watermarked scientific pair, safety-model inference, quality target or final detector result has been invented.

Actual independent reviewer `/root/b3_intake_review` found a concrete blocker at `61df1cbf6e49ae08fc29cbe12a6e28650557a277`: a candidate under conflicting static/optimization settings could pass shape/seed/raw-source checks and be labeled with a trial's arbitrary config hash. Repair introduces `src/embedding/config_binding.py`: exact C1 raw config/hash/value/current schema identity and recomputed static DCT ID, plus immutable binding of full config hash, schema hash, detector ID, seed, serialized complete component settings and the hash of the **actual float32 source tensor**. The engine validates the binding before learned-component encoding; unbound arithmetic candidates remain explicitly unbound. Trial creation now requires the C1 config snapshot, stores those exact bytes, independently derives expected settings/static/source-tensor binding, and rejects mismatch **before either PNG is written**. The added actual source-tensor check also rejects a different same-shape input misleadingly supplied with the same raw-source digest. A kernel caller cannot assign a trial config hash as an output claim. These are provenance guards in trusted reviewed worker code, not a cryptographic proof against an actor fabricating Python objects or modifying executing code. Full C1 schema validation and the official manifest approval remain external prerequisites.

The reviewer also warned that first-image safety evidence could disappear if the second checker failed before final pair writing. Repair fsyncs a PNG identity row before safety and a completed output/safety row after each checker, so first-image evidence survives a second-image failure. New regressions demonstrate settings/full-config/static/unbound/wrong-input rejection, and durable first-output records plus both PNG hashes when a second checker throws. Unit fixtures are now full-shaped schema-derived synthetic objects; Windows additionally invokes actual C1 validation on them, whereas WSL keeps its explicit missing-package skip. Their fabricated fixture artifact digests are test data, not real scientific configurations or permission.

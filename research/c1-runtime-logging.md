# C1 validated configuration and run provenance

Status: implementation candidate for [issue #14](https://github.com/Eshahi/Dynamic-image-ownership/issues/14), not a scientific run or gate decision. The implementation is in `src/runtime/config.py` and `src/runtime/logging.py`; synthetic regressions are in `tests/test_runtime.py`.

`load_method_config` rejects duplicate JSON keys, nonfinite values, missing or linked input files, and any failure of the A5 JSON Schema **and cross-field** validator. It validates private snapshots of the exact config and schema bytes that it hashes and retains, rather than rereading a potentially changed original config. The CLI is invoked in a separate, bounded process so C1 does not silently substitute a weaker shape-only validation. A returned `{valid_structure: true, scientific_execution_authorized: false}` is the only accepted validator verdict. A successful parse is still not permission to execute scientific compute.

`start_run` validates the method config, named input files, environment receipt, nonnegative integer seeds, finite JSON parameters and clean Git commit **before** publishing a unique run directory. It writes byte-identical `config.json` and write-once `start.json` in a private staging directory, then renames that directory into the canonical run ID; a launch-time interruption can leave a visible `.staging-*` directory but cannot publish a canonical run without a start record. The start record includes config/schema hashes, input and environment file hashes/sizes, commit, seeds and parameters. `RunRecord.finish` consumes the immutable start bytes, inventories **all** files inside the run directory, and writes one `manifest.json` with end time, status, output hashes/sizes and an explicit failure reason. A duplicate finalization or linked artifact fails closed. `recorded_run` yields only the output directory, owns finalization, records an exception's **type only** and re-raises it, avoiding potentially sensitive exception text in the manifest. An interrupted process leaves `start.json` but no final manifest and must never be interpreted as success.

This is a provenance component, not an experiment runner. It does not inspect dataset image rights, enforce the compute runner's exact-manifest user approval, prove environment receipt truth, prevent a privileged local user from modifying files later, or establish method/model correctness. A downstream runner must recheck declared bytes immediately before use and preserve its own authorization/expiry evidence; C1 must not be used to bypass that runner. Run roots should be ignored local `runs/` or another non-Git artifact directory; raw images, prompts, credentials and other private values must not be put in JSON parameters. The current tests are synthetic and do not claim a real method configuration or data manifest exists.

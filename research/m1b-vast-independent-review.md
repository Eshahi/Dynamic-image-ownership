## Baseline recovery findings (historical; fixed in reviewed v3 diff)

1. **CLIP API:** `three_threat_models.clip_feature_wrapper` does not exist. Use its actual `clip_feature(model, transform, rgb)` API for every view and preserve the frozen seven-view mean/normalization. Both embedding and detection depend on it.
2. **Resume completeness:** the source loop skips the entire source after finding only C0/C1 clean correct-claim IDs. Remaining wrong-owner and T3 rows never run. Restore saved source/marked images, then schedule all absent planned rows; do not re-embed a saved successful C1. A row's presence alone is not successful completion. Retain failed attempts and declare whether/how technical failures may be retried. The existing resume unit test checks dictionary membership, not execution completeness.
3. **Planned denominator:** endpoint IDs are collected from journal keys. Source-load/embed failure therefore removes all downstream calls from the denominator; an all-embed-failed run can have no cells and still `outcome=completed`. Construct expected row IDs from the manifest before execution, retain missing cells adversely, and distinguish execution completion from success. Smoke acceptance must compare planned, completed, failed and missing inventories, not only journal row counts.
4. **T4 runtime API:** the runner calls `residual_transfer(recipient_rgb, residual, scale)`; the actual signature is `(recipient_c0, donor_c1, donor_c0, scale)`. A supplied T4 smoke cannot complete until corrected. The fallback also truncates fractional residuals whereas the existing helper specifies ties-to-even quantization; use the normative helper without a silently different fallback.

A fresh two-source development smoke after these fixes is appropriate. Include clean controls, VAE, a diffusion dose/seed, both residual scales/sham/claims if testing that exploratory arm, and cross-owner calls. Exercise partial resume and an upstream failure with CPU fakes. Its purpose is integration and inventory validation; it cannot establish confirmatory readiness.

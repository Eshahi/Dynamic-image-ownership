# Core budget and proposals for the user's stage-1 decision

2026-10-19; reopened 2026-10-20. **Prior stage-1 proposal package under section 1b revision; no spending authorized by this document.** These are transparent engineering estimates, not measured GPU timings or live rental quotes. No server was contacted. Let p be the actual all-in instance hourly price; total cost is p×instance-hours plus any separately charged transfer/storage. Obtain that actual price before execution. The unchanged core ceiling is **15 instance-hours or USD 15, whichever arrives first**, including setup and return of results.

## Core

Recommend one fast CUDA 12.8-compatible GPU with at least 24 GB VRAM (32 GB preferred), at least 32 GB host RAM (64 GB preferred) and at least 100 GB free disk for models, environment and outputs. Serial loading avoids simultaneous F5/VINE/SDXL residency. The memory figures are planning allowances, not measured compatibility guarantees. A higher-priced GPU can make the dollar deadline shorter; a slow cheap GPU can make the hour deadline binding.

The final schedule includes **C0**, which some topic-local estimates omitted: 2,700 R0 +2,700 R1 +900 extra rinse diffusion calls,300 D1,300 each X1/X2,300 clean units =7,500 total. Smoke adds250 units on two disjoint sources. R0/R1 each require12,600 denoiser updates; rinse adds1,800. Four arms have240 native marks, and C0 is read by all detectors. Wrong-owner and wrong-message calls, LPIPS/CLIP, serialization and transfer are included in overhead.

P5's expanded estimate explicitly adds 900 control outputs at assumed 6-12 seconds each (1.5-3h) to the earlier 1.6-4.6h smoothing allowance, plus 0.4h for additional setup/readouts: 3.5-8h. This is sensitivity arithmetic, not a hardware forecast; approval must set a combined ceiling and a timing-only feasibility check. Four fixed public Gaussian arrays and their negatives are shared across sources/arms at 1024; clip to [0,1], average posterior modes, then apply the same .2 diffusion path as the matched mode control. No tuning, training or smoothing certificate is implied.

The baseline survey also inspected InvisMark, RoSteALS, ZoDiac, SpecGuard, SimuFreeMark, GenPTW, DistSeal, EditGuard, OmniGuard and other post-hoc methods. Some have public releases but unsuitable native cost/quality, while others lack complete artifacts or resolved implementation licenses. SimuFreeMark is now a verified primary paper with reported regeneration results; its executable release remains unresolved. Missing code, unreported attack settings and bit accuracy without calibrated image detection are recorded separately. No unavailable arm is treated as inferior. FLUX remains excluded while gated. Shared-autoencoder PixArt/Playground/Hunyuan variants add generator diversity without necessarily adding encoder diversity.

T2's expanded [proposal comparison](design-research/T2-encoder-landscape/proposal-comparison-1b.md) rejects a separate **P10 Klein** for this question: ungated Apache availability does not establish encoder initialization independence or a partial-noise strength API. A larger KD3/SANA/Qwen full-model panel is an illustrative 25.5 extra hours, 35.5–39.5 total, and exceeds 80 GB downloads even before all components. It requires a new study/budget decision. O1 plus the core is about 55.426 GB before packages/images, below 80 GB but above the present 40 GB model/retry allocation. These are file arithmetic and throughput assumptions, not measured server resource requirements.

Priority for a limited additional budget: P1 first, P4 for the central mechanistic uncertainty, then P9 for another practical modern baseline or P5 for the prespecified adaptive question.

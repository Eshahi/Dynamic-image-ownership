## Training independence and what each arm could establish

SD3 §5.2.1 and Table 3 compare f8 AEs with 4, 8 and 16 channels; the 16-channel model has reported reconstruction PSNR 28.62 and SSIM .86. This establishes a representation change. It does **not** state that the AE distributed with SD3.5 Medium was initialized from scratch rather than partially adapted. A new channel count permits shared or adapted layers. Label its strict independence field **unverified**, even though it is a useful out-of-family denoiser challenge. [SD3 paper](https://arxiv.org/html/2403.03206v1#S5.SS2.SSS1).

Sana §2.1 describes training an f32c32 AE and high-resolution fine-tuning. DC-AE §3.2 describes residual space-to-channel shortcuts and staged high-resolution adaptation; §4.1 describes AE training mixtures and EfficientViT blocks. These support a separately developed/trained codec family. The paper's §4.3 statement about training text-to-image models from scratch is not proof of the exact released AE's initialization. Do not silently transfer it to Sana-Sprint's distributed AE. [Sana method and experiments](https://arxiv.org/html/2410.10629v1), [DC-AE method and experiments](https://arxiv.org/html/2410.10733v1).

Stable Cascade's release is a three-stage chain, not one SD-style VAE. The card identifies Stage A/B compression and Stage C synthesis. The earlier Würstchen paper does not identify the released checkpoint lineage of all these stages. The paper/card evidence therefore cannot support a strict from-scratch claim for the release. [Stable Cascade release card](https://huggingface.co/stabilityai/stable-cascade), [existing Würstchen V2 card](../literature/encoders/pernias-wurstchen.md).

Kandinsky's report §3.4 describes the developed Sber-MoVQGAN and §4 its training; this is materially stronger separate-training evidence than a channel-count argument. It does not prove zero shared image data, and it does not identify every released file by hash. The existing retained stage-2b evidence is decisive for novelty: F5 full Kandinsky .2 C was 5/60, whereas MoVQ round trip retained 55/60. The next study can refine that mechanism contrast, not rediscover it as unseen evidence. [Kandinsky report](https://arxiv.org/html/2312.03511v3), [local V2 card](../literature/encoders/arkhipkin-kandinsky3.md).

## Native pipeline and severity audit

**SD3.5:** The pinned SD3 img2img implementation accepts image and strength, uses `FlowMatchEulerDiscreteScheduler`, selects a suffix of its actual time schedule, encodes with the AE and calls `scheduler.scale_noise`. Its step selection is `t_start = int(max(N - min(N*s,N),0))`, not Kandinsky's floor-of-`N*s` implementation. Preserve the entire schedule and first retained time/sigma. Equal numeric strength across flow and DDIM is not a noise-energy match. [SD3 img2img v0.35.1](https://github.com/huggingface/diffusers/blob/v0.35.1/src/diffusers/pipelines/stable_diffusion_3/pipeline_stable_diffusion_3_img2img.py).

**Sana:** The v0.35.1 exports contain ordinary Sana, Sana ControlNet, Sprint and Sprint img2img. A blanket statement that all Sana lacks native img2img would be false; ordinary Sana 600M remains unsupported for this purpose. Do not load ordinary weights into Sprint's consistency sampler merely because shapes match. [Pinned exports](https://raw.githubusercontent.com/huggingface/diffusers/v0.35.1/src/diffusers/pipelines/sana/__init__.py).

**Sprint:** Native input encoding is followed by trigonometric corruption. The released scheduler is `SCMScheduler`, `prediction_type=trigflow`, `sigma_data=.5`; a pipeline type annotation mentions DPM solver but is not the actual loaded scheduler. With default N=2, times are `[1.57080, 1.3, 0]`. Positive strengths .1, .2 and .4 all start at 1.3 and run the same single denoising step. Thus they are duplicate severity conditions, not a smooth low-strength sweep. This follows directly from pinned code and is not a measured quality claim. [Released scheduler](https://huggingface.co/Efficient-Large-Model/Sana_Sprint_0.6B_1024px_diffusers/blob/main/scheduler/scheduler_config.json), [SCM scheduler v0.35.1](https://raw.githubusercontent.com/huggingface/diffusers/v0.35.1/src/diffusers/schedulers/scheduling_scm.py).

The native Sprint pipeline also permits custom timesteps and `max_timesteps`; any use requires a preregistered schedule and server-only quality preflight. Its default aspect-ratio binning and prompt treatment must be fixed and reported. Native availability does not validate low-noise operation of a distilled model. Do not invent a custom pipeline or extrapolate ordinary Sana's Flow-DPM-Solver results to Sprint. [Sprint img2img v0.35.1](https://raw.githubusercontent.com/huggingface/diffusers/v0.35.1/src/diffusers/pipelines/sana/pipeline_sana_sprint_img2img.py).

**Cascade:** Pinned prior code passes supplied images through a feature extractor and image encoder to conditioning embeddings. It separately prepares generative latents and starts its normal prior schedule. There is no `strength` argument in that prior call. This is image-guided generation; it does not implement SD-like corruption of the source's compression latent. A meaningful regeneration construction would need a separate protocol and validation, so exclude it from this study's interchangeable family slot. [Cascade prior v0.35.1](https://github.com/huggingface/diffusers/blob/v0.35.1/src/diffusers/pipelines/stable_cascade/pipeline_stable_cascade_prior.py).

**Kandinsky:** Pinned native img2img uses a DDPM scheduler and `min(int(N*s),N)` selected steps. It has MoVQ encoding and native image corruption. Record actual selected step count and initial alpha/SNR, since neither nominal strength nor equal step count makes its perturbation comparable with DDIM or flow. [Kandinsky img2img v0.35.1](https://raw.githubusercontent.com/huggingface/diffusers/v0.35.1/src/diffusers/pipelines/kandinsky3/pipeline_kandinsky3_img2img.py).

Across every candidate, match achieved within-source distortion under a fixed procedure and report resolution, source preprocessing, prompt, scheduler class/config, initial corruption and effective denoising steps. A full-family comparison changes denoiser, schedule and often resolution along with the AE; use AE-only round trips separately and avoid causal identification claims.

## Bounded V2 mini-card: Sana-Sprint and the released AE lead

**Source:** Chen et al., *SANA-Sprint: One-Step Diffusion with Continuous-Time Consistency Distillation*, arXiv:2503.09641v1 (2025), [paper](https://arxiv.org/html/2503.09641v1). Method §3.1 converts a pretrained flow-matching model to TrigFlow by input/output transformations; §3.2–3.3 add consistency and adversarial distillation. Experiments §4.1–4.3 and Appendix F evaluate MJHQ-30K FID/CLIP and GenEval with 1–4 steps. At four steps the reported 0.6B FID is 6.48 and GenEval .76. These are T2I quality/efficiency results, not watermark-transfer, source-identity preservation or img2img severity validation. The paper describes pretrained Sana lineage; its statements about avoiding training from scratch refer to distillation, not AE initialization. No independent-AE claim follows from them.

**Release evidence:** The 0.6B [model index](https://huggingface.co/Efficient-Large-Model/Sana_Sprint_0.6B_1024px_diffusers/blob/main/model_index.json) names `AutoencoderDC`, `Gemma2Model` and `SCMScheduler`. Its [AE config](https://huggingface.co/Efficient-Large-Model/Sana_Sprint_0.6B_1024px_diffusers/resolve/main/vae/config.json) names `mit-han-lab/dc-ae-f32c32-sana-1.1-diffusers`, 32 latent channels and scaling .41407. This provides a concrete checkpoint lead. It does not itself certify file equality or original initialization. The official card labels Apache-2.0 and separately points to Gemma terms. No gate appeared on the checkpoint or public file listings; this observation is not a licence interpretation or acceptance.

**Verdict:** Native full regeneration and public component access are verified at source level. Strict released-AE weight independence, planned img2img memory and a useful low-distortion severity range remain unknown. It is a credible new reserve candidate with a demanding preflight, not an immediate drop-in fallback. Resolving its AE training record and file identity can be assigned to the future server preparation phase; do not download or run it on the laptop.

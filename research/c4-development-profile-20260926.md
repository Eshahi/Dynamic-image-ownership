## Concrete prerequisite conflict and bounded resolution

C4 produces marked validation examples needed by C5 calibration, while final A5 configurations require actual validation-frozen thresholds and the full final detector. Inventing those thresholds or putting fixture digests into a purported final config would fabricate evidence. Closing C4 with synthetic examples or silently weakening final C1 is also invalid. The development mechanism pilot therefore has a distinct typed profile which can produce retained engineering/gradient/output diagnostics but **cannot return a calibrated detection decision or scientific acceptance**. Full C4 acceptance and method-success claims still require final quality and blind verification; they are not inferred from this pilot.

`src/runtime/feasibility.py` derives a strict schema from the current A5 schema: only schema_version, profile and calibration properties differ. Every image/feature/signature/DCT/model/embedding/safety field and cross-field validator is retained. The new constants are `c4-feasibility-v1`, `public-derived-existing-image-feasibility`, and the exact calibration object `{status: not-calibrated-development-only, decision: prohibited, thresholds: absent}`. No tau, validation-result digest or calibrated label can be added. The existing full validator runs on the exact derived schema bytes in the controller; a separate `FeasibilityConfig` type is returned. Final `load_method_config` still rejects the development config and still requires all actual calibration fields for a final config. The shared validation mechanism is refactored without removing a final-schema check.

Embedding snapshot checks distinguish exact final/development types and corresponding schema identities; retyping a development config as final or attaching final calibration to it fails. The bridge's version **v2** records config_kind and checks the schema derivation code as a manifest dependency; its child reconstructs the correct type. A changed type/manifest cannot reuse a receipt. Output custody records actual config profile and calibration restriction with each trial, and already keeps scientific_acceptance false. This is not a grant to execute the pilot. The future reviewed worker must enforce development-only data and must not call final classification under this type. No general-purpose final detector is supplied or claimed by this checkpoint; C5 remains dependency-blocked/open.
